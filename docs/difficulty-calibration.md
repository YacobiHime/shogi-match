# CPU難易度の調整方針

最終更新: 2026-10-06

この文書は難易度の設計意図と校正結果を記録する。実値の正本は
`src/core/strength-settings.mjs`、回帰確認は`src/core/strength-settings.test.mjs`である。
着手選択の処理は`src/core/cpu-move-choice.mjs`、指し手の自然さは`src/core/move-naturalness.mjs`にある。

## 2026-09-27の再設計の経緯

旧版(Lv0〜24)は、表示名に対して低レベルが強すぎた。ぴよ将棋Lv15(R780、3級前後)程度のユーザーから、
「旧Lv6(十四級程度)にも勝ち目がない」と報告があった。1手当たりの評価損を測ると、旧Lv3〜10はほぼ同じ強さだった。

| 旧Lv | 平均損失 | 中央値 | 300以上の悪手 |
| ---: | ---: | ---: | ---: |
| 1 | 376 | 86 | 31% |
| 5 | 298 | 74 | 27% |
| 6 | 235 | 72 | 20% |
| 10 | 247 | 69 | 19% |
| 14 | 165 | 46 | 13% |

旧版では、探索上位4〜6手からだけ選んでいた。そのため、どのレベルも大半が「ほぼ最善の手」で、
弱さはときどきの見落としだけから出ていた。これを次のように作り直した。

1. レベルをLv0とLv1〜40の41段階にし、表示名をぴよ将棋の段級位の目安に合わせた。
   ぴよ将棋は1レベルでR約80上がり、Lv15が3級前後とされる。
2. 各設定を「技量」(0〜1)という1つの値から連続的に決める。
3. 低レベルでは「読まない手」を混ぜる。これは探索結果を使わず、合法手を自然さで選ぶ手である。
   相手の狙いを見逃したり、駒をただで取られたりする。
4. 各レベルの技量は、CPU同士の自動対局で推定したレーティングから割り付けた。

最初の割り付けでは、旧Lv6を新Lv20に置いた(以下「版C」)。その後、次のように割り付けを変え、版Cへ戻した。

| 版 | コミット | 割り付け | 報告 |
| --- | --- | --- | --- |
| C | (未公開) | 旧Lv6を新Lv20に置く | 「Lv6で2級くらい」。ただし公開中の旧版を遊んだ感想だった |
| D | 65a8951 | 版CのLv6(技量0.115)を新Lv17に置く | 「弱くなりすぎた」 |
| E | 974d02f | 版Dを一律に1段階強くする | 「Lv15がLv10くらい」 |
| F | e3256fc | 版EのLv15(技量0.109)を新Lv10に置く | 「手が不自然で、Lv25でも勝てる」 |
| C | (現在) | 版Cに戻す | - |

版D〜Fでは、自己対局で測った強さと実戦で感じる強さが一致しなかった。
版FのLv25は、自己対局では旧Lv6(報告者がまったく勝てなかった設定)より強い。それでも実戦では勝てたと報告があった。
低レベルの弱さの一部(読まない手、広い候補からの抽選、作戦の手への強いこだわり)は、
CPU同士では差が出にくい一方で、人間には突かれやすく、不自然にも見えると考えられる。
版Cを基準に、実戦の報告で校正し直す。

## 2026-10-06の弱さの出し方の作り直し

「Lv15(三級程度)でも、対局を台無しにする悪手が多い。読み抜けではなく、普通の手ですらない」との報告があった。
旧設定のLv15には、悪手の出る経路が3つあった。

| 経路 | 旧設定のLv15 | 起きていたこと |
| --- | --- | --- |
| 読まない手 | 14% | 合法手を自然さだけで選ぶ。目的のない手(端歩、意味のない金の移動など)は減点されず、ほぼ同じ重みで並んでいた |
| 見落とし | 32%の手番で試す | 最善手より最大2,300損する手まで選べた |
| 探索候補からの抽選 | 580nodes、許容損失970、温度650 | 970損する手でも最善手の約4分の1の重みで選ばれた |

弱さを「悪い手をときどき選ぶ」から「視野が狭い」へ作り直した。目に付く少数の自然な手だけを読み、
その中から選ぶため、静かな好手を見逃しても、意味のない手は指さない。あわせて、1手の損失上限、
大きな悪手の回数と間隔の制限、素人らしい分かりやすい手を好む自然さを加えた(各値は次の節)。

1手当たりの評価損(24局面×6回、基準探索30,000nodes、悪手の回数制限なしで計測)は次のように変わった。

| Lv | 平均損失(前→後) | 300以上(前→後) | 1,000以上(前→後) |
| ---: | ---: | ---: | ---: |
| 1 | - → 405 | - → 44% | - → 9.7% |
| 5 | 426 → 212 | 32% → 30% | 12.5% → 2.1% |
| 10 | 348 → 168 | 23% → 24% | 10.4% → 0% |
| 15 | 229 → 134 | 17% → 13% | 5.6% → 0% |
| 20 | 136 → 102 | 13% → 6% | 2.1% → 0% |
| 25 | - → 86 | - → 6% | - → 0% |

自己対局(技量0〜0.8の15点、隣と2つ先の相手まで各36局、旧Lv6の設定`old6000`と各16局)では、
技量0.05〜0.3がほぼ同じ強さ(1,214〜1,422)になり、どれも`old6000`(1,154)より強く出た。
自己対局の勝敗はほぼ大きな悪手の数と大きさで決まり、損失上限を掛けると、視野の広さや温度を変えても差が出にくい。
以前と同じ勝率に合わせるには、Lv15にも大きな悪手を1局に何度も戻す必要がある。
そのため、各レベルの技量(割り付け)は変えず、実際に遊んだ感想で割り付けを直す方針にした。
自己対局では、Lv2以上が旧設定より強く出る。人間から見た強さは未確認である。

## 技量から決まる設定

`strengthParametersForSkill(skill)`が次の値を決める。どの値も技量が上がるほど強くなる方向にだけ動く。

- 探索nodes: 50から480,000まで、技量に対して指数的に増やす。技量1(Lv40)だけは720,000nodesを2スレッドで読む。
- MultiPV: 4〜8。少ないnodesでは候補順位がノイズになるため、`log2(nodes)`で上限を付ける。
  上位レベルでは再び減らし、技量1では1にする。
- 最善手率: 技量の2乗。
- 最大評価損と温度: 技量が上がるほど狭める。最善手率の抽選に外れた場合は、最大評価損以内の候補から
  `exp(-評価損/温度) × 自然さ^α`の重みで選ぶ。
- 自然さα: `1 - 技量`。
- 読まない手の割合: `(1 - 技量/0.05)^1.5`。Lv0(技量0)の100%から技量0.05で0になる、Lv0とのつなぎだけに使う
  (2026-10-06に、技量0.4までだった範囲を狭めた)。
- 視野: 技量0.6未満では、目に付く手だけを読んで選ぶ。目に付く手は、自然さの上位`3 + 9 × 技量/0.6`手
  (駒をただで渡す手を除く)と、探索上位`MultiPV × (技量/0.6)^2`手。これらを最善手と並べて、
  そのレベルのnodes(下限1,000)で読み直し、`exp(-評価差/温度) × 自然さ^α`の重みで選ぶ。
  損失上限以内の手がなければ、探索候補からの抽選に戻る。
- 1手の損失上限: `max(400, 1300 × (1 - 技量)^3)`。見落とし・視野内の手・探索候補からの抽選のすべてに掛ける。
- 大きな悪手(最善手より300以上損する手)の回数と間隔: 1局に`max(1, round(5 × (1 - 技量)^4))`回まで、
  前の悪手からCPUの手数で`round(3 + 14 × 技量)`手あける。使い切った後は、300以上損する手を選ばない。
  待ったで戻した手の悪手は数えない。回数は対局の保存に含める(`cpuBlunderPlies`)。
- 上限を守る手の割合: `技量/0.05`(最大1)。技量0.05未満では、上限と回数制限を守らない手番も混ぜ、Lv0へつなぐ。
- 素人らしさ(`simplicity`): `(1 - 技量)^1.5`。自然さの重みに次の加減を、この度合いで効かせる。
  - 歩と歩がぶつかったら取る手(最大4倍)、取り返し(最大2倍)
  - 評価値300以上の優勢なら、駒の交換と取り返し(最大2.5倍)
  - 飛車先の歩を伸ばす手、相手の駒(香・桂以上)に新しく当てる手、飛車・角の利きを広げる手
  - 取る・逃げる・成る・王手・囲い・前進(端歩を除く)・攻めのどれでもない手は、目的のない手として最大0.4倍
- 作戦の定跡手を評価値より優先する幅の倍率: `1 + 2 × (1 - 技量)`。Lv1で約3倍、Lv40で1倍。
  低レベルほど、多少評価が下がっても決めた戦法・囲いの形を作り続ける。
- 見落とし: 技量0.75未満で混ぜる。浅い読み(そのレベルのnodes)で良く見えた手を、検証nodesで深く読み直す。
  実際には300以上「見落とし最大損」以下の損になる手を選ぶ。該当する手がなければ通常の抽選に戻る。
  見落とし最大損は1手の損失上限を超えない。悪手の回数を使い切った後は見落としを選ばない。

駒をただで渡す手(歩以外は王手・成り・駒得に見える取りも含む。歩は取られるだけの突き捨て)は、意味の無い手に見えやすい。
そのため次のように扱う(2026-09-27追加)。

- 自然さでは、歩以外をただで渡す手に`piece-sacrifice`の印を付け、王手や成りの加点があっても重みを0.05〜0.1に抑える。
- 読まない手では、駒をただで渡す手を選ばない。取られそうな駒の放置や、相手の狙いの見逃しは従来どおり起きる。
- 探索の2番手以下の候補にある駒捨ては、最善手との差が150以内の場合だけ選ぶ(`SACRIFICE_CANDIDATE_MAX_LOSS`)。

Lv15同士の自動対局(約2,000手、30,000nodes相当の深い読みで損失を測定)では、損失300以上の駒捨ての頻度が次のように変わった。

| 対象 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 歩以外の駒捨て | 73手に1回 | 約400手に1回 |
| 歩の突き捨て | 73手に1回 | 約120手に1回 |
| 1手当たりの平均損失 | 395 | 396 |

残った駒捨ては、主に浅い読みの最善手が深い読みでは悪かった場合である。平均損失は変わらず、難易度はほぼ保たれている。

Lv0は探索せず、合法手を自然さだけで重み付けして選ぶ。一様ランダムの着手は全レベルで廃止した。
互換のため、設定キー`randomLegalRate`・`randomFallback`は常に0・falseで残す。

## 上限(Lv40)

Lv40「藤井聡太並み」をCPU対局の上限とする。藤井聡太より強い人間はいないため、それより強いレベルは設けない。
2026-10-02に一時Lv41「最強」(150万nodes・最大4スレッド)を追加したが、同日に取り下げた。
保存データやURLにLv41の識別値(1500000)が残っている場合は、最も近いLv40として扱う。

同日に、Lv40だけ探索量を48万から72万nodes(1.5倍)へ増やし、2スレッドで読むようにした。
「探索量2倍でR+80」の目安ではR+50程度の強化になる。自動対局での強さの差は、局数が足りず測っていない。
2スレッドにすると読む速さがほぼ2倍になるため、待ち時間は以前より短い。Node上で、小山怜央の棋譜の11局面を
1局面ずつ置換表を消して読ませた時間は次のとおり。端末のコアが2つ以下なら1スレッドで読み、待ち時間は約1.5倍になる。

| 設定 | 平均 | 最大 |
| --- | ---: | ---: |
| 48万nodes・1スレッド(以前) | 0.63秒 | 0.74秒 |
| 72万nodes・1スレッド | 0.93秒 | 1.09秒 |
| 72万nodes・2スレッド(現在) | 0.45秒 | 0.53秒 |

スレッド数はCPUの着手探索の直前に設定し(`ShogiEngine.setSearchThreads`)、Lv1〜39では1スレッドへ戻す。

同日に、置換表(`USI_Hash`)を全レベルで既定の16MBから64MBへ広げた。棋譜解析の深読み(数十万〜数百万nodes)で
16MBではあふれるため。端末のメモリを使うだけで、配信サイズは変わらない。

自動対局で確かめた、探索量を増やしたときの強さの差は次のとおり。技量1の12万nodesと24万nodesを、
序盤12手を評価差80以内の候補からばらして12局対局させた(`--opening-plies 12`)。
24万nodesの9勝3敗で、レーティング差は+188±115だった。

## 校正方法

`scripts/cpu-level-selfplay.mjs`は、ブラウザと同じWASMエンジンをNode上で動かし、CPU同士を自動対局させる。
選手ごとに別のエンジンを使い、置換表を共有しない。120手以降は8手ごとに3,000nodesで形勢を判定し、
評価値4,000以上の差で打ち切る。256手に達した場合は10,000nodesで判定し、800未満なら引き分けにする。
結果は、引き分けを0.5勝としたBradley-Terryモデルでレーティングに換算する。

2026-09-27の校正では、次を行った。

1. 技量0〜0.8の21点を、隣と2つ先の相手までそれぞれ70局対局させた(2,730局)。
2. 旧版のLv1・6・10・14の設定を、技量0.2〜0.55の各点と30局ずつ対局させた。
3. 技量0〜0.15を0.01刻みで、3つ先の相手までそれぞれ80局対局させた(3,840局)。
4. `scripts/cpu-level-assign.mjs`で、技量に対するレーティングを単調な折れ線にした。
   技量0.8より先は、末尾の傾きで技量1まで延ばした。

自動対局での位置は、技量0を0として次のとおりだった(1.と2.の結果)。

## 限界と今後の校正

- 2026-10-06の作り直し後は、割り付けを自己対局では校正していない。実際に遊んで強すぎるレベルがあれば、
  そのレベルの技量を下げる。自己対局で以前の勝率に合わせると、大きな悪手が戻る(前述)。

- 基準点はユーザー1人の報告だけである。実際に遊んでもらい、勝ちやすいレベルがずれていれば、
  `cpu-level-assign.mjs`の`--anchor`(例: `old6000=20`)と`--curve`で割り付け直す。
- 自己対局の強さの順序は、人間から見た強さの順序と一致しないことがある(版D〜Fの経緯)。
  弱さの出し方を変えた場合は、自動対局だけで判断せず、実戦の報告で確かめる。
- 自動対局では序盤の作戦(戦法・囲いの案内手)を使っていない。実戦では、低レベルほど決めた作戦の形を作るのに手数を使う。
- ぴよ将棋とはエンジン、評価関数、候補選択方法が異なる。段級位の表示はあくまで目安である。
- 技量0.8より上は、実測ではなく延長である。上位の対局は1局が長く、校正の優先度も低いため、必要になったら測る。
- エンジンまたは評価関数を更新した場合は、同じ設定を同じ棋力とみなさず校正し直す。
- 1手当たりの評価損は`node scripts/cpu-humanlike-report.mjs`で測れる。サンプル局面の偏りで順位が入れ替わるため、
  強さの順序は自動対局で判断する。

## 作戦指定

居飛車、四間飛車などの作戦手を、常に唯一の探索候補として強制しない。
通常探索の安全な候補に作戦手が含まれる場合だけ優先し、王手、詰み、駒損への対応を作戦より優先する。
Lv0だけは練習目的で、合法な作戦手を通常の自然さ抽選より優先する。
作戦手を選ばなかった手番では、低レベルでも読まない手の抽選を行う。

「おまかせ」で角道・飛車・序盤の指し方の指定がない場合は、`randomOpeningCombinationRate`の確率で、
登録済みの全戦法・囲いを組み合わせる。確率は`max(0.1, 1 - 技量)`で、Lv1ではほぼ毎局、Lv40では1割になる。
組み合わせの対象は、CPUの手番と局面で成立するものだけである(`availableOpeningDefinitions`)。
囲いは戦法と飛車の方針(居飛車・振り飛車)が合うものから選ぶ。相手の飛車の方針が分かっていれば、
対抗形・相居飛車・相振り飛車のうち、その戦型に合う囲いを優先する。
アヒル囲い・右玉など戦法と一体の定義は、相方と組み合わせない。
組み合わせを使わなかった対局では、従来どおり主要な作戦から重み付きで選ぶ。
組んだ作戦は対局の保存データに含め、リロード後も引き継ぐ。
