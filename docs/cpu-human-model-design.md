# 人間らしいCPUの設計（思考のモデルとレベル表）

最終更新: 2026-10-28（12章で実装。実装・自動テスト済み）

この文書は、CPUを「その段級位の人間が考えるように」指させるための設計です。
ロジック（何に気づき、何を読むか）と評価値（大局観）を1つの式で組み合わせ、レベルごとの値を決めます。
主な対象はLv11〜39です。Lv1〜10は、台無しの手を防ぐ仕組みだけを足す案です（10章で決める）。
実装の指示書は、この設計が決まってから別に作ります。

## 0. この文書について

### 0-1. 頼まれたこと

ユーザーの要望（2026-10-19）:

> 前までのCPUはちょっと強すぎました。しかし、対局を台無しにするような手（特に人間らしくないミス）は見過ごせない。
> 人間が将棋をするときの思考とかを、そのレベルに合わせて高い精度で模倣したい。
> できるだけ将棋AIは、人間のように論理的に考えて指すようにしたい。ロジックと評価値を上手く組み合わせると良いかも。
> とにかく人間らしい指し手と丁度良い難易度設定にしたい。

これまでの指示で決まっていること:

- Lv40「藤井聡太並み」は変えない（720,000nodes・2スレッド・MultiPV1・最善手だけ）。Lv40より強いレベルは作らない。
- 旧CPUの各Lvの強さを目安にし、多少弱くなってもよい。
- 意味のない手（関係ない端歩、9二香など）は指さない（`cpu-purposeful-moves-design.md`）。
- Lv11以上でもロジックを使い、評価値と組み合わせる。

### 0-2. 読んだ指針

`docs/nintendo-design/`のうち、次の原則に基づいて設計しました。本文では「→D:4-9」のように示します。

| 原則 | この設計での使い方 |
|---|---|
| D:4-9 コンピューター相手は「反応できて、倒せる」 | 弱さを「見えなかったこと」から出す。CPUの間違いに、プレイヤーが理由を見つけられるようにする |
| D:4-10 作り手は基準にならない | 強さは測った値（評価値の損・勝率）で決め、思っているより弱めに置く |
| D:4-1 初心者にはやさしく | 低いレベルほど、プレイヤーのミスを見逃すことがある |
| D:4-5 ズルを許す | レベルごとの「見えにくい手」（打つ手・遠くの利き・後ろへの手）を一貫させ、プレイヤーが見つけた弱点をすぐには塞がない |
| D:4-7 平均と平凡は同じ | 棋士の特徴（読みが深い・終盤で頓死が多い など）を、気づきと読みの値の差として大きく出す |
| D:4-4 単調な坂は山登りにならない | レベルの帯ごとに、見えるものが質的に変わる（取られる駒→取り合い→3手の筋→大局観） |
| D:4-3 安全網 | 難易度は黙って変えない。負けが続いたときは既存の提案を使う |
| D:2-2 溜めと解放 | 台無しの手で終盤の緊張を壊さない。詰ます快感は残す |
| D:7-2 負けた人も楽しい | CPUの間違いに理由（「銀取りに気づかなかった」）を残し、振り返りで説明できるようにする |
| I:8 難易度とCPU | 難しさは測った値で決める。意味のない手で弱さを出さない |
| I:11 避けること | 難易度を黙って自動で下げない。意味のない手で弱さを出さない |

## 1. 機能設計メモ（Game_Nintendo_Design 14章）

### 機能名：人間らしいCPU（見えたものの中で最善を尽くす相手）

- 一言で：同じ段級位の人と指しているように、「勝てそうで、ちょっと手ごわい」相手。間違えるときは、人間が見落とすところで間違える。（2-1）
- 解く課題：（2-5）
  1. 前のCPUは強すぎた。ふだんの手がエンジンの手そのもので正確すぎ、プレイヤーのミスをほとんど咎めた。
  2. 一方で、弱くするための抽選が、1手で見える大きな損（大駒をただで渡す、など）を混ぜた。人間らしくない台無しの手になる（2章の測定）。
  3. レベルの違いが「間違いの回数」の違いでしかなく、何が見えるかの違いになっていない。
  4. CPUがなぜ間違えたか分からず、振り返りで説明できない。
- リスクとリターン：プレイヤーは、CPUの見落としそうな手（打つ手・遠くの利き・3手先の筋）を狙って勝ちに行ける。強いレベルほど見落としが減り、狙いが通りにくい。（2-1, 4-2）
- 溜めと解放：CPUは攻めてくる。受け切ってから、CPUが見落とした筋で逆転する、という解放を作る。CPUが自分から大駒を捨てて終わる「しらけた勝ち」は作らない。（2-2, 4-9）
- 初めての人の最初の1分：Lv11前後のCPUは、取れる駒はたいてい取り、自分の駒の当たりにはたいてい気づく。でも、打つ手の両取りや、3手先の筋は見落とす。プレイヤーは「この相手は自分と同じくらいだ」と感じる。（4-1）
- 上級者の深さ：Lv26以上は、1手・3手で見える台無しの手を指さない。勝つには、読みの深さと大局観で上回る必要がある。（2-4）
- 失敗したとき：今までと同じ（終局画面の「もう一局」、振り返り、3連敗の提案）。CPUの手に、何を狙い、何に気づかなかったかの記録が残る。（7-1, 7-2）
- ご褒美と使い道：今までと同じ（初めて勝ったLvの★、称号）。この設計では足さない。（5-1）
- ほめる瞬間：CPUの見落としを突いて駒得・逆転したとき、既存の好手判定でほめる。CPUが気づかなかったことを、やこび姫が説明に使える（後の段階）。（5-4）
- 捨てるもの：
  - 評価値の差を大きな温度でばらして選ぶ抽選（人間らしくない大損の元）。
  - 「深く読むと悪い手を、わざと選ぶ」見落としの抽選（理由のない大損の元）。
  - 対局中に黙って強さを変える仕組み（接待AI。→I:11）。
  - 評価値を0に近づける形勢の調整（相手の悪手に、同じくらいの悪手で応じてしまう。3-4）。
  - Lv40より強いレベル。
- 確かめ方：測定スクリプトで、台無しの手の割合と平均損失をレベルごとに測る。旧CPUとの自動対局で強さを合わせる。作り手以外の人に、決めた場面（大駒の当たり、タダの駒、詰み）を含む対局をしてもらう。（10-2, 4-10）

### 2-1. 測り方

`node scripts/cpu-mistake-report.mjs`（この設計のために作った開発用スクリプト）。

- 局面：20,000nodesの自己対局（上位3手から選ぶ）8局の、10〜74手目を8手おきに取った72局面。
  そのうち、互角に近い局面（審判の評価値の絶対値が1,500未満）の45局面だけを数える。
- 各レベルが、各局面で3回ずつ手を選ぶ（1レベル135手。旧CPUの測定では、境目の1局面の審判の評価が変わり138手）。
- 審判：80,000nodes。最善手と選んだ手を、同じ探索（MultiPV2・searchmoves）で比べる。別々の探索で比べると、揺れで損が大きく出る。
- 間違いの種類（5章）：損が300以上の手を、ロジックの取りの読みと詰みの探索で分ける。
  - 「駒を取られる」：取って取り返すまで（2手）の読みで、今より300以上駒を失い、最善手より300以上悪い。
  - 「取れる駒を逃す」：2手の読みで、最善手なら300以上の得があった。

### 2-3. 分かったこと

1. **1手で見える台無しの手が、上のレベルでも残っている。**
   今のLv20では、互角の局面の着手の約2%（2回の測定の合計）が「取って取り返すまでの読みで、800以上の駒を取られる手」だった。
   1局で互角に近い局面を40手指すとすると、1局に約1回。Lv30は約0.7%で、3〜4局に1回。エンジンの最善手では0%。
   300以上（銀・金を取られるくらい）まで含めると、Lv20・30とも約5%で、1局に約2回。
   七級〜一級の人が、これだけの頻度で1手で見える駒損をするのは多すぎる。
2. **典型例。** 今のLv20とLv25が、どちらも次の局面で▲8八金（7八の金を逃げる手）を選んだ。
   - 局面（先手番）：`1ns3s2/k2gg4/1ppppp+N1p/N5+Bp1/l1P3p2/2l1P1SP1/1P1P1P2P/2GS3R1/1K3G+l1L b RBPn2p 1`
   - 3九に相手の成香があり、4九の金に当たっている。▲3九金（4九の金で成香を取る）が最善。
   - CPUは7八の金への香の当たりに反応して逃げ、成香を取れるのに放置して4九の金を取られた（審判で約1,500の損）。
   - 気づいた当たりへの「逃げ」が、もっと大きな得（取れる駒）と比べられずに選ばれた。人間なら「取れる」に先に気づく。
3. **エンジンだけなら、少ない探索量でも強い。** 200〜1,000nodesの最善手の平均損失は88〜109で、今のLv30（179）より小さい。
   Lv11〜30の弱さは、探索量ではなく、手の選び方（大きな温度の抽選、わざと選ぶ見落とし）から生まれている。
   ノイズで弱くする限り、弱さは「ふだん正確で、ときどき理由のない大損」という形になる。
4. **新旧どちらも同じ形。** 今のCPUは旧CPUよりLv15・20の平均損失が小さいが、台無しの手は同じくらいの水準で残る（Lv30では今のほうが多い）。
5. **Lv10（ロジックAI）は、駒を取られる800以上の手が13.3%。** 18例すべてが、動かした駒をそのまま取られる手で、選んだ理由の多くは攻め（王手・玉への圧力）だった。
   入門者らしい手でもあるが、Lv11との差が大きく、段差の原因にもなる（10章の決めること3）。

## 3. 人間の考え方のモデル

### 3-1. 1手を決めるまで

人間は、合法手をすべて読むのではなく、目に付いた少しの手だけを、目に付いた応手だけで読みます。
この設計では、1手を次の7つの段階で決めます。どの段階も、レベルによって「どこまでできるか」が変わります。

| 段階 | 人間がしていること | CPUでの対応 |
|---|---|---|
| 1. 見る（知覚） | 直前の相手の手で何が変わったか。王手・当たり・成り込み・詰めろ。目立つものから気づく | `analyzePosition`の脅威と機会。気づくかどうかを、目立ち方・駒の価値・見えにくさで決める（3-3） |
| 2. 方針を決める | 序盤は作戦どおり。中盤は駒得か攻めか受けか。優勢なら安全に、劣勢なら勝負手 | 段階（序盤・中盤・終盤）、作戦、形勢による危険への態度（既存の`riskAttitude`） |
| 3. 候補手を挙げる | 気づいたことへの対応と、狙いの手、作戦の手を数手 | 気づいた脅威・機会への手、作戦の手、目的のある静かな手、見えたエンジンの上位手。数の上限はレベルで決める |
| 4. 読む | 候補ごとに、取る・王手・当たりのような強い応手を中心に数手読む | そのレベルの探索量の評価値と、そのレベルの手数の取り合いの読み |
| 5. 比べる | 読んだ先の局面を、駒の損得と形の良さで比べる。形の良さの判断はぶれる | 信念の式（4章）。見えていない損得は数えない。形勢判断に小さなぶれを入れる |
| 6. 指す前に確かめる | 「この手で駒を取られないか」「詰まされないか」をもう一度見る | 安全確認（4-5）。レベルが上がるほど確かめ損ないが減る |
| 7. 指す | 一番良いと思った手を指す | 信念の最大の手。理由と見落としを記録する |

### 3-2. 人間らしい間違いと、人間らしくない間違い

人間の間違いには、見えにくさの順序があります。弱い人ほど浅いところで間違え、強い人ほど深いところでしか間違えません。
同じ人が、ふだんは正確なのに、ときどき1手で見える大駒をただで渡す、ということはまずありません。

| 間違い | 例 | 人間らしいか |
|---|---|---|
| 見えなかった | 打つ手の両取り、遠くの角の利き、3手先の筋、長い詰み | 人間らしい。レベルが上がるほど減る |
| 形の判断が少しずれる | 駒の働き、玉の堅さ、攻めの速さの見積もりが100〜200点ずれる | 人間らしい。どのレベルでも多い。弱いほど大きい |
| 相手のミスを見逃す | プレイヤーのタダの駒を取らない、詰みを逃す | 人間らしい。低いレベルほど多い |
| 最初に気づいたことに引っ張られる | 当たりに気づいて逃げたが、もっと良い反撃（取り返し）を見なかった | 人間らしい。ただし大きな得を見逃すのは低いレベルだけ |
| 気づいていたのに、わざと悪い手を選ぶ | 当たりに気づいているのに、別の場所の歩を打つ | 人間らしくない |
| 1手で見える大損を、ふだん正確な手の合間に混ぜる | 直前の手で当たりになった飛車を放置する（Lv20以上） | 人間らしくない。対局を台無しにする |
| 意味のない手 | 関係ない端歩、9二香 | 人間らしくない（対策済み） |

この設計の原則は次の2つです。

1. **CPUは、見えたものの中では最善を尽くす。** 弱さは、見え方（気づき・読みの深さ・形の判断）の限界から出す。
2. **そのレベルに見えるはずのものは見落とさない。** レベルごとに「必ず見える」範囲を決め、その範囲の大損は指す前の確認で防ぐ。

### 3-3. 見えにくさの決まり方

気づく確率は、次の4つで決まります。どれも、人間の見落としの傾向に合わせたものです。

1. **目立ち方**：直前の相手の手で生まれた当たり・王手は目立つ。前からある当たり、別の場所の当たりは目立たない（既存の`salience`）。
2. **駒の価値**：大駒・金銀への当たりは、歩への当たりより気づきやすい。取られる価値が大きいほど気づく。
3. **駒の動き方**（新しく足す）：次の手は見えにくい。

   | 見えにくい手 | 見落とし率の倍率 |
   |---|---:|
   | 持ち駒を打つ手（歩の叩き、桂打ちの両取り、角打ち） | 2.0 |
   | 遠くからの利き（3マス以上離れた飛・角・香） | 1.6 |
   | 後ろへ下がる手での取り | 1.6 |
   | 空き王手・素抜き（手前の駒が動いて、後ろの駒の利きが通る） | 2.5 |
   | 直前の手から遠い場所（4マス以上） | 1.4 |

4. **手数**：1手で見えるもの、3手で見えるもの、5手以上で見えるもの。詰みは手数が長いほど見えにくく、捨て駒を含むとさらに見えにくい。

見落とし率は、レベルの基準値（6-2）に、当てはまる倍率をすべて掛けて決めます。上限は60%です。
例：基準の見落とし率4%のレベルで、打つ手（2.0）かつ遠くの利き（1.6）なら、約13%。
レベルの基準値が0なら、倍率を掛けても0です。強いレベルでは、見えにくい手でも見落としません。

同じレベルのCPUは、いつも同じ種類の手を見落としやすくなります。
プレイヤーは「このLvは桂の両取りに弱い」と覚えて、勝ち筋にできます。（→D:4-5）

## 4. ロジックと評価値の組み合わせ（信念のモデル）

### 4-1. 二つの目：CPU自身の目と、審判の目

- **CPU自身の目（信念）**：そのレベルの人が、その局面をどう見ているか。気づいたこと、読めた手数、形の判断（ぶれを含む）でできている。手はこれで選ぶ。
- **審判の目**：深い読みによる本当の評価。手を選ぶのには使わない。使うのは、テストと校正（どのくらい損をしたか、どの種類の間違いか）だけ。

今のCPUは、エンジンの評価値（審判に近い目）で候補を並べてから、大きな温度の抽選でわざと外していました。
この設計では、CPU自身の目で一番良い手を選びます。弱さは、目の解像度の低さから出ます。

### 4-2. 信念の式

候補手`c`の、CPUから見た良さ（信念）を次の式で決めます。

```
信念(c) = 見えている駒の損得(c)
        + w × ( 評価値_N(c) − 全部見えたときの駒の損得(c) )
        + 詰みの項(c)
        + 判断のぶれ(c)
        + 好み(c)
```

| 項 | 意味 | 作り方 |
|---|---|---|
| 見えている駒の損得 | CPUが読めた範囲の駒の損得 | ロジックの取りの読み。気づいた当たりだけを、レベルの手数`d`まで読む |
| 評価値_N | そのレベルの読み | やねうら王を、そのレベルの探索量`N`で読んだ評価値 |
| 全部見えたときの駒の損得 | 取り合いをすべて読んだときの駒の損得 | ロジックの取りの読み。すべての当たりを6手まで読む |
| w × (…) | 大局観 | 評価値から駒の損得を除いた残り（駒の働き・玉の堅さ・深い筋）。重み`w`は、形の判断の確かさ |
| 詰みの項 | 気づいた詰みだけを数える | 4-3 |
| 判断のぶれ | 形勢判断のずれ | 候補ごとに正規分布（標準偏差σ）から1回引き、その手番の間は固定する |
| 好み | 作戦・棋風・分かりやすさ | 既存の加点（`logicBonus`）。上限も既存のまま |

CPUは、信念が最大の候補を指します（同点なら自然さの高い手）。抽選の温度は使いません。ばらつきは「判断のぶれ」と「気づき」のくじだけから出ます。

すべてに気づき、取り合いを最後まで読み、`w = 1`のレベルでは、式は次のようになります。

```
信念(c) = 評価値_N(c) + 判断のぶれ(c) + 好み(c)
```

つまり、上のレベルほど「エンジンの評価値に小さなぶれ」で選ぶことになり、Lv40（ぶれなし・最善手だけ）へなめらかにつながります。
下のレベルほど、ロジックで見えている駒の損得の比重が大きくなり、Lv10（ロジックAI）へなめらかにつながります。

注意：やねうら王の評価値と、ロジックの駒の価値（歩100・香300・桂400・銀500・金600・角800・飛1000）は、どちらも歩を約100とする尺度で、近い値です。
実装では、静かな局面で「評価値 − 全部見えたときの駒の損得」がおおむね±600に収まることを確かめます。

### 4-3. 各項の作り方

#### 見えている駒の損得

- 候補を指したあと、相手の取り・成りを読む（既存の`replyLoss`）。ただし次の2つを除く。
  - 気づかなかった当たりのマスへの取り（最初の1手から除く）。
  - レベルの手数`d`より深い取り合い。
- 候補を指したあとの自分の駒の安全（指したあとに取られないか）も、候補ごとに気づくかを決める。

  | 指したあとの当たり | 見えやすさ |
  |---|---|
  | 動かした駒そのものが取られる | 見えやすい（基準の見落とし率の半分） |
  | 動かしたことで、守っていた駒の守りが外れる | 見えにくい（基準のまま） |
  | 動かしたことで、相手の遠い駒の利きが通る | 見えにくい（遠い利きの倍率を掛ける） |

気づかなかった当たりの損は「見えている駒の損得」に入りません。CPUはその損がないと思って指し、実際に駒を取られます。これが見落としです。
気づいていた当たりの損は必ず入るので、気づいたのにわざと放置する手は生まれません。

#### 詰みの項

- 評価値が詰み（自分が詰ます、または詰まされる）を示す候補は、詰みの手数`n`ごとの確率で、CPUがその詰みに気づくかを決める。
- 気づけば、詰ます手は最優先、詰まされる手は除く。
- 気づかなければ、評価値の代わりに、見えている駒の損得と、王手・玉の周りの利きの加点（ロジックAIの終盤の点数）で比べる。
  詰ます手を、ただの「良い攻めの手」として見ることになる。
- 自分の詰みに気づく確率は、`p(n) = 1 / (1 + exp(−(c − n)))`。`c`は、そのレベルで半分の確率で見える手数（6-2）。捨て駒を含む詰みは`c`を1下げる。
- 相手の詰み・詰めろに気づく確率も、同じ形で、別の値`c'`で決める。弱いレベルほど`c'`が`c`より小さい（攻めには気づくが、受けには気づきにくい。→D:4-9）。

#### 判断のぶれ

- 正規分布のぶれだけで、本当は300点悪い手を選ぶ確率は、σ=150のとき約8%、800点悪い手は約0.01%です（2手の比較）。
- 大きな損の多くは、ぶれではなく「見えなかったこと」から生まれます。人間の損の分布（小さなずれは多く、大きな損はまれで理由がある）に近い形です。
- 序盤（作戦の定跡手があるうち）は、ぶれを半分にする。定跡を覚えている人は、序盤では迷いが少ない。

#### 好み

- 既存の加点（作戦の定跡手、棋風、分かりやすい手、受からないときの方針）をそのまま使う。上限も既存のまま。
- 好みは、ぶれの前に足す。人間も、同じくらいに見える手なら、好きな形を選ぶ。

### 4-4. 候補の挙げ方

- 既存の`chooseAwareMove`と同じ行（王手の回避、気づいた脅威への逃げ・受け・取り、気づいた機会、作戦、静かな目的のある手、エンジンの上位手）を使う。
- 候補の数の上限`K`をレベルで決める（6-2）。上限で落ちる手は「目に付かなかった手」になる。
- 気づいた脅威への応手は、「逃げ」だけでなく「攻めている駒を取る」「取り返せるように守る」も必ず並べる。
  今のCPUは逃げを選んで、攻めている駒を取る手と比べ損ねていた（2-3の2.）。比べるのは信念で行う。
- エンジンの最善手・2〜3位が見えるかは、レベルの確率で決める（既存の視認率）。見えなかった最善手は候補に入らない。
- 目的のない手は候補にしない（既存）。

### 4-5. 指す前の安全確認と、台無しの手を防ぐ仕組み

信念で選んだ手について、指す前に、ロジックだけで次を確かめます。

| 確かめること | 種類 | 計算 |
|---|---|---|
| 指したあと、相手の取り（取り返しまで）で駒を損しないか | A級 | 取りの読み2手 |
| 相手の1手詰めがないか | A級 | 1手詰めの探索 |
| 自分の1手詰めを逃していないか | A級 | 1手詰めの探索 |
| 取り合いを最後まで読むと損しないか | B級 | 取りの読み6手 |
| 相手の3手詰めがないか | B級 | 3手詰めの探索（時間の上限つき） |

- 確認で間違いが見つかったら、その手を捨てて、信念が次に高い手を同じように確かめる（最大3手。全部だめなら、確認で見つかった損が一番小さい手）。
- 確認に成功する確率は、レベルと損の大きさで決める（6-2の表3）。大きな損ほど確かめ損ないが少ない。
- **台無しの手**（5-2）は、レベルごとの1局の上限を超えて指さない。上限を使い切ったら、その種類の確認は必ず成功する。
- **狙いのある捨て駒**は、確認で止めない。CPU自身の読み（評価値_N）で、取られた駒の分を、`d`手以内の取り返しか、気づいた詰みで取り戻せる手に限る。
  Lv25までは、それ以外の捨て駒（読みの裏付けのない攻め）を止める。人間の級位者は、読み切れない駒損をあまりしない。
- 確認はロジックだけで行い、エンジンを追加で使わない。1手あたりの追加は数十ミリ秒の見込み。

### 4-6. 計算の量と時間

- エンジンの探索は、今と同じく「本体の探索1回」と「候補の追加評価1回」だけ。危険への態度の追加の読み（`probe`）は今のまま。
- 審判の深い読みは、対局中には使わない（測定スクリプトだけ）。
- ロジックの計算（気づき、見えている損得、安全確認、詰みの探索）は、今の600ミリ秒の上限の中で行う。
- エンジンは同時に1つの探索しか処理できない決まり（`AGENTS.md`）を守る。追加の探索は直列に行う。
- 今の「わざと選ぶ見落とし」の追加探索（`tryOversight`の検証）はなくなるので、探索の回数は今より減る。

### 4-7. 理由と見落としの記録

選んだ手ごとに、次を残します（既存の`reason`・`missed`を広げる）。

- 選んだ理由：作戦、駒得、逃げ、受け、攻め、詰み、など。
- 気づかなかったこと：当たりの見落とし（どの駒か、なぜ見えにくかったか：打つ手・遠くの利き など）、詰みの見落とし。
- 安全確認で捨てた手（「最初に考えた◯◯は、銀を取られるのでやめた」）。

対局後の振り返りで、やこび姫が「この手で、CPUは角の利きに気づかなかったみたい」と説明できます（後の段階）。

**台無しの手**は、互角に近い局面（評価値±1,500以内）から、1手で800点以上を失う手、または詰みを許す手とします。

台無しの手のうち、A級とB級は、ロジックで対局中に見つけられます。
C級は深い読みでしか分からないので、対局中には数えず、探索量で自然に減らします。

## 6. レベルごとの設計

### 6-1. 帯ごとの人物像

| 帯 | Lv | 段級位 | 見えるもの | よくある間違い | 指し方 |

## 7. 丁度良い難易度

### 7-1. 目標

- 各Lvは、旧CPUの同じLvより少し弱くする（ユーザーの指示）。どれだけ弱くするかは10章で決める。
- 同じ段級位を自己申告した人が、同じ表示名のLvに数十局指して勝率50〜60%になること（→D:4-10。少し易しめ）。
- 隣のLvより確かに強いこと（自己対局で上のLvが55%以上）。
- 難易度は対局中に黙って変えない（→I:11）。負けが続いたときは、既存の「Lvを1つ下げる／香落ち」の提案を使う（→D:4-3）。

### 7-2. 測る指標と目標

2章と同じ局面・同じ測り方で、旧CPUと比べた目標です（局面の鋭さに左右されないよう、絶対値ではなく旧CPUとの比で決める）。

| 指標 | 目標 |
|---|---|
| 平均損失（1手1,000で打ち切り） | 旧CPUの1.0〜1.2倍（少し弱い） |
| 100〜300の小さな損 | 旧CPUより多くてよい（弱さの主な出どころ） |
| 800以上の損 | 旧CPUの半分以下 |
| 駒を取られる（800以上） | Lv11〜15は0.5%以下、Lv16以上は0%（エンジンの最善手と同じ水準。審判の揺れと狙いのある捨て駒の分は残る） |
| 旧CPUとの得点率 | 10章の決定による（案：同じLvの旧CPUに35〜45%） |
| 隣のLvとの得点率 | 上のLvが55%以上 |
| 1手の時間 | 今以下（600ミリ秒の上限、`tryOversight`の追加探索がなくなる分は減る） |
| 人間の勝率 | 申告した段級位のLvで50〜60%（`human-calibration-report.mjs`） |

### 7-3. 校正の順序

1. 台無しを防ぐ仕組み（安全確認と上限）を入れ、「駒を取られる（800以上）」が目標に入ることを確かめる。
2. 判断のぶれσと候補数Kで、平均損失を目標に合わせる。
3. 旧CPUとの自動対局で、強さの目安に合わせる。足りなければ、気づき（特にプレイヤーのミスに気づく率）と探索量Nを動かす。
   台無しを防ぐ仕組みは、強さ合わせのために緩めない。
4. 隣のLvとの段差を確かめる。特にLv10→11（ロジックAIとの境目）。
5. 実際に人に指してもらい、勝率と感想を集める。

## 8. 確かめ方

### 8-1. 自動テスト

- 安全確認：飛車がタダで取られる局面、1手詰めを許す局面、1手詰めがある局面、2-3の2.の局面を用意する。
  Lv16以上は、乱数を変えた数百回の選択で、A級の台無しを一度も選ばない。
- 台無しの上限：上限を使い切った手番では、Lv11でも台無しの手を選ばない。
- 見落としの一貫性：同じ乱数なら同じ手を選ぶ。気づいた当たりの損は信念に必ず入る（わざと放置しない）。
- 狙いのある捨て駒：CPU自身の読みで取り戻せる捨て駒は、確認で止めない。
- 詰み：手数ごとの確率が設定どおりになる（統計の許容幅で）。
- 先後：同じ局面を反転しても、同じ手（反転した手）を選ぶ。
- 目的のない手：0（既存のテストを保つ）。
- Lv40：設定と最善手選択が変わらない（既存）。

### 8-2. 測定

- `scripts/cpu-mistake-report.mjs`で、レベルごとの間違いの種類と台無しの割合を測る（2章の表）。
- 強さは`scripts/cpu-level-selfplay.mjs`の自動対局（旧CPUとの比較、隣のLvとの比較）で測る。

### 8-3. 手で指す確認

作り手以外の人に、次の場面を含む対局をしてもらいます（→D:10-2, 4-10）。デスクトップ・スマホ縦・タブレット縦で行います。

- プレイヤーが飛車に当たりをかけたとき、CPUが逃げるか、攻めている駒を取るか（Lv16以上は必ず対応する）。
- プレイヤーが駒をタダで置いたとき、CPUが取るか（低いLvでは、見えにくい場所なら見逃すことがある）。
- 桂打ちの両取り・歩の叩き・遠い角の利きを、低いLvが見落とすか。上のLvが見落とさないか。
- CPUが攻めてくるか。受け切ったあと、逆転の筋があるか。
- 負けたとき、なぜ負けたかが振り返りで分かるか。
- 「強すぎる」「弱すぎる」「急に変な手を指した」と感じた場面を、棋譜と一緒に記録する。

### 12-1. 10章で決めたこと

ユーザーへは確かめず、次のように決めました（AGENTS.mdの「迷っても質問せず、自分で決めて進めます」）。

1. **どれだけ弱くするか → 案A（今の表と同じ強さにそろえる）**。この設計を書いたあと（2026-10-22・23）に、段級位の表を作り直して50段階にし、強さを`source`で測り直しました。「前までのCPUはちょっと強すぎました」は、その作り直しで直してあります。レーティング・棋力測定の表（`LOG_LOSS_TABLES`）・大会の世界の物差し・観戦の本局の強さの表（`LEVEL_STRENGTH`）は、今の表の強さで測ってあるので、強さを動かすと全部を測り直すことになります。この実装では、強さはそのままにして、**負け方（間違いの形）だけを人間らしく変えます**（D:4-10 丁度良い難易度、D:4-9 理不尽に感じさせない）。
2. **低いLvに大きな見落としを残すか → 案A（残す）**。もとの校正のLv11〜15では、A級の台無しを確認で防ぐ率を90〜98%にし、残りは悪手の回数（`blunderAllowed`）の範囲で出ます。
3. **ロジックAI（Lv1〜9）に入れるか → 今回は入れない**。今のLv1〜9（24級〜16級）は、2026-10-23に気づく確率で強さを分けて作ったばかりで、入門者は駒を取られて覚える段です。気になる報告があれば、次の段階で案Bを入れます。

### 12-2. 作ったもの

- `src/core/human-model.mjs`（新規）：
  - レベル表`HUMAN_TABLE`と`humanSettingsForLevel(level)`（もとの校正のLvで引く。点の間は直線）。気づきの見落とし率（表2の直前の大駒・小駒への当たり・ほかの当たり・取れる駒・両取り）、確認で防ぐ率（表3のA・B・小さな損）、判断のぶれ`sigma`。
  - 見えにくさの倍率`threatHardness`・`chanceHardness`（3-3。遠くからの利き1.6倍・直前の手から遠い当たり1.4倍、打つ手2倍・下がる取りと遠くからの取り1.6倍。上限60%）と、それを気づきに掛ける`humanPerception`。
  - 判断のぶれ`pickByBelief`（4-3）：候補ごとに正規分布のぶれを1回引き、点＋ぶれが最大の手を選ぶ。温度の抽選（ガンベルのぶれ）と同じ大きさ（標準偏差の倍率1.28＝π/√6）にして、裾だけを軽くした。800点悪い手は、ぶれだけではほとんど選ばない。
  - 指す前の確認（4-5）：`blunderKind`（A：取り返しまでの読みで800以上の損、または相手の1手詰めを許す。B：取り合いを4手読むと800以上の損。small：取り返しまでで300〜800の損。基準は最善の候補の同じ読みの損）と`preventsBlunder`（レベルの確率で止める。悪手の回数を使い切ったら、AとBは必ず止める）。1手詰めの確かめ`allowsMateInOne`は、詰みの探索（`problem-solver.ts`）を呼ぶ側から渡す。探索が上限に達したときは詰みと数えない。
- `src/core/aware-move-choice.mjs`：`strength.human`があれば、気づきに見えにくさを掛け、目に付いた手（浅い読みの手）も確認し、温度の抽選の代わりに判断のぶれで選び、確認で止めたら次に良い手を同じように確かめる（最大4手。全部止めたら最善手）。わざと選ぶ見落とし（`tryOversight`）はしない。止めた手は`prevented`、選んだ手の間違いの種類は`blunderKind`に残す（4-7の記録の始まり）。
- `src/core/strength-settings.mjs`：エンジンの校正の設定に`human`を入れる（`HUMAN_MODEL_DEFAULT`）。対局で人間らしい選び方になるのは、`chooseAwareMove`で指す**Lv10〜48（15級〜タイトル保持者）**。Lv1〜9はロジックAI（`chooseLogicMove`）で指すので使われない。Lv0（練習相手）とLv49（藤井聡太並み。最善手だけ）は変えない。観戦の本局（`engine-game.mjs`）も同じ選び方で指す。
- 測る道具：`scripts/cpu-level-selfplay.mjs`の選手指定に`classic`（今までの選び方。例：`L28classic`）と`sig<倍率>`（例：`L10sig1.6`）、`scripts/cpu-mistake-report.mjs`に`--classic`。
- テスト：`src/core/human-model.test.mjs`（表の単調さ・見えにくさ・ぶれの裾・A級の判定・1手詰め・止める確率・乱数を変えた120回の選択で、当たりの金を放っておく台無しの手を一度も選ばない。今までの選び方は選ぶ）。

### 12-4. 間違いの種類（今までの選び方と比べる）

- 「駒を取られる（800以上）」は、もとのLv12で4.4%→3.5%、Lv20で1.6%→0.6%に減った。ただし7-2の目標（Lv16以上で0%）には届いていない。残りは、審判の深い読みでは駒損だが、ロジックの取り返しまでの読みでは損に見えない手（取り返しの先の損・王手をかけながらの損）。確認の読みを深くするのが次の候補。
