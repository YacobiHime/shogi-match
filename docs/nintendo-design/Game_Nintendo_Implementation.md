# Game_Nintendo_Implementation ― 桜井政博・任天堂のゲーム論に基づく実装ルール

コードを書く・直すときに参照する文書です。演出・音・ほめ言葉・ご褒美・難易度・教え方・負けたときの流れを実装するときの決まりをまとめます。

- 「何を作るか」「なぜそうするか」は`Game_Nintendo_Design.md`にあります。`→D:3-2`や`[D:3-2]`はその章番号です。
- 画面・操作・文言の一般的なルールは`UI_Nintendo_Implementation.md`にあります。`→U:6`はその章番号です。`→N:4-2`は`UI_Nintendo.md`の章番号です。
- このリポジトリの決まり（`AGENTS.md`）は、この文書より優先します。食い違ったら`AGENTS.md`に従い、この文書を直します。

数値は**初期値**です。出典に数値がないものは「→ 補足」の扱いで、実際に触って調整してかまいません。調整したら、その表の値も直します。

## 1. 実装の優先順位

1. **将棋として正しい**：合法手・反則・詰み・評価値・棋譜を、演出やご褒美のために変えない。
2. **反応がある**：入力したら、まず反応を返す（→D:3-1）。
3. **待たせない**：演出でプレイヤーの操作を止めない（→D:3-3）。
4. **重さが伝わる**：出来事の重要度に応じて、止め・音・見た目・台詞を変える（→D:3-2）。
5. **続けたくなる**：ほめ言葉・ご褒美・次の目標（→D:5）。

- 下位のために上位を落とす変更はしません。例：神の一手の演出を見せるために、次の手を指せない時間を作らない。
- 演出の変更と、判定（合法手・神の一手の基準・難易度の値）の変更は、同じ変更に混ぜません。判定を変えるときは、その判定のテストを先に直します。

## 3. 出来事の重さと演出（→D:3-1, 3-2, 3-4, 4-8）

### 3-1. 重さの段階

出来事を次の段階に分け、段階が上がるほど強く見せます。同じ段階の出来事は、同じ強さで見せます。

| 段階 | 出来事の例 | 止め（初期値） | 音 | 見た目 | やこび姫 |
|---|---|---|---|---|---|
| 0 | メニュー操作、駒を選ぶ | なし | UIの音（あれば） | 押した表示 | なし |
| 1 | 通常の着手 | なし | 駒音（普通） | 着地の動き | なし |
| 2 | 駒を取る、成る | なし〜50ms | 駒音（普通） | 取った駒が駒台へ動く、成りが分かる | なし |
| 3 | 大駒を取る、王手 | 80ms | 駒音（強い） | 王手の知らせ | 必要なら一言 |
| 4 | 好手、詰めろを掛ける、受け切る | 80ms | 駒音（強い） | 指した駒を強調 | 何が良かったかを一言 |
| 5 | 神の一手 | 250ms | 専用の音 | 盤の光り、短い揺れ | 何が良かったかを一言 |
| 6 | 詰ませる（勝ち）、逆転 | 400ms | 専用の音 | 止め → 終局の演出 | 勝ちの台詞 |

- 止めの長さは→ 補足です。桜井氏は「攻撃の強さで長さを変え、上限を設ける」ことを示していますが [D:3-2]、具体的な値は示していません。
- 段階は、判定済みの結果から決めます。演出のために新しい判定を足す場合は、判定の関数（例：`god-move.mjs`）に足し、テストを書きます。
- 負け・やられの段階（悪手を指した、詰まされた）は、7章のルールに従い、勝ちより短く控えめにします。

### 3-2. 止め（ヒットストップ）の入れ方

- **プレイヤーの入力は止めません。** 止めるのは「次に起きること」（CPUの応手の表示、終局画面の表示）の開始です。止めている間に盤を触ったら、止めを打ち切ります（→U:8「演出中に操作を受け付けないこと」）。
- 止め・揺れ・光りの合計は1.5秒以内にします（→U:6）。
- **揺れは見た目だけにします。** 盤の座標・クリックの判定・矢印の位置は揺らしません。『スマブラ』のヒットストップでも、揺れるのは見た目だけで、当たり判定は動かしません（`Game_Nintendo_Design.md`の出典G5『8つのヒットストップ仕様』）。
- 揺れは大きく始めて、だんだん小さくします。振幅は段階に比例させます。
- 光らせるときは、盤の木目（黄色系）の上で消えないよう、暗い色を混ぜるか、縁や影で示します。升の強調に黄色を使わない決まりは守ります（`AGENTS.md`の「盤面の色の使い分け」）。
- `prefers-reduced-motion: reduce`のときは、揺れ・拡大・移動をなくし、色の変化と音だけ残します。止めの時間は残してかまいません。

### 3-3. 音

- 音量は重要度で決めます。重要度は3-1の段階の順です。同時に鳴るときは、段階の高い音を優先し、低い音は鳴らさないか小さくします [D:3-4]。
- 音は立ち上がりを強く、余韻を短くします。主な部分は、止めの間に鳴り終わるようにします（桜井氏『アタック強め、残響ほどほど』の応用）。
- 音の種類を増やすときは、`move-sound.ts`の`MoveSoundKind`と`selectMoveSound`に足し、判定のテストを書きます。音声ファイルは`public/audio/`に置きます。
- 音だけで意味を伝えません。同じ出来事を、必ず見た目でも伝えます（→U:5）。
- 安いスピーカーやスマートフォンの内蔵スピーカーでも聞き分けられるか確かめます（桜井氏『色んな環境で聞き比べ』）。

### 3-4. 無反応をなくす

- 押した・触ったら、処理の完了を待たずに反応します（→U:6）。
- 指せない手を選んだときも、駒が元の位置へ戻るなど、責めない形で反応します。
- 時間のかかる処理（CPUの思考、解析）は、進み具合か「考えている」ことを見せます。いまはCPUの思考ゲージ（`useCpuSearchGauge.ts`）があります。

## 4. 時間（→D:3-3, 7-1, 9-1）

| 対象 | 初期値 | 根拠・メモ |
|---|---|---|
| ページを開いてから最初の1手まで | ホームの「つぎはこれ」を押して、すぐ対局が始まる | →D:3-3『とにかくゲームさせてみて』 |
| 終局から「もう一度」を押せるまで | 終局の演出の開始と同時に押せる | →D:7-1 |
| 終局の演出 | 1.5秒以内、タップで飛ばせる | →U:6 |
| 負け・やられの演出 | 勝ちより短く。1秒程度 | →D:7-1。派手でも短く |
| 止め（段階3〜6） | 3-1の表 | → 補足 |
| 王手の知らせ | いまの実装の値を使う | `checkCallout` |
| やこび姫の助言の最低表示 | 6秒 | `COACH_ADVICE_MIN_DISPLAY_MS` |

- 長い演出・台詞・自動の再生（振り返りなど）は、必ず飛ばせるか止められるようにします（桜井氏『必ず飛ばせるように、止められるように』）。
- 解析などで待たせるときは、待ち時間に意味を持たせます（→N:3-6）。例：解析中に、その局面の考え方を一言出す。

## 5. ほめ言葉（→D:5-4, 5-8, 4-8）

- **何が良かったかを1文で言います。** 「すごい！」だけで終えず、「大駒の両取りだね」「詰めろを外しながら受けたね」のように、盤上の事実を添えます。
- ほめる強さは、手の良さ・見つけにくさに見合わせます（3-1の段階）。ありふれた良い手（駒得、受け切り）も、段階4として拾います。
- 神の一手は1局3手までです（`GOD_MOVE_LIMIT`）。上限を増やすと特別さが薄れるので、増やす前に設計を見直します。
- 同じ褒め言葉を続けて出しません。助言の重複の制限（`COACH_ADVICE_REPEAT_PLIES`）を使います。
- 危険の知らせ（詰み・王手・悪手）は、褒め言葉より優先します（`coachAdvicePriority`）。直前の手への褒め言葉は、CPUの手のあとの通常の助言に上書きされないようにします（いまの実装どおり）。
- 判定は対局中と棋譜解析で同じ基準を使います（`god-move.mjs`）。対局中だけ甘くする、といった別の基準を作りません。
- 支配的な言い方（「〜しなさい」「〜すべき」）を避けます。ほめ言葉は、情報として伝わる形にします [D:5-8]。

## 6. ご褒美と記録（→D:5-1〜5-7, 9-2）

### 6-1. ご褒美を足すときの手順

1. **使い道を先に決めます。** 手に入ったものが、何に使えるか（盤・駒の見た目、新しい相手、台詞、図鑑の印など）を決めてから作ります [D:5-1]。
2. **条件は将棋の行為にします。** 勝つ、囲いを完成させる、問題を解く、強い相手に挑む、など。ログインした日数や遊んだ時間だけを条件にしません [D:5-7, 9-1]。
3. **次までの残りを見せます。** 対局中か対局直後に、次の目標と残りが見えるようにします [D:5-2]。
4. **まだ持っていないものは、存在だけ見せます。** 名前やシルエットを見せ、全部を最初から渡しません [D:5-1]。
5. **数える範囲を明記します。** レーティングと同じく、対象（平手の通常対局だけ、など）を決め、READMEにも書きます。
6. **保存は端末に、壊れても遊べるように。** `localStorage`のキーは`yacobihime:shogi-match:<名前>`の形にし、形を変えるときは`:v1`などの版を付けます。読み込みに失敗しても、遊びは止めません。

### 6-2. 数字の見せ方

- 数字は身近な尺度に直して見せます。レーティングは級・段で見せます（いまの実装どおり）[D:5-5]。
- 順位を出すときは、自分の近くを中心に見せ、大きな順位の数字で恥をかかせません [D:5-6]。
- 下がった値は隠しませんが、強調もしません。上がった値と次の目標を先に見せます。

### 6-3. 連続記録・習慣

- 連続記録を作るなら、途切れても責めない仕組み（休みを認める、記録を「最長」で残す）を同時に作ります [D:9-2]。
- 「今日やらないと失う」という形で急かしません。

## 7. 負けとやり直し（→D:7）

- 負けの演出は短く、責めない言葉にします。「残念」「失敗」より、次にすることを伝えます（→U:4）。
- 終局画面では、次の挑戦（もう一度、振り返る）をすぐ押せる位置に置きます。
- 敗因は、まず1つに絞って見せます。全部の悪手を並べるのは、振り返りの中で行います（`guided-review.mjs`）。
- やり直しの単位を小さくします。対局全体だけでなく、局面（敗着の前など）からやり直せる形を優先します。局面から始める仕組み（学習対局の開始局面、感想戦）を使い回します。
- 何度も負けたときに難易度を下げる提案は、自動で下げず、選べる形にします。文言は「挑戦を続ける」選択肢と並べ、恥ずかしくない言い方にします [D:4-3]。
- 大会（竜王戦）のように進行がある遊びでは、負けて先へ進めない状態が長く続かないようにします（敗者復活、昇級・降級の仕組み）[D:4-3, 4-4]。

## 8. 難易度とCPU（→D:4）

- CPUの強さの上限はLv40です。それより強いレベルは足しません（`AGENTS.md`）。強さの値を変えたら、`docs/difficulty-calibration.md`を直します。
- 難しさは、作り手の手応えではなく、測った値（平均損失、勝率）で決めます [D:4-10]。
- 弱いレベルのCPUは、人間がよくする間違い（駒をタダで取られる、詰みを見逃す）で負けるようにし、意味のない手（不自然な端歩など）で弱さを出しません。手の自然さの判定（`move-naturalness.mjs`）を使います [D:4-9]。
- CPUは「攻撃的だが倒せる」ように作ります。完璧に受け切るだけのCPUにしません [D:4-9]。
- 棋士の個性（棋風、得意・苦手）は、一言で言えるくらい大きく振ります。勝率は`ryuo-strength.mjs`のレーティングでそろえ、個性は削りません [D:4-7, 8-1]。
- 難易度を選ぶ画面では、強い相手を選ぶことに見返り（記録・称号）があると分かるようにします [D:4-2]。
- プレイヤーが見つけた勝ち筋（CPUが同じ手に引っかかる、など）は、将棋として正しい範囲なら、すぐには塞ぎません [D:4-5]。

## 9. 教えること（→D:6）

- 盤の上で、触らせながら教えます。説明の文は1〜2文にします（→N:4-2, 4-3）。
- 同じ説明は、最初の数回だけ詳しく出し、慣れたら短くします。王手の知らせ（最初の3回だけ説明）と同じやり方にします。
- 課題は「誘導つき」から「自由」へ移します。例：「この駒をここへ」→「詰ませる手を探そう」[D:6-4]。
- 正解は問題に書かず、探索で決めます（`AGENTS.md`、`problem-solver.ts`）。別の正しい答えを不正解にしません。
- 前に学んだことを、間をあけてもう一度使わせます（例：前の章の手筋を、後の章の問題に混ぜる）[D:6-4]。
- 攻略法を1つに決めつけません。複数の正解があるなら、どれも正解として扱います [D:6-3]。

## 10. キャラクターと台詞（→D:8）

- やこび姫の台詞は短くします。盤を隠す長い吹き出しや、対局を止める会話を、対局中に出しません [D:8-2]。
- 表情は出来事と一致させます。褒め言葉で心配顔にしない、悪手で笑顔にしない（`coach-expression.mjs`）。
- 長い物語や説明は、対局の外（教室、大会の幕間）で見せ、飛ばせるようにします [D:8-2]。
- 棋士の台詞は、その棋士の棋風と一致させます（攻め将棋の棋士は攻めの言葉、など）[D:8-1]。
- 観戦や他の対局の結果を見せるときは、肩入れする理由（好きな棋士、予想、対戦成績）を添えます [D:8-3]。

## 11. 避けること

| 避けること | 理由 |
|---|---|
| 演出のために合法手・判定・評価値を変えること | 将棋として正しいことが最優先（1章） |
| 演出中にプレイヤーの操作を受け付けないこと | 待たせる（→D:3-3、→U:8） |
| 盤の座標やクリックの判定まで揺らすこと | 揺れは見た目だけ（3-2） |
| すべての手に同じ強さの演出を付けること | 特別な瞬間が埋もれる（→D:3-2） |
| 中身のない褒め言葉（「すごい！」だけ） | 情報にならず、慣れると響かない（→D:5-8） |
| 神の一手などの上限を安易に増やすこと | 特別さが薄れる（5章） |
| 使い道のないご褒美 | 集める動機にならない（→D:5-1） |
| ログイン日数・遊んだ時間だけを条件にしたご褒美 | 遊びが義務になる（→D:5-8, 9-1） |
| 途切れたら責める連続記録 | 遊びが義務になる（→D:9-2） |
| 低い順位を大きく見せること | 恥をかかせる（→D:5-6） |
| 長い負けの演出、責める言葉 | 次の挑戦が遠のく（→D:7-1） |
| 難易度を黙って自動で下げること | 選ぶのはプレイヤー（7章） |
| 意味のない手でCPUの弱さを出すこと | 理不尽に見える（→D:4-9） |
| Lv40より強いCPU対局のレベル | 決まりに反する（`AGENTS.md`） |
| 対局中の長い会話・説明 | 盤（主役）を隠す（→D:8-2、→N:2-5） |
| 盤の升の強調に黄色を使うこと | 木目と区別できない（`AGENTS.md`） |
| 対局画面から教室・問題集・図鑑の重いモジュールを静的にimportすること | 最初に読むJSが重くなる（`AGENTS.md`） |

## 12. 実装後のチェックリスト

**正しさ**
- [ ] 合法手・判定・評価値・棋譜が、演出の変更で変わっていない
- [ ] 判定を変えた場合、その判定のテストを直した
- [ ] `npm test`、`npm run build`、`npm run typecheck`、`git diff --check`が通る（`AGENTS.md`）

**反応・演出**

- [ ] 出来事の段階（3-1）に応じて、止め・音・見た目・台詞が変わる
