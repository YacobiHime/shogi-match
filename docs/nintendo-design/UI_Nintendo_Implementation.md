# UI_Nintendo_Implementation ― 将棋WebアプリのUI実装ルール

コードを書く・直すときに使う実装ルールです。設計上の判断（何を作るか、優先順位、確認ダイアログの方針など）は `UI_Nintendo_Design.md`、その根拠は `UI_Nintendo.md` にあります（`→D:` は Design、`→N:` は Nintendo の章番号）。

数値は**初期値**です。テストで調整してよく、調整したら6章の表を更新します。

---

## 1. 優先順位

1. 迷わない・間違えない → 2. 待たせない → 3. 説明なしで伝わる → 4. 気持ちいい → 5. 装飾（→D:2）

- UIの変更とゲームロジック（合法手判定・CPU思考・棋譜）の変更は、同じ変更に混ぜません。
- 下位（演出）のために上位（わかりやすさ・速さ）を落とす変更はしません。

## 2. 盤面操作

### 2-1. 状態

| 状態 | 表示 |
|---|---|
| `idle` | 直前の一手（移動元・移動先）を薄く色付け |
| `selected` | 選択した駒を持ち上げる／枠で囲む。動けるマスに印、取れる駒のマスは別の印 |
| `promoting` | 移動先に「成る」「成らない」の2択（成った後と成らない駒の姿で示す） |
| `animating` | 駒の移動アニメ中。入力は受け付けるが、二重実行はしない |
| `opponent_thinking` | 相手側の名前欄などに「考え中」。盤の操作は不可 |

### 2-2. 遷移ルール（→D:5-1）

- 自分の駒をタップすると `selected` になります。
- `selected` の状態では、次のように動きます。
  - 動けるマスをタップ → 移動（成りの選択が必要なら `promoting` へ）
  - 同じ駒をタップ → `idle` に戻る
  - 別の自分の駒をタップ → その駒が選択される
  - 動けないマスをタップ → `idle` に戻る（エラー音・エラー表示は出さない）
- 持ち駒も盤上の駒と同じ流れで扱います。
- ドラッグはタップと同じ結果にします。ドラッグを離した位置が無効なら、駒は元の位置に戻ります。
- 行き所がなくなる移動は `promoting` を経由せず、自動で成ります。
- 反則手は、動けるマスの印に**含めません**（合法手判定の結果だけを表示に使います）。

### 2-3. 相手（CPU）の指し手

- 移動元と移動先を強調し、自分の手のアニメより少し長めに見せます（6章）。
- 「考え中」の表示は、思考が一定時間を超えたときだけ出します。すぐ返ってくる場合に一瞬だけちらつくのを防ぐためです。

## 3. コンポーネント

### 3-1. 確認ダイアログ（→D:5-2, N:3-4, 3-5）

確認ダイアログは、次の3つの場合にだけ出します。
- 投了
- 対局をやめてタイトルに戻る
- 学習の進み具合のリセット

それ以外の操作には追加しません。

**文言とボタン**
- 1行目は主題で、「〜します。」の形にします。2行目は小さな補足です。
- ボタンは動詞にします。「はい」「いいえ」「OK」は使いません。
- 取り返しのつかない操作では、**初期フォーカスを「続ける／キャンセル」側**にします。

```text
投了します。
この対局は負けになります。
[対局を続ける]  [投了する]
```

**配置と操作**
- 実行ボタンは右、続行・キャンセルボタンは左に置き、全ダイアログで統一します。
- 背景タップ、Escキー、戻る操作は「続ける／キャンセル」として扱います。

### 3-2. メッセージ表示（→D:5-3, N:2-3）

```ts
type MessageKind = 'normal' | 'attention' | 'blocked' | 'special';
showMessage(kind: MessageKind, text: string, options?)
```

- メッセージは必ずこの関数を通して表示します。見た目と音は `kind` から自動で決まるようにし、呼び出し側で個別に指定しません。
- 新しい種類（第5の `kind`）は追加しません。どうしても必要なら、先に Design 側の表を更新します。
- `blocked` は柔らかい表現にし、赤い警告色や大きな音は使いません。
- 同じメッセージを連続して表示しません（短時間で同じものが来たら1つにまとめます）。
- スクリーンリーダー向けに `aria-live="polite"` の領域へ同じ文を出します。王手は `assertive` にします。

### 3-3. 初回ヒント（→D:6-2）

- 表示済みのヒントのIDは保存し、同じヒントは二度と出しません。
- 一度に表示するヒントは1つだけです。
- 盤の操作を妨げない位置に出し、タップで閉じられるようにします。数秒で自動的に消えるようにもします。
- タイトルに戻ったとき（次の来場者になったとき）は、ヒントの表示記録をリセットできるようにします。

### 3-4. 操作ボタン（待った・投了・メニュー）

- 小さくまとめますが、タップ領域は7章の最小サイズを守ります。
- 盤面とボタンが重ならないようにします。
- 押せない状態のボタンは見た目を薄くし、`disabled` と `aria-disabled` を設定します。

## 4. 文言

- 主題を文の先頭に置き、1つの表示では1つのことだけを伝えます（→N:3-5）。
- 子どもも読むことを想定し、将棋用語には言い換えか読み仮名を付けます。例：「成る（なる）＝駒がパワーアップ」
- 責める表現（「間違いです」「反則です」「残念」）は使わず、理由を短く伝えます。例：「同じ列に歩は2枚置けないよ（二歩）」
- 文言は1つのファイル（例：`messages.ts` や `ja.json`）にまとめ、コードの中に直接書きません。

---

## 5. 音

- 種類は次のとおりです：駒を置く／駒を取る／成る／打つ／メニュー移動／決定／戻る／メッセージ4分類（3-2）／画面遷移。
- 再生は1つの `SoundManager` を通して行い、音量・ミュート・音の割り当てをまとめて管理します。
- ブラウザの自動再生制限があるため、**最初のユーザー操作のあとに**音声を有効にします（Web Audio の `resume` など）。
- 音だけで意味を伝えません。必ず見た目の変化と組み合わせます（→D:5-3）。
- 連続して鳴る操作音は、同時に重なりすぎないようにします（同じ音の連打では前の音を止める、など）。
- 音量の設定とミュートの状態は保存します。

## 6. 時間（初期値）

| 対象 | 初期値 | 根拠・メモ |
|---|---|---|
| 押したことへの反応（押下表示・音） | 即時（入力と同じフレーム） | 処理の完了を待たずに、まず「押せた」ことを示す |
| 画面遷移（全体） | 約200ms | →N:3-3。0にすると何が起きたかわからなくなる |
| 自分の駒の移動アニメ | 120〜180ms | |
| 相手の駒の移動アニメ | 250〜350ms | 見逃しを防ぐため長め |
| 相手の指し手の強調 | 次の自分の操作まで | 移動元・移動先 |
| 「考え中」表示を出すまでの待ち | 400ms | ちらつき防止 |
| 初回ヒントの自動消去 | 4〜6秒 | |
| 放置時に戻るまでの予告 | 60秒操作なしで予告 → さらに15秒でタイトルへ | 展示用。対局中のみ予告を出す |
| 演出（王手・勝利など） | 1.5秒以内、タップでスキップ可 | →D:7-2 |

- 時間はすべて定数（CSS変数またはTSの定数）にまとめます。
- `prefers-reduced-motion: reduce` のときは、移動アニメと遷移を最小限（ほぼ即時、または短いフェード）にします。直前の一手の強調は残します。

## 7. 見た目・レイアウト

### 7-1. デザイントークン

色・サイズ・角丸・影・時間は、CSS変数（例：`--color-board`、`--color-highlight-move`、`--size-tap-min`、`--duration-move`）にまとめます。個々のコンポーネントの中に、色や数値を直接書きません。

### 7-2. 盤面

- 盤面は画面内で最大の要素にします。スマートフォンの縦画面では、横幅いっぱいに近づけます。
- 自分の持ち駒は盤の下、相手の持ち駒は盤の上に置きます。
- 手番は、手番側の持ち駒エリアや名前欄の強調で示します。文字だけで示しません。
- 駒の文字は、少し離れた場所からでも読める大きさにします。

### 7-3. 強調表示

- 次の4つは、**色だけでなく形も変えて**区別します（点、枠、塗りなど）。
  - 動けるマス
  - 取れる駒のマス
  - 直前の一手
  - 選択中の駒
- 目立たせたいものは彩度を高く、それ以外は彩度を低くします（→N:2-8）。
- 確認方法：画面をグレースケールにして（または目を細めて見て）、盤面・手番・強調表示がまだ区別できるかを見ます（→N:2-8）。

### 7-4. 操作しやすさ・アクセシビリティ

- タップ領域は最小44×44px（CSSピクセル）にします。盤のマスがこれより小さくなる画面幅では、盤を最優先で大きくします。
- 文字と背景のコントラストは 4.5:1 以上を目安にします。
- キーボード操作では、フォーカス位置が見えるようにします（`:focus-visible`）。方向キーでマス目を移動し、Enterで選択・決定できると理想的です。
- `hover` でしか出ない情報を作りません（タッチ端末では見えないため）。

### 7-5. 画面の大きさと向き

- 1つの画面は1画面に収め、ページをスクロールさせません。スクロールを探す操作は、ボタンを探す操作と同じく遊びを止めます（→N:3-3）。
- 収まらないときは、次の順で直します。
  1. 並びを変える。背の低い横長の画面（スマホの横向き）では、縦に積んだものを左右の2列にします。
  2. 内容をタブで分け、1つずつ見せます。選んだ内容を残りの高さいっぱいに出します。広い画面では、いつも見たいもの（トーナメント表など）をタブから外して横に出します。
  3. 補足の文を省きます。見出しと状態（星・値）は残します。
- 地図のように「動かして見るもの」は、枠の中だけを動かしてかまいません（将棋教室の地図、トーナメント表、図鑑・辞典の一覧、コレクション）。
- 確かめる端末は、スマホ縦（360×640と390×844）、スマホ横（844×390）、タブレット縦（820×1180）、タブレット横（1180×820）、デスクトップ（1366×768）です。

## 8. 避けること

| 避けること | 理由 |
|---|---|
| 「はい／いいえ」のボタン | 全文を読まないと意味がわからない（→N:3-5） |
| 選択の余地がない処理への確認（強制的に成る場合など） | 手数が増えるだけ（→N:3-4） |
| 投了などの確認をなくすこと | 信頼と端的は「確認をなくす」という意味ではない（→N:3-4 注意） |
| 反則手を一度選ばせてからエラーを出すこと | 選べないようにする方がよい（→D:5-4） |
| 赤い警告と大きなエラー音の多用 | 責めている印象になる |
| 最初に長いチュートリアルを読ませること | 読まれない（→N:4-2） |
| 対局中に長い説明文を常に表示すること | 主役の盤面を邪魔する（→N:2-5） |
| 演出中に操作を受け付けないこと | 待たせる（→N:3-3） |
| 色だけ・音だけで情報を伝えること | 伝わらない人や環境がある |
| メッセージ分類を増やすこと | 一貫性が崩れる（→N:2-3） |
| コンポーネント内への数値・色・文言の直接記述 | 調整しにくく、統一が崩れる |
| 機械的な評価（「よくできました」「残念」など） | プレイヤーを判定する表現は避ける（→N:6-3） |
