# 研究モードの設計

将棋ソフト（ShogiGUIなど）で研究するときの使い方を、このゲームの見た目と操作で使えるようにする「研究モード」の設計です。
モックアップは`docs/research-mode/mock.html`（写真は同じフォルダーの`mock-*.png`）にあります。

## 0. 依頼

> 研究モードを追加しよう。shogiソフトではこのような感じで研究します。マルチPVの数も設定できるようにしたい。また、研究モードには、現在の感想戦モードみたいに、閃き無限大での「この局面から対局」もできるようにしたい。また、局面編集もできるようにしたい。（何も置いていない盤に駒を配置していったりなど。）将棋AIで解析しながらの棋譜解析もできると良い。この画像を参考にしながら、この将棋ゲームにうまく馴染むようにデザインして、実装してください。まずはこの内容を整理して設計してメモしよう。それができたらモックアップを作成してみて。（2026-11-05）

参考の画像はShogiGUIの検討の画面です。写っているものは次のとおりです。

- 盤と候補手の矢印
- 棋譜の一覧（手数・指し手・消費時間）と、「分岐（次の手）」の一覧、手を進める・戻すボタン
- 評価値のグラフ
- 検討の欄（候補手の数、矢印の表示、定跡の利用、思考時間（無制限・時間・ノード数・深さ）、エンジンの追加、思考の終了）
- 読みの情報（深さ・ノード数・NPS）と、読み筋の表（順位・評価値・候補手・読み筋）

読んだもの: `docs/nintendo-design/`の5つの文書（とくに`UI_Nintendo_Design.md`の4・5・9・10章、`UI_Nintendo.md`の2-5・2-6・3-6・4-5、`Game_Nintendo_Design.md`の2-4・4-5・6-5）、今の対局画面と検討（棋譜解析・感想戦）のコード、エンジンの`go`、tsshogiの棋譜（`Record`）と局面編集（`Position.edit`）。

## 1. 依頼の整理

依頼は次の5つに分けられます。

| 番号 | やりたいこと | 今あるもの | 足りないもの |
| --- | --- | --- | --- |
| R1 | 好きな局面をエンジンで読み、候補手を何本も並べる（検討） | 閃き（`showHint`）・助言の探索。MultiPVは`applyStrengthOptions({ multiPv })`で変えられる。`go`は読みの途中の`onUpdate`（深さ・局面数・NPS・候補）を返す | 止めるまで読み続ける`go infinite`、候補の数を選ぶ画面、読み筋の表、何本もの矢印 |
| R2 | 棋譜を分岐つきで行き来する | 検討の`review-navigation.mjs`（本譜と1本の変化だけ） | 何本もの分岐。tsshogiの`Record`が分岐を持っている（`switchBranchByIndex`・`removeNextMove`・`importKIF`・`exportKIF`） |
| R3 | 「この局面から対局」（閃き∞・待った∞） | 検討中の感想戦（`toggleKansousen`。対局相手のCPUが同じ強さで応え、閃きと待ったは∞） | 研究の局面から始める対局と、指した手を研究の棋譜へ戻す道 |
| R4 | 局面編集（空の盤に駒を置いていく） | 盤の部品`BoardView.vue`の`allowEdit`と`edit`のイベント（もとの将棋GUIの機能が残っている）、tsshogiの`Position.edit`・`isValidEditing`・`countNotExistingPieces`・駒落ちと詰将棋の初期局面 | 駒箱・手番・初期局面の選択・合法の確かめの画面 |
| R5 | エンジンで解析しながらの棋譜解析 | 対局後の棋譜解析（`analyzeKifuStaged`。追加のエンジンで並べて読み、評価値のグラフ`EvaluationGraph.vue`に悪手・好手・神の一手の印） | 研究の棋譜（分岐を含む）を読むこと、検討で読んだ局面をグラフへ書き足すこと |

## 2. 方針

1. **研究は「調べる」遊び**です。ホームの「しらべる」に、図鑑と並べて「研究」のタイルを置きます。初心者の通り道には出しません（UD:1「作らないもの」、N:4-5 触っているうちに見つかる）。対局後の検討からも「研究で開く」で入れます（感想戦の延長として見つけられる）。
2. **ShogiGUIの情報はそのまま持ってくる**。そのうえで、このゲームの言葉と見た目に直します（N:1-2 ツールではなく娯楽、N:5-3 らしさ）。
   - 「MultiPV」は「候補の数」、「思考時間」は「読む長さ」、「ノード数」は「局面数」、「NPS」は「1秒に読む局面」と書きます。
   - 評価値の数字はそのまま出します。あわせて、勝率のバーと「先手やや有利」の一言（中継と同じ`rateVerdict`）を盤の上に出し、数字を読めない人にも形勢が分かるようにします。
   - 右の欄の下に、やこび姫の小さな顔と一言を置きます。いちばんの候補を言葉にして伝えます（例:「▲2四歩の飛車先の交換がいちばんだって。先手やや有利」）。
3. **盤が主役**です（UD:4-1）。盤の大きさと位置は、欄の中身で変えません（`docs/stable-board-layout-design.md`）。候補手は盤の矢印、読み筋の表は横の欄に置きます。
4. **消えない仕組みにして、確認を減らします**（UD:5-2）。研究はいつも自動で研究帳に残します。局面編集や新しい棋譜の読み込みで、前の研究が消えることはありません。確認を出すのは、研究帳から消すときだけです。
5. **エンジンは1つずつ使います**（AGENTS.mdの「CPU」）。検討の読みは研究の画面のあいだ、対局用のエンジンを借ります。棋譜解析は追加のエンジンで読みます。追加できない端末（スマホ）では、検討を止めてから棋譜解析をして、終わったら検討に戻ります。

## 3. 画面

### 3-1. PC（横長）の配置

今の対局画面と同じ3列です（左に情報と棋譜、真ん中に盤、右にやこび姫の欄）。研究では、右の欄をやこび姫の立ち絵から検討の欄に替えます。

| 場所 | 中身 |
| --- | --- |
| 左の列 | 戻る・研究の名前・研究帳のボタン、棋譜の一覧（手数・指し手・評価値・印。分岐のある手には「＋」。いまの手がいつも見える位置に送る）、「次の手」の分岐の一覧、評価値のグラフと「棋譜解析」 |
| 真ん中 | 盤（今の対局と同じ`BoardView.vue`）と候補手の矢印、左右に駒台。盤の上に勝率のバーと「先手やや有利」。盤の下に手の行（⏮ ◀ 「12手目 △8二玉」 ▶ ⏭）。手を動かすボタンは盤のすぐ下に大きく置く（盤の下の空きを使い、目を盤から離さずに進められる） |
| 右の列 | 検討の欄。上から、読む／止めるのボタンと読みの情報（深さ・局面数・1秒に読む局面）、設定の行（候補の数・読む長さ・矢印）、読み筋の表、やこび姫の一言、下に3つの操作（局面編集・この局面から対局・棋譜解析） |

### 3-2. スマホ（縦長）の配置

縦積みの5段の形（`docs/stable-board-layout-design.md`）に合わせます。

1. 上の帯: 戻る・勝率のバーと「先手やや有利」・研究帳（下の欄の高さを空けるため、勝率のバーを上の帯に入れる）
2. 相手の駒台（細い1行）、盤（幅いっぱい。大きさは中身で変えない）、自分の駒台（細い1行）
3. 手の行: ⏮ ◀ 「12手目 △8二玉」 ▶ ⏭
4. 下の欄（残りの高さ）: タブ「検討」「棋譜」「グラフ」。中はタブごとにスクロールする。検討のタブは、読みの情報・候補の数・読む長さを1行にまとめ、読み筋の表を3行以上見せる
5. いちばん下に操作の帯（読む／止める・局面編集・対局・その他（棋譜解析・研究帳・読み込みと書き出し））

### 3-3. 検討の欄（R1）

| 項目 | 決めたこと | 原則 |
| --- | --- | --- |
| 読み始め | 研究の画面を開くと、すぐ今の局面を読み始める（ShogiGUIの「検討開始」を押す手間をなくす）。手を進める・戻すと、新しい局面を読み直す | U:3-2 停止距離、D:3-3 すぐ遊ばせる |
| 読む／止める | 右の欄のいちばん上の大きいボタン1つ。読んでいるあいだは「止める」、止めたら「読む」。読んでいるあいだは、ボタンの横の小さな点が脈を打つ | UD:5-3 通常、N:2-6 存在感は抑え、伝えることは伝える |
| 候補の数（MultiPV） | 「候補の数 [−] 3 [＋]」。1〜10。はじめは3。変えたらすぐ読み直す | 参考画像の「候補手の数」 |
| 読む長さ | 「読む長さ: ずっと」の行を押すと、選択シート（`PregamePicker.vue`と同じ形）で「ずっと」「時間（1・3・5・10・30秒）」「深さ（10・15・20・25）」「局面数（10万・100万・1000万）」から選ぶ。はじめは「ずっと」 | 参考画像の「思考時間」。選択肢は種類で4つに分ける（UD:9 同じ種類の選択肢は3つ程度、グループ分け） |
| 矢印 | 「矢印 あり／なし」。ありのときは候補の数だけ（最大5本）出す。1位は太く、2位から細く薄く、矢印の先に順位の数字 | 盤の色の決まり（AI候補は赤の実線） |
| 読みの情報 | 「深さ 24 ・ 1,234万局面 ・ 85万/秒」を1行で。止めたら「止めました（深さ24）」 | 参考画像の深さ・ノード数・NPS |
| 読み筋の表 | 1行に、順位の札・評価値（先手から見た値。詰みは「▲5手詰」）・候補手・読み筋（1行に入る分だけ。続きは「…」）。1位の行は濃く。読みの途中で順位が入れ替わっても、行は順位の順のまま中身を替える（行が跳ねない） | UD:4 大きさ・濃さで優先度、U:7-2 動きは情報のためだけ |
| 行を押す | その読み筋を盤の上で薄い駒の手順として見せる（▶で1手ずつ。もう一度押すと戻る）。「この手順を棋譜に入れる」で分岐として足す | N:4-5 触って見つかる |
| 評価値の向き | 先手から見た値（ShogiGUIと同じ）。「表示: 評価値／勝率」で、表の数字を勝率（%）に替えられる | 初心者にも読める形を選べる |
| やこび姫の一言 | 1位の候補を、作戦の名前・手筋の名前（`coach-insight.mjs`・`move-praise.mjs`の言い方）と形勢の一言で言う。読みが落ち着いて（同じ1位が2回続いて）から言い換える | N:1-3 文字に頼りすぎない、U:3-5 斜め読み |
| 片方の玉しかない局面 | エンジンは読めないので、「詰みを探す」に切り替える（問題集と同じ`problem-solver.ts`の詰み探索）。見つけたら読み筋の表に1行で出す | 詰将棋の研究を落とさない |

作らないこと: エンジンの追加（このゲームのエンジンは1つ）、定跡の利用の切り替え（研究では定跡を使わずに読む。候補が並ぶほうが研究に向く）、スレッド数・置換表の大きさの設定（端末に合わせて自動）。

### 3-4. 棋譜と分岐（R2）

- 研究の棋譜はtsshogiの`Record`で持ちます。分岐は何本でも持てます。
- 盤で指すと、その局面の次の手として足します。同じ手があればそこへ進むだけ（`Record.append`の動き）。ちがう手なら新しい分岐になります（確認は出さない）。
- 棋譜の一覧は、いま選んでいる道だけを並べます。分岐のある手には小さな「＋」を付け、その手を押すと「次の手」の一覧（本譜と分岐）が出ます。押すと道が切り替わります（参考画像の「分岐（次の手）」）。
- 分岐の一覧の行を長押し（PCは右クリック）すると「本譜にする」「この分岐を消す」。消すのは取り消せるよう、直後に「もとに戻す」の帯を5秒出します（確認のダイアログは出さない。UD:5-2）。
- 手の行の⏮ ◀ ▶ ⏭は、PCでは←→キーでも動きます（Homeで最初、Endで最後）。

### 3-5. 局面編集（R4）

「局面編集」を押すと、盤のまわりが編集の形に替わります。盤の大きさと位置は変えません。

| 項目 | 決めたこと | 原則 |
| --- | --- | --- |
| 置き方 | 駒箱か持ち駒の駒を押す → 置きたいマスを押す。盤の駒を押す → ほかのマスを押すと動く、駒箱を押すとしまう。ドラッグでも同じ（`BoardView.vue`の`allowEdit`） | UD:5-1 駒の操作ルールのまま（選ぶ→行き先） |
| 成る・向き | 盤の駒を選ぶと、欄に「成る／戻す」「向きを変える」「駒箱へ」の3つのボタンが出る。PCは右クリックで「くるっと」（先手→先手の成り→後手→後手の成り。今の`BoardView`の`rotate`） | 迷わない操作を先に作る（N:2-2） |
| 駒箱 | 盤と持ち駒にない駒（全部で40枚）を、種類ごとの数で並べる（`countNotExistingPieces`）。置くたびに数が減る | 駒が増えも減りもしない（いつも40枚） |
| 置く駒の向き | 駒箱から置くときの向きを「▲先手の駒／△後手の駒」で選ぶ。はじめは先手 | |
| はじめの形 | 「平手」「何もない盤」「詰将棋（相手の玉だけ・残りは相手の持ち駒）」「駒落ち…」（香落ち〜十枚落ちをシートで）。押すとすぐその形になる | tsshogiの`InitialPositionSFEN` |
| 手番 | 「▲先手番／△後手番」 | |
| 完了 | 押すと確かめ、問題がなければ、その局面から新しい研究を始める（前の研究は研究帳に残る）。問題があれば、そのマスに赤い輪と、やこび姫の柔らかい一言（「2筋に歩が2枚あるよ（二歩）」）。完了はできない | UD:5-4 反則は責めずに理由を伝える |
| 確かめること | 二歩、行き所のない駒（1段目の歩・香、1・2段目の桂）、玉が2枚以上、手番でない側の玉に王手がかかっている | |
| やめる | 「編集をやめる」で、編集を始める前の局面に戻る | |

### 3-6. この局面から対局（R3）

- 右の欄（スマホは操作の帯）の「この局面から対局」を押すと、小さなシートが出ます。
  - 持つ側: 「▲先手」「△後手」（はじめは今の手番の側）
  - 相手の強さ: 「Lv19（6級程度）」の行。押すと対局準備と同じ選択シートでLvを選ぶ（はじめは最後に使った強さ）
  - 「対局開始」のボタン。シートの下に小さく「閃き・待ったは何回でも。記録には数えないよ」
- 対局は今の対局画面で指します（感想戦と同じく、閃きは「×∞」、待ったは「×∞」。待ったは研究から持ってきた局面まで何度でも戻れる）。対局の札の行には「研究の対局」と出します。
- 左上の「戻る」か、終局のあとの「研究に戻る」で研究の画面へ戻ります。指した手は、始めた局面からの分岐として研究の棋譜に入り、最後の局面を開きます。対局の途中で戻っても、それまでの手は入ります。
- 記録には数えません（レーティング・最近の対局・コレクション・棋力カルテ・コツの回数）。今の感想戦と同じ扱いです。

### 3-7. 棋譜解析（R5）

- 2つの道で評価値のグラフを埋めます。
  1. **検討で読んだ局面を書き足す**: 手を進める・戻すたびに読んだ評価値（深さ12以上まで読めたもの）を、その手のグラフの点にします。手を進めながら検討していくと、グラフができていきます（ShogiGUIと同じ）。
  2. **棋譜解析のボタン**: グラフの欄の「棋譜解析」を押すと、いま選んでいる道を最初から最後まで、対局後の棋譜解析（`analyzeKifuStaged`、深さは「解析の深さ」の選択）で読みます。グラフに悪手・好手・神の一手の印を付け、読み終えた局面から順に棋譜の一覧の評価値の列も埋まります。
- 棋譜解析のあいだも検討は続けます（PCは追加のエンジンで棋譜解析、対局用のエンジンで検討）。追加のエンジンが起動できない端末（`analysisEngineCount`が1のとき）は、検討を止めて棋譜解析をし、終わったら検討に戻ります。読み終わるまでの進み具合（「24/80手」）をグラフの上に出します。
- グラフの点を押すと、その手へ移ります（今の`EvaluationGraph.vue`と同じ）。

### 3-8. 研究帳と棋譜の読み書き

- 研究帳: 研究はいつも自動で残します（最新の30件。古いものから消える）。名前は「11月5日 平手 ▲2六歩」のように日付・はじめの形・1手目。行を押すと開く、名前を変える、消す（消すときだけ確認。初期フォーカスは「やめる」。UD:5-2）。
- 読み込み: 研究帳の「棋譜を読み込む」で、KIF・KI2・CSA・SFEN・USIの文字を貼り付ける（tsshogiの形式の判定と読み込み）。「自分の対局から」で、残した自分の対局（`my-games:v1`）を選んで開く。
- 書き出し: 「棋譜をコピー（KIF）」「局面をコピー（SFEN）」。

## 4. 入口と戻り先

| 入口 | 開くもの | 戻り先 |
| --- | --- | --- |
| ホームの「しらべる」の「研究」のタイル | 前に開いていた研究（なければ平手の新しい研究） | ホーム |
| 対局後の検討の「研究で開く」 | その対局の棋譜（いま見ている手） | 検討の画面 |
| 研究の「この局面から対局」 | 対局画面 | 研究（指した手を分岐に入れて） |

- 画面の間を移る入口を足したので、戻り先も足します（`docs/return-path-design.md`、`navigateBack`と`useBackNavigation`の`canGoBack`）。
- 研究の画面は、ほかの大きな画面と同じく`defineAsyncComponent`で開いたときに読み込みます（`ShogiResearch.vue`）。対局画面から重いモジュールを静的にimportしません。

## 5. 機能設計メモ

### 機能名：研究モード

- 目的（コンセプトとの関係）：強くなりたい人が、気になった局面をAIと一緒に調べ、自分で指して確かめられるようにする。大会・物語で出会った局面や、自分の対局を調べ直して、次の大会で勝つための練習の場にする（AGENTS.mdの「このゲームの柱」）。
- 利用場面（誰が・いつ・どのくらいの時間）：慣れてきた人が、対局のあとや大会の合間に、5〜30分。展示の来場者向けではないので、ホームの「しらべる」の奥に置く。
- 画面の主役：盤と候補手の矢印。
- 情報の優先順位（1〜5）：1 盤と矢印 / 2 1位の候補と評価値（勝率のバー） / 3 読み筋の表 / 4 棋譜と分岐・グラフ / 5 読みの情報（深さ・局面数）と設定。

## 10. 相手の手を自動で指す（2026-11-05）

### 10-1. 依頼

「この局面から対局の他に、相手が自動で指すみたいなのも欲しい。検討中に相手の手を動かすのが面倒なので、それを自動化することも出来たら楽。また、それで相手が気に入らない手を指した場合のために、途中でオンオフもできるようにしたい。」

### 10-2. 機能設計メモ

機能名：相手の手を自動で指す（検討の設定「相手の手: 手で指す／自動で指す」）

- **目的**: 検討で自分の側の手を考えるとき、相手の手を毎回盤で動かす手間をなくす。自分の手だけに集中できる。
- **遊びの核**: 自分の手を指す → 将棋AIがすぐ答える → また自分の手を考える、の短い往復（G:3-3 遅さは罪）。対局と違い、勝ち負けも記録もない。
- **リスクとリターン**: なし（研究の道具）。気に入らない手は、◀で戻して指し直せる（UD:5-2 取り消せる操作に確認を出さない）。
- **決めたこと**:
  - 自動で指す側は「▲先手／△後手」で決める（はじめは△後手）。研究ではどちらの側も研究するので、「盤で指した側の反対」ではなく、はっきり選ばせる（UD:2 迷わない）。
  - 盤で**自動で指す側でない**手を指したら、相手が答える。自動で指す側の手を盤で指したとき（気に入らない手を戻して、自分で相手の手を指し直したとき）は答えない。切らなくても指し直せる（UD:2 手数が少ない）。
  - 答えるのは盤で指したときと、自動を入れた・側を変えたときに自動で指す側の番のときだけ。◀▶や棋譜の一覧で手を動かしただけでは指さない（読み返すたびに手が増えると迷う）。
  - 考える長さは1秒・3秒・10秒から選ぶ（はじめは3秒）。その長さが過ぎるか、読む長さ（深さ・局面数・秒）で読み終えたら、候補の1番を指す。止めていても、答えるときは読み始める。
  - 指した手は棋譜の手として入る（分岐の仕組みのまま）。手の行に「△後手が自動で指した」と出し、考えているあいだは「△後手が考えています…」とやこび姫の一言「気に入らない手なら、◀で戻して指し直してね」を出す（G:3-1 無反応をなくす）。
  - 考えているあいだに盤で指した・手を動かした・局面編集を始めた・自動を切ったときは、答えるのをやめる。
  - いつでも切れるよう、PCは検討の設定の並び（相手の手・自動の側・考える）に、スマホは下の操作の帯に「相手△ 自動／手で」のボタン（押すたびに入れる・切る）を出したままにする。自動の側と考える長さは「…」のシートで選ぶ。設定は研究の設定（`research-settings:v1`）に残す。
- **やらないこと**: 相手の強さを変える（強さを選んで勝ち負けを競うのは「この局面から対局」の役目）。両方の側を自動にする（観戦は中継の役目）。

### 10-3. 実装（2026-11-05、実装・自動テスト済み）

- 設定は`research-record.mjs`の`autoReply`・`autoSide`・`replyMs`と選択肢`REPLY_TIMES`。指すか待つかの判断は`research-analysis.mjs`の`autoReplyDecision`（考える長さが過ぎるか読み終えたら候補の1番、候補がないまま読み終えたら指さない）。
- 画面は`ShogiResearch.vue`の`requestAutoReply`・`checkAutoReply`・`cancelAutoReply`・`setAutoReply`・`setAutoSide`（PCの`data-research-auto`、スマホの`data-research-auto-toggle`、シートの`data-research-auto-sheet`）。

### 10-4. 直した不具合

- 自動で指す確かめの途中で、画面が固まることがあった。原因は`useResearchEngine`の`start`が、前の読みを止めるのを待ったあとに世代の印を取っていたことで、続けて2回読みを頼むと2つとも同じ世代になり、エンジンに2回`go`を送っていた（読んでいるエンジンに次の`position`を送ると、止まるまで返らない）。頼んだ順の番号を先に取り、待つあいだに次を頼まれたら始めないようにした（テストつき）。
- 矢印や表示の設定を変えただけでも、読み直していた（見張る値を配列を返す1つの関数で見ていたため）。1つずつ見るようにした。
- 盤の矢印が、上に開いたシートの上に出ていた。盤の欄の中に閉じ込めた（`isolation: isolate`）。

確かめたこと: 単体テスト（設定の整え方・指すか待つかの判断・続けて頼んだ読み）、型チェック、ビルド。ブラウザ（1366×768・390×844・820×1180・844×390）で、自動を入れて▲7六歩を指すと「△後手が考えています…」のあと△の手が入る・戻して△の手を手で指すと答えない・切ってから指すと答えない・△の番で入れるとすぐ考えて指す、を操作して確かめ、はみ出しがないことを見ました。実際に研究してもらっての確かめは未確認です。
