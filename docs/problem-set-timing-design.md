# 問題集の解く時間（2026-10-31）

依頼: 詰将棋などを解くときは、時間を測って記録するようにしたい。

読んだ指針: `Game_Nintendo_Design.md`（3-3 遅さは罪、4-8 どれぐらい良いことをした？、5-5 スコアの見せ方、5-6 ランキングの功罪、5-8 外からのご褒美の注意点、6-1 上達そのものが楽しさになる）、`UI_Nintendo_Design.md`（5-3 メッセージ分類、7-4 日常の「うれしい」）、`UI_Nintendo_Implementation.md`（4 文言、7-4 操作しやすさ、9 実装後のチェックリスト）。

## 1. 機能設計メモ（Game_Nintendo_Design.mdの14章の形）

- **一言で**：問題集の問題を解くと、かかった時間と自己ベストが残り、前の自分より速く解けたら「自己ベスト！」と言われる。
- **解く課題**：一発で解けた問題は★が付くだけで、そのあと何度解いても上達が見えない。同じ1手詰めでも「すぐ見える」ようになったことが、上達のいちばん分かりやすい形になる（D:6-1）。
- **リスクとリターン**：急ぐと間違えて「一発で正解」の★を逃す。じっくり読むと時間がかかる。どちらも自分で選べ、制限時間で負けにはしない。
- **初めての人の最初の1分**：問題を開くと、やこび姫の台詞の下に小さく「⏱ 2秒」と数える。正解すると「正解！ 3.2秒」。初めてなので比べるものはない。
- **失敗したとき**：間違えても時計は止めない（解けるまでの時間を測る）。「答えを見る」を押したら、その回は時間を記録しない（D:4-8。答えを見て指した手を自分の速さにしない）。
- **捨てるもの**：制限時間・秒読み（詰将棋で急かすと、読む練習でなく当てる練習になる。D:5-8）。ほかの人との順位（D:5-6。比べるのは前の自分だけ）。1手ごとの時間（問題ごとの合計だけ）。
- **確かめ方**：1手詰めを解いて「正解！ n秒」、解き直して速ければ「自己ベスト！（前はn秒）」、一覧に「・ベストn秒」が出ること（ブラウザで3つの大きさを確かめた）。実際に何問も解いての使い心地は未確認。

## 2. 決めたこと

- 時計は問題を開いた時（解き直し・「もう一度解く」で盤を戻した時も）から、正解の最後の手を指した時まで。2手以上の問題では、相手の応手のあいだも数える（読む時間も含めて「解く時間」）。
- ほかのタブに移った・画面を隠したあいだは止める（`visibilitychange`）。問題の一覧に戻ったら止める。席を外した時間を自分の遅さにしない。
- 問題を解いている間の表示は、台詞の下の小さな「⏱ 12秒」だけ（スクリーンリーダーには読ませない`aria-hidden`）。答えを見たら消す。盤や台詞より目立たせない（UD:5-3。主役は盤）。
- 正解の札に時間を足す。「正解！ 12.3秒」、前より速ければ「12.3秒・自己ベスト！（前は15.0秒）」（緑の字）、遅ければ「12.3秒（ベストは9.0秒）」。1分を超えたら「1分05秒」、60分以上は「60分以上」。数字だけでなく前の自分と比べた言葉にする（D:5-5）。
- 一覧の各問題の行に「・ベスト12.3秒」を足す（UD:7-4。集めて眺めるとうれしい）。
- 保存は今までの問題集の記録（`shogi-match:problem-set:v1`）の各問題に`bestMs`（自己ベスト）と`lastMs`（前回）を足すだけ。前の版の記録（`firstTry`だけ）はそのまま読める。答えを見て解いた回は、今までのベストを消さずに残す。
- 処理は`src/core/problem-progress.mjs`の`recordProblemSolved`（`ms`）・`solveTimeText`・`solveTimeResult`、画面は`src/ShogiProblemSet.vue`の`startClock`・`stopClock`・`clockElapsed`・`solveResult`・`answerSeen`。

## 3. 実装（2026-10-31、実装・自動テスト済み）

- `src/core/problem-progress.test.mjs`で、ベストの更新・前の版の記録・答えを見た回・時間の文を確かめた。`src/core/match-ui-regression.test.mjs`で、時計を止める場所（答えを見る・一覧へ戻る・画面を隠す）と、答えを見た回を記録しないことを確かめる。
- ブラウザ（390×844・820×1180・1366×768）で、1手詰めの第1問を解き（「正解！ 3.2秒」）、「もう一度解く」で解き直して「1.2秒・自己ベスト！（前は3.2秒）」、一覧で「一発で正解！・ベスト1.2秒」が出ることと、横にはみ出さないことを見た。
- 実際に遊んでの確かめは未確認。

## 4. まだのこと

- 将棋教室の「1手詰めドリル」など、教室の中で解く問題集の問題は、時間を測っていない（教室は時間で比べる場ではないため、今は入れない）。
- 脳トレの「目隠しの詰将棋」は脳トレの記録で別に数える。

## 5. 解いている間の時計を見出しに大きく出す（2026-11-02、ユーザーの依頼「詰め将棋では、解いている間にタイマーが表示されるようにしたい」）

- 解く課題：解いている時間は2章で測っていたが、時計は問題文の下に小さな灰色の字（「⏱ 3秒」）で出ていただけで、解いている間に目に入らなかった。
- 決めたこと：
  - 時計は見出しの右に、いつも同じ場所で大きく出す（「⏱ 0:03」。数字の幅を固定して、秒が進んでも揺れない）。問題文の下の小さな時計はやめた。
  - 数字の形は`problem-progress.mjs`の`clockDigits`（「0:03」「12:05」「1:02:03」）。正解の一言と一覧の記録は前のまま（「12.3秒」）。
  - その問題の自己ベストがあれば、時計の下に小さく「ベスト 0:08」。
  - 正解したら時計を止め、緑の縁と字で光らせる（自己ベストの緑と同じ）。答えを見たら測らないので時計を消す。画面を離れたときに止めるのは前と同じ。
  - 詰将棋だけでなく、問題集のどの問題（練習問題・図巧・あなたの対局）でも同じ時計を出す（測っているのは全部の問題なので）。
- 根拠：UD:4（大事な状態はいつも同じ場所に）、G:5（自己ベストが見えると、もう一度解く目標になる）、U:6（動く表示は揺れないように）。

### 実装（2026-11-02、実装・自動テスト済み）

- 処理とテスト：`problem-progress.mjs`の`clockDigits`、`problem-progress.test.mjs`。
- 画面：`ShogiProblemSet.vue`の見出しの`shogi-problems__timer`（`data-problem-clock`・`role="timer"`）、`clockDigitsText`・`currentBestText`。
- ブラウザ（390×844・820×1180・1366×768）：1手詰めの第1問を開くと、見出しの右に「⏱ 0:03」が出て進むことを見た。
