# 定跡補助の手順と完成形をそろえる（設計 2026-10-27）

依頼: 「定跡補助で、玉を8八に置くために、動かしてはいけない桂を跳ねて道を作ろうとする。完成形が間違っている場合がある。以前、定跡エディターで入力した手順と完成形はほとんど正しいので、それを参考に直してほしい」。

決めたこと（ユーザー、2026-10-27）: 案A（手順を正にして完成形をそろえる）＋案B1（手順で動かす駒だけを動かす）＋案C（戦法と囲いを駒ごとに合わせる）＋案D（本番と同じデータで通しで確かめるテスト）。

## 1. 調べて分かったこと

作戦カードの87組を、決まった相手の手（相手が振り飛車なら居飛車らしい手、居飛車なら振り飛車らしい手）で、案内どおりに60手まで指させた（開発用の`scripts/opening-guide-audit.mjs`）。

1. **手順にない駒を動かす案内**。居飛車穴熊の19手目に▲7七桂を案内した。手順どおりに指せないときの近道（完成形までの距離を縮める手なら何でも候補にする`formationProgressMoves`）が、道をふさぐ駒を「どけば1手で通れる」と数えるため。ほかに、片美濃・金無双の▲1八飛、原始中飛車＋本美濃の▲6八飛（5八の飛車をどかして金を5八へ）、原始棒銀＋中住まいの▲3六歩・▲4八銀（棒銀の銀を囲いへ戻す）などが出た。
2. **完成形のデータの誤り**。居飛車穴熊（エディターの保存）の完成形に「7七桂」が入っている（手順どおりなら7七は角）。上の▲7七桂の直接の原因。ほかに、手順の最後の形と完成形が合わないものが単独で7件（ひねり飛車・原始中飛車・森下システム・角換わり腰掛け銀・居飛車穴熊・右矢倉など）。
3. **戦法と囲いを合わせたときの食い違い**。戦法と囲いの手順は、どちらも初めの配置から書いてある。同じ駒を両方が使うと（原始棒銀と中住まいの3九の銀、原始中飛車の5八の飛車と本美濃の5八の金）、合わせた手順が指せない。作戦カードの完成形の小さな盤も、合わせた手順から作るので崩れる。
4. エディターの保存があるのは、作戦カードで使う63の定義のうち25。残りの38（美濃・矢倉・舟囲い・四間飛車など）は組み込みの定義のまま。
5. エディターの保存の「実戦確認」（相手の応手の記録）は、どの定跡も本線だけで、応手は入っていない。
6. テストでは、エディターの保存を読まない（`EDITOR_OVERRIDES_ENABLED`）。だから本番と同じデータを確かめるテストがなかった。

## 2. 機能設計メモ

### 機能名：手順どおりの定跡補助

- 一言で：矢印は、選んだ作戦の手順の駒だけを動かす。完成形の絵と、完成の判定と、手順が同じ形を指す。
- 解く課題：手順にない駒を動かす矢印で迷う／絵と判定が違う形を指す／戦法と囲いの組み合わせで手順が崩れる。
- リスクとリターン：変えない（作戦を選ぶと案内どおり組める代わりに、相手の手で崩れることがある）。
- 溜めと解放：変えない（完成までの残り、完成）。
- 初めての人の最初の1分：作戦カードの小さな盤の形と、対局中の薄い駒と、完成の知らせが、同じ形になる。
- 上級者の深さ：変えない。
- 失敗したとき：手順の駒で進めないときは、ほかの駒をどかして無理に進めず、今までどおり「作戦を変えよう」の札で近い作戦を勧める（D:7-2 失敗の理由が納得できる）。
- ご褒美と使い道：変えない（コレクションの印は、完成の判定で付く。判定が正しくなるので、印も正しく付く）。
- ほめる瞬間：変えない。
- 捨てるもの：道をふさぐ手順外の駒をどかす近道（迷わせる。U:2の1番「迷わない・間違えない」）。組み合わせると指せなくなる戦法と囲いの組（カードに出さない。N:2-2 迷う並べ方をやめる）。
- 確かめ方：87組の通しの指し手（2種類の相手）で、手順にない駒を動かさないこと、手順の形と完成形が合うことを、本番と同じデータでテストする。実際の対局で、ユーザーに居飛車穴熊・矢倉・美濃を組んでもらう。

## 3. 案A：手順を正にして、完成形をそろえる

- **決まり**：完成形のマスは、その定義の手順を初めの配置から指した最後の形（自分の駒だけ。歩の交換など、自分の駒がいるマスへ動く手は交換として扱う。`opening-formation.mjs`と同じ）に、すべて合っていなければならない。
  - 完成形に挙げる駒は、形の要になる駒だけでよい（手順で動く駒をすべて挙げなくてよい）。歩は、交換で消えたり相手に取られたりしやすいので、形の要（中飛車の5五歩など）だけにする。
  - 戦法は、手順の途中で完成させたい場合（中飛車の▲5七銀で完成、そのあとは完成後の案内）、完成の時点より後ろの手を手順に置かない。置くと、その手は案内されないまま残る。
- **直し方**：最後の形と食い違うマスを、同じ駒の最後のマスに直す。その駒が手順のどこにも出てこない（居飛車穴熊の7七桂）ときは、そのマスを完成形から外し、そのマスにいる手順の駒（7七角）に替える。玉を動かす囲いで完成形に玉がないときは、玉の最後のマスを足す。
- **どこを直すか**：
  - エディターの保存は、取り込み元の`opening-library-export.json`を直してから`npm run import:opening-library`で作り直す（生成物だけを直すと、次の取り込みで戻るため）。ユーザーの手元のエディターの下書き（ブラウザの保存）は自動では直らないので、直したJSONを「JSONを読み込む」で読み込み直してもらう。
  - 組み込みの定義は`opening-guide.mjs`を直す。同じIDのエディターの保存があるときは、保存の方が本番で使われるので、両方を直す（AGENTS.md）。
- 直した一覧は、この文書の6章に残し、ユーザーに確かめてもらう。

## 4. 案B1：手順で動かす駒だけを動かす

- 手順どおりに指せないときの近道（囲いの`castleProgressCandidates`、戦法の駒組みの`shapeFallback`）で候補にする手を、**完成形のマスに割り当てた駒が、そのマスへ近づく手**だけにする（`formationProgressMoves`に「動かしてよい駒」を渡す。割り当ては`variantDistance`の`assignments`）。道をふさいでいるだけの駒（8九の桂、2八の飛車など）は動かさない。
- それで進めなければ、近道は出さない。手順の手（と、予定の駒がいないときの「同じ種類の駒が同じ行き先へ」の代わりの手。AGENTS.md）だけを案内し、それもなければ今までどおり中断して「作戦を変えよう」の札を出す。
- 距離の数え方（`variantDistance`）は変えない（ふさぐ駒を「どけば通れる」と数えるのは、完成までの残り手数の目安としては正しい。近道の候補にしないだけ）。

## 5. 案C：戦法と囲いを、駒ごとに合わせる

- 戦法と囲いの手順を、それぞれ初めの配置から指して、1手ごとに「どの駒の手か」を決める（駒は初めにいたマスで呼ぶ）。
- 合わせ方（`composeOpeningPlan`）：
  - 戦法の手を先に、囲いの手を後ろに並べる（今までどおり）。
  - 戦法がすでに動かした駒を囲いが動かす手は、囲いの手から外す（その駒は戦法の駒）。
  - 同じ手（▲7六歩など）は一度だけ（今までどおり）。
  - 囲いの飛車を振る手（美濃の▲6八飛など）は、戦法が飛車を動かすなら外す（今までどおり）。
- **合わない組**：合わせた手順を自分の駒だけで指したときに、
  - 指せない手がある（行き先に戦法の駒がいる、通り道をふさがれている）、または
  - 最後の形が、戦法か囲いの完成形を満たさない、
  ときは「合わない組」とする。合わない組は、作戦カードの合う囲いから外す（カードの囲いがすべて外れるときは、囲いなしのカードにする）。対局中に古い保存から合わない組が読まれたときは、囲いを外して戦法だけを案内する。
- 作戦カードの完成形の小さな盤と、対局中の薄い駒は、合わせた手順から作る（`opening-formation.mjs`）。
- エディターで「その組専用の手順」を入れる仕組みは、今回は作らない（合わない組が少なければ要らない。多ければ次に考える）。

## 6. 案D：本番と同じデータで、通しで確かめる

- テストで、エディターの保存を読む状態を作れるようにする（環境変数`OPENING_GUIDE_EDITOR_OVERRIDES=1`。テストのファイルごとにモジュールを読み直すので、ほかのテストの組み込みの定義のままの確かめには影響しない）。
- `src/core/opening-guide-integrity.test.mjs`（本番と同じデータ）で、次を確かめる。
  1. カードで使うすべての定義で、完成形が手順の最後の形に合う（3章）。
  2. 作戦カードのすべての組が、合う組である（合わない組はカードに出ていない。5章）。
  3. 作戦カードのすべての組を、2種類の相手（居飛車らしい手・振り飛車らしい手）で60手まで指させ、案内した手が、合わせた手順の駒（手順で動かす駒）だけを動かす（4章）。
- 監査の処理は`src/core/opening-audit.mjs`に置き、テストと開発用の`scripts/opening-guide-audit.mjs`（一覧を出す）から使う。
- 振り飛車用の囲いだけのカードは、対局中は先に飛車の振り先を選ばせる（AGENTS.md）。監査と、完成形から始める学習対局（`learning-setup.mjs`の`buildFormationStart`）では、振り先を四間飛車にする。

### 6-1. 直したデータ（エディターの保存。ユーザーに確かめてもらう）

取り込み元の`opening-library-export.json`を直して、`src/data/opening-guide-overrides.mjs`を作り直した。手元のエディターの下書きは自動では直らないので、直したJSONを「JSONを読み込む」で読み込み直す。

| 定義 | 直したところ | 理由 |
| --- | --- | --- |
| 居飛車穴熊（囲い） | 完成形の「7七桂」を「7七角」に | 手順に桂の手がなく、7七は角。▲7七桂を案内していた直接の原因 |
| ひねり飛車（戦法） | 完成形の飛車を「3六」から「7六」に | 手順の最後は▲7六飛 |
| 原始中飛車（戦法） | 完成形の銀を「5七」から「5六」に | 手順の最後は▲5六銀 |
| 森下システム（戦法） | 手順の最後に▲3七銀を足し、完成形に「6八角」を足した | 完成形（作者の入力）は3七銀だが、手順は▲4八銀で止まっていた。手順を完成形に合わせた唯一の例外（作者の意図が完成形の方にはっきりある）。6八角は、角が7九にいるうちに完成して、組み込みの金矢倉の▲7九玉がふさがれないため |
| 原始鬼殺し（戦法） | ▲2二角成と▲6五桂の順を入れ替え、桂を先に跳ねる | ▲7七桂のあとは、7七の桂が角道をふさいで▲2二角成が指せない |
| 松尾流穴熊（囲い） | 手順の2つ目の▲6六歩を消した | 同じ手が2回あり、2回目は指せない |

組み込みの定義（`opening-guide.mjs`。テストで使う）は変えていない。本番はエディターの保存を使う。

### 6-2. 合わない組（作戦カードから外した囲い。本番のデータ）

| 戦法 | 外した囲い | 理由 |
| --- | --- | --- |
| 原始棒銀・早繰り銀 | 中住まい | 中住まいの4八銀（3九の銀）を、戦法の銀が使う |
| 相掛かり・ひねり飛車 | 中住まい | 戦法の3八銀が、中住まいの▲3八金の行き先をふさぐ |
| 原始中飛車・端角中飛車 | 本美濃 | 本美濃の5八金の行き先に、中飛車の飛車がいる |
| ゴキゲン中飛車 | 本美濃・高美濃 | 同じ（5八の飛車） |
| 原始鬼殺し | 金無双 | 鬼殺しは飛車を振らないので、金無双の▲2八銀の行き先に飛車がいる |

外れても、カードには「囲いは組まない」と、ほかの合う囲いが残る（例: 原始中飛車は片美濃）。組み込みの定義では合う組もあるので、テストと本番でカードの囲いの並びが違うことがある。

### 6-3. 作ったもの（2026-10-27）

- `composeOpeningPlan`・`trackPlanPieces`・`playPlanSteps`・`openingPlanCompatibility`（`opening-guide.mjs`）：駒ごとに合わせた手順と、合わない組の判定。`openingPlanSteps`と作戦カードの小さな盤（`opening-formation.mjs`）は、合わせた手順を使う。
- 近道（`formationProgressMoves`）は、完成形に割り当てた駒だけを動かす。囲いは、手順の残りの手を先に案内し、それで進めないときだけ近道を使う（近道を先にすると、玉が7九を回る道を選んで止まることがあった）。
- 作戦カードの目録（`opening-catalog.mjs`の`plan`）は、合わない囲いを並べない（名前付きの組のカードは除く）。
- `src/core/opening-guide-integrity.test.mjs`：本番と同じデータで、上の3つ（6章の1〜3）を確かめる。`scripts/opening-guide-audit.mjs`は、その一覧を出す（いまは4つの見出しがすべて空）。
