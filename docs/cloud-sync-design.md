## 2. 機能設計メモ（UI_Nintendo_Design.mdの10章の形）

### 機能名：Googleアカウントで同期

- 目的（コンセプトとの関係）：大会（竜王戦・名人戦）と物語は何日も続けて遊ぶ主役。スマホとPCのどちらで開いても続きから遊べ、端末やブラウザの記録が消えても戻せるようにする（D:4-3 安全網）。引き継ぎコードは「1回運ぶ」、同期は「いつも同じ」。
- 利用場面：スマホとPCの両方で遊ぶ人。ログインは1回1分、あとは何もしない。
- 画面の主役：ログインのページの「Googleでログイン」の1つのボタン。ログインしたあとは、ホームの「引き継ぎ・同期」の下の小さな状態（「☁ 14:05 保存」）。
- 情報の優先順位：①ログインしているか ②最後に保存した時刻 ③どちらの記録を使うか（食い違ったときだけ）④ログアウト ⑤クラウドの記録を消す。
- 操作の流れ（手数）：
  - ログイン：ホームの「引き継ぎ・同期」→「Googleでログイン」→ ログインのページの「Googleでログイン」→ Googleの窓でアカウントを選ぶ → 自動でゲームへ戻る（押すのは3回）。
  - 同期：何もしない（開いたとき・戻ってきたとき・遊んでいるあいだ・閉じるときに自動）。
  - 食い違ったとき：開くと「どちらの記録を使う？」が出る → どちらかを押す（1回）。
- 確認ダイアログ：
  - どちらの記録を使うか：選ばなかったほうが消えて取り消せないので、文で言う。初期フォーカスは「あとで決める」（どちらも消さない。N:3-5）。
  - クラウドの記録を消す：取り消せないので確認する。初期フォーカスは「戻る」（UD:5-2の「学習の進み具合をリセット」と同じ）。
  - ログアウト：何も消えないので確認しない（U:3-1）。
- 使うメッセージ分類：通常（保存した・読み込んだ・ログアウトした）と不可（通信できない・準備中・混んでいる）。不可は責めずに、理由と次にすることを1文で言う（U:4）。ゲームが止まるような出し方はしない。
- 初めて使う人への伝え方：ログインのページに3行（何ができるか・使う情報・ログアウトしても記録は残る）。ホームの小さな状態（☁と時刻）で「同期している」が文字を読まなくても分かる。
- 快の要素：ほかの端末の続きを読み込んだら、ホームに「ほかの端末の続きを読み込んだよ」の一言（通常）。待たせない（同期は裏で。3-3）。
- 見ている人への配慮：なし（1人で使う）。メールアドレスはシートの中だけに出し、ホームには出さない（画面を人に見せることがあるため）。
- 作らないと決めたこと：
  - アカウントの管理（名前・写真・ほかのログイン方法）。名前はゲームの名前の札のまま。
  - 記録を項目ごとに混ぜ合わせる（名簿や順位戦のように、ほかの記録とつながる保存が食い違うため。引き継ぎと同じく、記録はいつも全部で1つ）。
  - 前の版の記録をいくつも残す履歴（無料の枠の保存を食う。安全網は「選ばなかったほうをファイルに残す」と、すべてを消すとログアウトしてクラウドを残す決まり（7章））。
  - 対局画面でのログイン（見出しの理由で、ログインは別のページ）。
- 検証方法：自動テスト（決め方・送る文書の形・食い違い・トークンの更新・掃除）、FirestoreとAuthenticationのエミュレーターでの通しの確かめ（2台をまねて、片方で遊ぶともう片方に届く・両方で遊ぶと選ぶ画面が出る・ルールがほかの人の記録を読ませない）、ブラウザの4つの大きさ。本物のGoogleログインは、ユーザーがコンソールで有効にしてから確かめる。
- 根拠：N:2-3（メッセージ）、N:3-4・3-5（確認の文とボタンと初期フォーカス）。

## 3. 同期の決まり（`src/core/cloud-sync.mjs`）

- **記録の単位**：引き継ぎと同じまとめ（`save-transfer.mjs`の`collectSave`。運ぶ鍵は`isTransferKey`）。同期のための鍵（ログインの印と、前に合わせた時点）は運ばない（`TRANSFER_SKIP_KEYS`に足す）。
- **前に合わせた時点（base）**：この端末が最後にクラウドと同じだったときの、クラウドの版（Firestoreの更新時刻`updateTime`と番号`rev`）と、この端末の記録の指紋（鍵を並べた中身のハッシュ）。
- **決め方**（`decideSync`）：

  | クラウド | この端末 | すること |
  | --- | --- | --- |
  | まだない | 記録がある | 送る（初めて作る） |
  | まだない | 記録がない | 何もしない |
  | 前に合わせた時点のまま | 変わっていない | 何もしない |
  | 前に合わせた時点のまま | 変わった | 送る |
  | ほかの端末が進めた | 変わっていない | 受け取って置き換え、読み直す |
  | ほかの端末が進めた | 変わった | どちらを使うか聞く |
  | ある（この端末で初めてログイン） | 記録がない | 受け取って置き換え、読み直す |
  | ある（この端末で初めてログイン） | 記録がある | どちらを使うか聞く |

  - 「記録がない」は、データリセットの種類（`data-reset.mjs`の`RESET_GROUPS`）の鍵と中断した対局が1つもないこと。名前と設定だけなら「ない」に数える（新しい端末で名前だけ入れてからログインしても、聞かずに受け取る）。
  - 「この端末が変わったか」は、ページを開いた直後（対局画面の準備の最初）の指紋で決める。開いたときに各画面が書く小さな保存（移しかえ・見た印）で、変わったと数えないため。
- **いつ合わせるか**：
  - ページを開いたとき：クラウドの見出し（1件）を読んで決める。
  - 戻ってきたとき（ほかのアプリやタブから60秒以上たって戻った）：同じ。
  - 遊んでいるあいだ：60秒ごとに指紋を見て、変わっていて、前に送ってから3分たっていれば送る。
  - 閉じる・ほかへ移るとき（画面が隠れたとき）：変わっていて、前に送ってから30秒たっていれば送る。
  - 受け取って置き換えたら、ページを読み直す（引き継ぎと同じ。どの画面も新しい記録から始まる）。読み直したあと、ホームに「ほかの端末の続きを読み込んだよ」。
- **送り方**：まとめの文字をgzipで縮めてbase64にし（`save-cloud.mjs`の`packText`）、65万文字ずつ最大6件に分ける（引き継ぎと同じ大きさ）。見出し1件と分けた文書を、1回のまとめ書き（`documents:commit`）で書く。見出しには「前に読んだ版のときだけ書く」（`currentDocument.updateTime`。初めては「ないときだけ」）を付ける。ほかの端末が先に書いていたら書けず、食い違いとして扱う（両方を上書きしない）。
- **受け取り方**：見出しと分けた文書を読み、全部が同じ`rev`か確かめる（読むあいだにほかの端末が書いたら、1回だけ読み直す）。
- **ログインの印**：ログインのページが、FirebaseのSDKでログインして得た「更新のための印」（refresh token）とアカウントの番号・メールアドレス・表示名を、この端末の保存`yacobihime:shogi-match:cloud-sync:v1`に置く。対局画面は、合わせるときにRESTで1時間有効の印（IDトークン）を作り直す。印が無効になった（パスワードの変更・アカウントの停止など）ときは、ログアウトして「もう一度ログインしてね」。
- **休む**：通信できないときは次の機会に（60秒ごと・戻ってきたとき）。無料の枠を超えた（429）・書けない（403）ときは1時間休む。

## 4. Firestoreの形とルール

- `cloudSaves/{uid}`（見出し）：`v`（1）・`rev`（1から数える整数）・`at`（保存した時刻）・`device`（保存した端末の印）・`parts`（分けた数、1〜6）・`size`（縮める前の大きさ）・`summary`（確認の窓に出す要約の文字。名前・レーティング・対局数・竜王戦の期数。2000文字まで）。
- `cloudSaves/{uid}/parts/{0〜5}`：`v`・`rev`・`data`（70万文字まで）。
- ルール（`firestore.rules`）：ログインした本人（`request.auth.uid == uid`）だけが読み・書き・消しできる。項目・型・大きさを決める。一覧は出さない。ほかの人の記録は読めない。
- 見積もり（無料の枠）：1人の記録は縮めて0.2〜1MB。保存1GiBで1000〜5000人。書き込みは1回の保存で2〜3件、遊んでいる1時間で多くて20回（3分おき）なので、1日2万件で延べ300〜500時間ぶん。読みは開くたびに1件と、受け取るときに数件。超えたら同期を休み（3章）、記録は端末に残る。人が増えて足りなくなったら、送る間隔を広げるか、課金のプランを考える（ユーザーが決めること）。

## 5. ログインのページ（`auth.html`・`src/auth/login-page.ts`）

- 対局画面の「Googleでログイン」は、`auth.html?return=<今のページ>`へ移る（ページごと移る。対局中は出さないので、移っても対局は消えない）。
- ページ：タイトル「Googleでログイン」、3行の説明、Googleの「G」のボタン「Googleでログイン」、「ゲームに戻る」。
  - 説明：「ログインすると、記録をGoogleアカウントにひもづけて保存し、ほかの端末でも同じ記録で遊べるよ。」「使うのは、アカウントの番号と、この端末に出すメールアドレスと名前だけ。」「ログアウトしても、この端末の記録はそのまま残るよ。」
- ボタンを押すと、FirebaseのSDKの`signInWithPopup`（Googleの窓）。SDKの保存は使わず（`inMemoryPersistence`）、得た印を3章の保存に書いて、`return`のページへ戻る（`location.replace`）。`return`は同じサイトの道（`/`で始まり`//`でない）だけ受け付け、ほかは`./`。
- 失敗の一言：窓が止められた（もう一度押してね）、窓を閉じた（何も言わない）、準備がまだ（「Googleログインの準備がまだできていないよ。引き継ぎコードを使ってね。」）、通信できない。
- SDKはこのページだけが読む（Viteの別のビルド`vite.auth.config.js`で`dist/auth/login.js`を作る）。
- 確かめのため、`127.0.0.1`と`localhost`で開いたときだけ、`?emulator=1`でAuthenticationのエミュレーターにつなぐ（印にエミュレーターの場所を書き、対局画面もFirestoreのエミュレーターを使う）。公開先ではこの道は開かない。

## 6. 画面（`SaveTransferSheet.vue`とホーム）

- ホームの「引き継ぎ」のボタンを「引き継ぎ・同期」にする。ログインしていれば、ボタンの下に小さな状態：「☁ 14:05 保存」「☁ 合わせています…」「☁ どちらを使うか決めてね」（注目）「☁ 休んでいます」。
- シートの最初の段（メニュー）のいちばん上に「Googleアカウントで同期」の組（公開先だけ）：
  - ログインしていない：「Googleでログイン」（小さく「どの端末でも、自動で同じ記録になるよ」）。
  - ログインしている：「○○（メールアドレス）でログイン中」「最後に保存：11月13日 14:05」、ボタン「今すぐ同期」「ログアウト」、小さく「クラウドの記録を消す」。
- どちらを使うかの段（`cloud-choice`）：見出し「どちらの記録を使う？」、補足「選ばなかったほうの記録は消えるよ。」、2つの札（この端末・クラウド。要約の行と保存した時刻）とそれぞれの「この記録を使う」、「この端末の記録をファイルに残す」、「あとで決める」（初期フォーカス）。あとで決めるあいだは送らない（どちらも消さない）。開いたとき・戻ってきたときにもう一度出す。
- クラウドの記録を消す段（`cloud-delete`）：「クラウドの記録を消して、ログアウトします。」「この端末の記録は残るよ。」「消す」「戻る」（初期フォーカス）。
- 言葉は`cloud-sync.mjs`の`CLOUD_SYNC_TEXT`にまとめる（U:4）。

## 7. データリセットとの関係

- 種類を選んで消す（大会・教室など）と、ログインしていればクラウドにも届く（どの端末でも同じ記録、が同期の約束）。確認の窓に「ログイン中なので、ほかの端末でも消えます。」を足す。
- 「すべて（最初から）」は、ログインの印も消すのでログアウトになり、クラウドの記録は残る（もう一度ログインすると、どちらを使うか聞かれる。うっかり消しても戻せる安全網。D:4-3）。確認の窓に「ログアウトします。クラウドの記録は残ります。」を足す。

## 9. ユーザーがコンソールですること

1. Firebaseのコンソール（`https://console.firebase.google.com/project/shogi-64125/authentication`）で「始める」を押す。
2. 「ログイン方法」→「Google」→「有効にする」→ プロジェクトのサポートメールを選んで「保存」。

承認済みドメインには、はじめから`shogi-64125.web.app`と`shogi-64125.firebaseapp.com`が入る。コードの公開し直しは要らない。
