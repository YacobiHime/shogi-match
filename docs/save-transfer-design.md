## 1. 機能設計メモ（UI_Nintendo_Design.mdの10章の形）

### 機能名：引き継ぎ

- 目的（コンセプトとの関係）：大会（竜王戦・名人戦）と物語は何日も続けて遊ぶ主役。端末を替えても続きから遊べるようにして、積み上げた期や称号を失わせない（D:4-3 安全網）。
- 利用場面：スマホとPCの両方で遊ぶ人、端末を買い替える人。1回1分。月に何回か。
- 画面の主役：送る側は「引き継ぎコード」の12文字。受け取る側は、置き換える前の「引き継ぐ記録」と「この端末の今の記録」の見くらべ。
- 情報の優先順位：①何をするか（送る・受け取る）②コード ③期限（7日・1回で消える）④運び方の説明 ⑤ファイルの代わりの道。
- 操作の流れ（手数）：
  - 送る：ホームの「引き継ぎ」→「引き継ぎコードを作る」で2回。
  - 受け取る：ホームの「引き継ぎ」→「コードを入れる」→ 入力 →「受け取る」→「置き換える」で4回と入力。
  - ファイル：「ファイルに書き出す」で保存、もう1台で「ファイルを読み込む」→ ファイルを選ぶ →「置き換える」。
- 確認ダイアログ：置き換えるときだけ出す。この端末の記録が消えて取り消せないので、5-2の「学習の進み具合をリセット」と同じ扱い。最初のフォーカスは「戻る」。送る（コードを作る・書き出す）は何も消さないので、確認しない（U:3-1）。
- 使うメッセージ分類：通常（あずけている・受け取っている・保存したよ）と不可（コードが違う・通信できない）。不可は責めずに、理由と次にすること（打ち間違いか7日を過ぎたかも・ファイルで運んでね）を1文で言う（U:4）。
- 初めて使う人への伝え方：メニューは「この端末から送る」と「この端末で受け取る」の2つの見出しに2つずつ並べ、どちらの端末で押すかを見出しで分ける（UD:3-1。同じ種類の選択肢は2つまで）。コードの画面に、もう1台でどこを押すかを1文で書く。
- 快の要素：コードは大きな等幅の字で、4文字ずつハイフンで区切る。押すとすぐ「あずけているよ…」と回る印が出る（U:9 押した瞬間に反応）。
- 見ている人への配慮：なし（1人で使う）。
- 作らないと決めたこと：
  - ログインと自動の同期（アカウント管理は作らない。両方の端末で遊んだときの「どちらを残すか」を毎回聞くことになり、迷う場面が増える）。
  - 記録の一部だけを運ぶ（大会だけなど）。名簿と順位戦のように共有する記録が食い違うため、引き継ぎはいつも全部を置き換える。
  - コードの作り直しの取り消し（7日と1回で消えるので要らない）。
- 検証方法：自動テスト（まとめ・置き換え・暗号・分割・期限）と、ブラウザで2台をまねて、コードとファイルの両方で名前と成績が移ること。
- 根拠：N:3-4・3-5（確認の文とボタン）、N:2-3（メッセージの分類）。

## 2. 運ぶもの（`src/core/save-transfer.mjs`）

- このゲームの保存の鍵（`exhibit-reset.mjs`の`isAppStorageKey`。頭が`yacobihime:shogi-match:`・`shogi-match:`・`shogi-match-`・`shogiMatch`）を全部まとめる（`collectSave`）。新しい保存の鍵を足しても、そのまま運ばれる。
- 運ばない鍵（`TRANSFER_SKIP_KEYS`）：匿名送信の端末の番号と同意（端末ごとに聞く）、読み直しの印、やこびノートの開いていた項目とアルバムのページ。
- 音と盤・駒の見た目は運ぶ（その人の好み）。中断した対局も運ぶ（同じページの場所の鍵なので、もう1台で「対局を再開」できる）。
- まとめの形は`{ format: "yacobihime-shogi-save", v: 1, at, entries: { 鍵: 文字 } }`。読むとき（`decodeSave`）は、このゲームの鍵で文字の値だけを受け取る。新しい版のまとめは読まない（「ページを読み直してから」と言う）。古い版の保存の中身は、各モジュールの読み込みがいつもの移しかえで新しくする。
- 置き換え（`applySave`）は、運ぶ鍵を全部消してからまとめの中身を書く（もう1台と同じにする）。容量を超えて書けないときは、置き換える前の記録に戻す。
- 置き換えたらページを読み直す（データリセットと同じ。どの画面も新しい記録から始まる）。

## 3. 引き継ぎコード（`src/core/save-cloud.mjs`）

- コードは12文字。見まちがえやすい0・O・1・I・Lを除く31文字から選ぶ（約59ビット）。見せるときは`XXXX-XXXX-XXXX`、入れるときは空白・ハイフン・全角・小文字を受け付ける。
- 中身：まとめの文字をgzipで縮め（`CompressionStream`）、コードから作った鍵（SHA-256）のAES-GCMで暗号にする。Firestoreに置くのは暗号だけで、名前も成績も、コードを知らない人には読めない（Firestoreの持ち主にも）。
- 置き場所：公開先のFirebaseプロジェクトのFirestoreの`saveTransfers`。文書の名前もコードから作る（SHA-256の先頭40文字）。文書は1件1MBまでなので、65万文字ずつ最大6件に分ける（縮めたあとで約3MBまで。超えたら「ファイルで運んでね」）。分けた文書を先に置き、最後に0番を置く（0番があれば全部そろっている）。
- SDKは使わずRESTで送る（最初に読むJSを重くしない。棋力テストの答えの送信`skill-data.mjs`と同じ）。
- ルール（`firestore.rules`）：
  - 作る：名前の形・項目・型・大きさ（1件70万文字まで）・期限（8日以内）を決める。同じ名前への上書きはできない。
  - 読む：期限までの1件ずつ（一覧は出さない。名前はコードを知る人しか分からない）。
  - 消す：名前を知る人（受け取った人）。受け取ったら消す（コードは1回だけ）。
- 期限は7日。過ぎた文書はルールが読ませない。消すのは受け取った人。受け取られなかった文書は、Firestoreの持ち主がTTL（`expireAt`の項目）を設定すると自動で消える（設定はFirebaseのコンソールで行う。2026-11-11の時点では未設定）。
- 使えるのは公式の公開先で、暗号が使える（httpsの）ときだけ（`canUseSaveCloud`）。展示用のパッケージやローカルの開発では、メニューにコードの2つを出さず、「ファイルで運んでね」と書く。

## 4. 画面（`src/SaveTransferSheet.vue`）

- 入口：ホームのタイトルの下（PCでは左列の下、スマホでは画面のいちばん下）に「引き継ぎ」。展示用の「データリセット」と並べる（どちらも記録の出し入れ。`shogi-title__tools`）。いつも出す。
- 段は`menu`（送る・受け取るの2組）→`busy`（回る印）→`code`（コード・期限・もう1台ですること・コピー）／`enter`（入力）→`confirm`（2つの記録の見くらべと「今の記録をファイルに残す」・置き換える／戻る）。
- 戻る操作・Esc・外を押す：段を1つ戻し、メニューなら閉じる（`goBack`）。あずけている・受け取っているあいだは戻らない。
- 置き換えの確認は、主題を先頭に「この端末の記録を、引き継いだ記録に置き換えます。」、補足に「いまのこの端末の記録は消えます。」、ボタンは「置き換える」と「戻る」（N:3-5）。消える前に残したい人のために「今の記録をファイルに残す」を1つ置く（D:4-3）。
- 言葉は`save-transfer.mjs`の`SAVE_TRANSFER_TEXT`にまとめる（U:4）。
