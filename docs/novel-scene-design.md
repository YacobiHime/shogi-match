# ノベルの場面のUI（`NovelScene.vue`）

団体戦の場面・将棋まつりのトークショー・後で作る物語モードで使う、ノベルの場面の部品の設計です。
台本の形（`{ id, title, background, cast, lines: [{ who, face, name, text, choices? }] }`）は`docs/team-battle-design.md`の6章、ノベルから使える人物と舞台は`docs/novel-reference.md`にあります。

## 1. 依頼と前提（2026-11-01）

ユーザーの依頼：「ノベルゲーム部分のUIについて、実際のゲーム（サクラノ刻やSummer Pocketsのような近年の名作ノベルゲームなどや、近年の人気ゲームのノベルゲーム形式部分など）のUIを参考にしながら、強化して。」

いまの部品にあるもの：文字送り（30ms/字）、押して進む（クリック・Enter・Space・→）、答えの選択肢、右上の「飛ばす」、話していない人の立ち絵を暗くする、背景（CSSの4種）、`prefers-reduced-motion`。

いまの部品にないもの（ノベルゲームの標準と比べて）：読み返し、オート、窓を隠す、文字の速さ、飛ばした場面の中身を知る方法、既読の早送り、場所の札、立ち絵の動き。文字送りの途中で行の折り返しが変わって文が動く。

## 2. 参考にしたゲームのUI（調べたことと、使う形）

| ゲーム | UIの形 | このゲームで使う形 |
| --- | --- | --- |
| 近年の美少女ゲーム・ノベルゲーム（『サクラノ刻』『Summer Pockets』など） | 下に横長の文の窓。窓は背景が透ける半透明で、名前は窓の左上の札。窓の下の端に小さな操作の帯（ログ・オート・スキップ・設定・窓を消す など）。右クリックで窓を消す、ホイールの上でログ、Ctrlを押している間は既読を早送り。読み返し（バックログ）で過去の台詞を名前つきで読める。文字の速さ・オートの速さを設定で選べる。場面の始めに場所や日付の札が出る | 窓と名前の札、操作の帯（ログ・オート・隠す・設定）、右クリックとHで隠す、ホイールとキーの操作、Ctrlの既読の早送り、ログ、2つの速さの設定、場所の札 |
| スマホの人気ゲームの物語（ノベル形式の部分） | 画面の右上に「オート」「ログ」「スキップ（メニュー）」。スキップを押すと、その話の「あらすじ」を見せてから飛ばす。話している人の立ち絵が少し前に出て、表情が変わると小さく跳ねる。選択肢は画面の中央に大きく、選んだ答えはログに残る | 「飛ばす」で、まだ読んでいない場面ならあらすじを見せる。話す人の立ち絵を前に、表情が変わったら小さく跳ねる。選択肢は中央に番号つきで、ログに「▶ 選んだ答え」 |

まねる対象は「形」だけで、絵・文言・配色は写しません（`AGENTS.md`の約束。ほかのゲームの再現は作らない）。

## 3. 機能設計メモ（Game_Nintendo_Design.mdの14章・UI_Nintendo_Design.mdの10章の形）

### 機能名：ノベルの場面のUIの強化

- 一言で：場面を「自分の速さで読める」ようにし、羽音・百花と過ごす時間を気持ちよくする（D:8-2 ゲームのシナリオは特異、D:3-1 無反応をなくす）。
- 解く課題（D:2-5）：
  1. 読み飛ばした台詞を読み返せない（ログ）。
  2. 押し続けないと進まない・自分には速すぎる/遅すぎる（オート・速さの設定）。
  3. 飛ばすと何が起きたか分からない（あらすじ）。2回目以降の場面がまどろっこしい（既読の早送り・読んだ場面はすぐ飛ばす）。
  4. 文字送りの途中で文が折り返し直して動き、読みにくい（先に場所を取る）。
  5. 立ち絵が止まっていて、誰が話しているか・気持ちが変わったかが伝わりにくい（前に出る・跳ねる）。
- 初めての人の最初の1分（D:3-3）：場所の札が出て、そのまま押して読める。操作の帯は文字のボタンなので、説明なしで分かる（UD:6-1）。何も覚えなくても、今までどおり押すだけで最後まで読める。
- 上級者の深さ（D:2-4）：キーとホイールの操作、Ctrlの早送り、速さの設定。画面には出さず、知っている人だけが使う（N:2-5）。
- 失敗したとき（D:7-1）：読み飛ばしたらログで戻って読める。
- ご褒美と使い道（D:5-1）：この依頼では足さない（場面の思い出の回想は6章の候補）。
- 捨てるもの（N:1-4）：
  - セーブ・ロード（場面は12行までで短い。D:9-1）。
  - 声・文字の音・BGM（音の素材がない。音は今の`SoundManager`の外に増やさない）。
  - ログから過去の行へ戻って読み直す（選択肢の返しを差し込む形と食い違う）。
  - 窓の濃さ・文字の大きさの設定（設定は2つまで。UD:3-1「設定は最小限」）。
  - 既読の文の色を変える（場面が短く、意味が小さい）。
- 確かめ方：3つの大きさのブラウザで、場面を開き、操作の帯・ログ・オート・隠す・設定・あらすじ・選択肢を押す。実際に読んでの手ざわりはユーザー（未確認）。

## 4. 決めたこと

### 4-1. 画面の並び（UD:4、U:7-5）

| 優先度 | 要素 | 表し方 |
| --- | --- | --- |
| 1 | 文 | 下の窓。いちばん明るい文字。窓は下ほど濃い半透明で、背景と立ち絵が透ける |
| 2 | 話している人 | 名前の札（人ごとの色の線）と、その人の立ち絵が明るく少し前に出る |
| 3 | 送りの印 | ▼（続く）・■（終わり）。オート中は窓の下の端に細い待ちの線が伸びる |
| 4 | 操作の帯 | 窓の右下に小さく「ログ」「オート」「隠す」「設定」。オート中は「オート」が点く |
| 5 | 場所・飛ばす | 左上の場所の札、右上の「飛ばす」 |

- 文字送りでは、まだ出していない字も透明で先に置き、行の折り返しを最初から決める（文が動かない。UD:2の1「迷わない」）。読み上げには、行が変わったときに文の全部を1回だけ伝える（U:7-4）。
- 選択肢は窓の上・画面の中央に、番号（1〜3）つきの大きなボタンで出し、後ろを少し暗くする。キーの1〜3でも選べる。選択肢は立ち絵の段の下のほうに重ね、立ち絵の段を縮めない（スマホの横向きで立ち絵が小さくなるため）。

### 4-2. 操作（U:2の考え方を場面に当てる）

| 操作 | 結果 |
| --- | --- |
| 画面を押す・Enter・Space・→・ホイールの下 | 文が出かけなら全部出す。出ていれば次の行 |
| ログ・↑・ホイールの上 | 読み返しのシート（名前・文・選んだ答え） |
| オート・Aキー | 文が出きってから、文の長さに合わせて待って進む。選択肢では止まる。もう一度押すと切れる |
| 隠す・Hキー・右クリック | 窓と帯を隠して立ち絵と背景を見る。どこを押しても戻る。タッチの長押しでは隠さない（押しまちがいで消えないように） |
| 設定 | 文字の速さ（ゆっくり・ふつう・はやい・すぐ）とオートの速さ（ゆっくり・ふつう・はやい） |
| Ctrlを押している間 | 読んだことのある行を早送り。まだ読んでいない行・選択肢で止まる（PCだけ） |
| 飛ばす | 読んだことのある場面、あらすじのない場面はすぐ最後へ。まだ読んでいない場面は、あらすじのシート（[続きを読む] [飛ばす]。はじめのフォーカスは「飛ばす」） |
| 戻る操作・Esc | 開いているシート（ログ・設定・あらすじ）や隠した窓を先に閉じる。なければ今までどおり（団体戦は場面を閉じる） |

- あらすじのシートは「はい／いいえ」の確認ではなく、読まずに飛ばす場面の中身を伝える情報として出す。飛ばす意思はもう示されているので、はじめのフォーカスは「飛ばす」（UD:5-2の「選択の余地がないことを質問しない」に合わせ、問いではなくあらすじを主題にする。N:3-4）。トークショーのように答えのある場面は「飛ばすと、答えなかったことになるよ」と添える。
- どの操作も押した瞬間に見た目が変わる（オートが点く、帯の押した表示、シートが開く）（D:3-1）。

### 4-3. 動き（D:3-2、U:6）

| 動き | 長さ（初期値） |
| --- | --- |
| 場所の札（左から出て、1.8秒で小さくなる。押して読むのは止めない） | 出る320ms・残る1.8秒 |
| 立ち絵が出る（下から少し上がって現れる） | 240ms |
| 話す人が前に出る・ほかが暗くなる | 160ms |
| 表情が変わったときの小さな跳ね | 220ms |
| シートが開く | 160ms |

- `prefers-reduced-motion: reduce`のときは、動きをなくし、明るさの変化だけ残す。文字送りもすぐ全部出す（今までどおり）。

### 4-4. 速さ（初期値。触って直したら表も直す）

| 文字の速さ | 1字の間隔 |
| --- | --- |
| ゆっくり | 55ms |
| ふつう | 30ms（今までの値） |
| はやい | 14ms |
| すぐ | 0ms |

| オートの速さ | 文が出きってから進むまで |
| --- | --- |
| ゆっくり | 2.2秒＋1字90ms（上限7秒） |
| ふつう | 1.4秒＋1字60ms（上限6秒） |
| はやい | 0.8秒＋1字35ms（上限4秒） |

- Ctrlの早送りは1行70ms。

### 4-5. 保存

- 設定は`yacobihime:shogi-match:novel-settings:v1`（データリセットでは消さない設定）。
- 読んだ行の印は`yacobihime:shogi-match:novel-read:v1`（場面のidごとに、行の文の短い印。データリセットの「大会の進み具合」で消す。場面は大会から開くため）。1つの場面は200行・場面は120までで、古いものから捨てる。

### 4-6. 置き場所

- 画面に依存しない処理（速さの表・オートの待ち・設定と既読の保存・ログの行・言葉）は`src/core/novel-ui.mjs`、テストは`novel-ui.test.mjs`。
- 画面は`src/NovelScene.vue`。戻る操作のために`goBack()`を出し、団体戦（`ShogiTeamBattle.vue`）と将棋まつり（`ProFestival.vue`）の戻る操作から先に呼ぶ。
- あらすじは台本の`summary`（団体戦の場面は`team-story.mjs`、トークショーは`pro-festival.mjs`の`talkScene`）。

## 7. 立ち絵を上半身にし、文を大きくする（2026-11-01、ユーザーの指摘）

ユーザーの言葉：「立ち絵の表示がおかしい。例えばですが、この3枚のように、キャラクター表示は基本的にキャラクターの全身像を映さず、上半身を映す。また、文字部分ももっと大きい。3枚の画像を参考にUIを修正して。」（将棋のノベルゲームの画面写真3枚）

参考の写真から読み取った形：

- 立ち絵は頭から腰までの上半身を大きく映し、腰から下は文の窓の後ろに沈む。2人なら左右、3人なら左・中・右。
- 文の窓は画面の下いっぱいの帯で、上の端は透明、下へ行くほど温かい紙の色になる（立ち絵が透けて見える）。細かい点の模様。
- 名前は窓の左上の紙の札（点線の縁・左に駒の印・右に色の帯）。
- 文は大きく濃い字で2行ほど。右下に駒の形の送りの印と「NEXT」。

まねるのは形だけで、絵・模様の細部・文言は写さない（4章と同じ）。決めたこと：

| 項目 | 前（5章） | 今 |
| --- | --- | --- |
| 立ち絵 | 全身を窓の上の段に収める | 上半身。絵の高さhは「窓の上の高さ÷0.47（頭から腰まで）」と「1人の幅（1人は84%、2人は64%。細い縦の画面の2人は74%）÷絵の縦横比」の小さいほう。腰が窓の上の端に来るよう、絵の下を窓の後ろへ沈める。縦横比は出ている人のうちいちばん横に広い絵でそろえ、みんな同じ縮尺（`team-story.mjs`の`portraitAspect`）。2人は横の28%と72%に立つ |
| 話していない人 | 暗く（明るさ0.6） | 少しだけ暗く（明るさ0.84）。参考の写真ではみんなふつうの色なので、話す人が分かる程度にとどめる |
| 文の窓 | 浮いた暗い角丸の箱 | 画面の下いっぱいの温かい紙の色の帯（上は透明）。中身の幅は58remまで |
| 文の大きさ | 1.08em（約17px） | 画面の幅と高さで決める（スマホ縦で約18px、タブレット縦で約26px、デスクトップで約28px）。濃い茶色 |
| 名前 | 色の線つきの暗い札 | 紙の札（点線の縁・駒の印・色の帯）。地の文でも札の行を取っておき、窓の高さを変えない |
| 送りの印 | ▼・■ | 駒の形の印と「つぎへ」（最後は「おわり」）。子どもも読めるよう日本語にした（U:4） |
| 操作の帯 | 窓の右下 | 窓の左下（送りの印を右下に置くため） |
| 隠す | 窓を消す（`display: none`） | 窓を見えなくするだけで場所は残す（立ち絵の大きさが変わって跳ねないように） |
| 場所の札 | 窓の上の段の1行 | 画面の左上に重ねる（立ち絵の段を狭めない） |

- 原則：主役（話している人と文）を大きく濃く（UD:4 情報の優先順位、N:2-8）、読みやすさを先に（UD:7-3 新鮮さより可読性）、メニューは世界を語る（D:8-4。紙の札と駒の印で将棋の物語らしく）。
- 実装（2026-11-01、実装・自動テスト済み）：`src/NovelScene.vue`の書式を作り直した（`.novel__stage`の`container-type: size`と`--bust`・`--slot`・`--aspect`で絵の高さ`--h`を出す、`.novel__box`の帯、`.novel__name`の札、`.novel__next`の印）。言葉は`novel-ui.mjs`の`NOVEL_UI_TEXT.next`・`end`。
- 確かめたこと：`npm test`・`npm run typecheck`・`npm run build`、ブラウザ（390×844・820×1180・1366×768・844×390）で団体戦の誘いの場面の写真（上半身・大きな文・名前の札・つぎへ）、ログ・設定・オート・隠す・あらすじ・飛ばすの操作、トークショーの選択肢（390×844・1366×768・844×390）。どの大きさでも横にはみ出さない。
- まだ確かめていないこと：本物のスマホ・タブレットでの見え方（`cqh`・`cqw`の単位は新しめのブラウザが要る。Safariは16以降）、実際に読んでの文の大きさ（未確認）。スマホの横向きは窓が画面の半分近くを取り、立ち絵は小さめ。

## 8. 身長差（2026-11-01、ユーザーの指定）

ユーザーの言葉：「羽音の身長は147cmで、百花の身長は158cmです。今はなぜか羽音の方が大きいので、身長差に合わせた大きさに修正してください。」

- 原因：立ち絵は全身の絵の高さ（約2325px）がそろえてあり、羽音の絵のほうが横に細いので、同じ高さで並べると羽音が大きく見えていた。
- 決めたこと：身長を`team-story.mjs`の`PORTRAIT_HEIGHT_CM`（羽音147・百花158）に持ち、場面に出ている人のうちいちばん背の高い人を1とした比（`portraitScale`）で絵を縮める。足元の位置はそろえるので、背の低い人は頭が下がる（147/158で約93%）。1人だけの場面はそのままの大きさ。
- 実装（実装・自動テスト済み）：`NovelScene.vue`の`.novel__person`の高さを`var(--h) * var(--scale)`にした。テストは`team-story.test.mjs`。ブラウザ（4つの大きさ）で、2人の場面の百花が羽音より頭ひとつ弱く高いことを写真で見た。

## 9. 立ち絵をもっと大きく・身長差を少し小さく（2026-11-01、ユーザーの指摘）

ユーザーの言葉：「キャラクター画像の表示の仕方をもっとこの画像に寄せよう。これはもっと画像が大きく表示されている。また、実際の身長差より、少し身長差が小さくなっています。適度に調整してください。」（将棋のノベルゲームの画面写真1枚）

## 11. 文字の音とクリックの音（2026-11-01、ユーザーの依頼）

ユーザーの言葉：「ノベルゲーム部分は、文字が出る時にモールス信号やタイプライターみたいな音を出したい。」「おすすめの音はある？ クリックした時に出す音も欲しい。必要ならネットで探してダウンロードしてきても問題ありません。」

### 11-1. 機能設計メモ（Game_Nintendo_Design.mdの14章の形）

### 機能名：ノベルの場面の文字の音とクリックの音

- 一言で：文字が「ピッ、ピッ」「カタカタ」と鳴りながら出てきて、人物が話している手ざわりが耳でも分かる（D:3-4 音は心に直接届く）。
- 解く課題：
  - 文が出ているあいだ、無音で待つ間延びをなくす。
  - 誰が話しているかを、音の高さでも伝える（名前の札と合わせて、目と耳の両方で。UD:5-3）。
  - 押したのに何も起きないように感じる無反応をなくす（G:3-4）。
- リスクとリターン：なし（演出）。
- 溜めと解放：文が打ち出されるあいだ音が続き（溜め）、行の終わりで止まり、押すと「ポッ」で次の行へ（解放）。句読点では黙るので、音が文の間（ま）を刻む。
- 初めての人の最初の1分：場面を開くと、地の文はタイプライターのカタカタ、羽音の台詞は低めの「ピッ」、百花の台詞は高めの「ピッ」。押すと柔らかい「ポッ」。設定を開かなくても、初期値の「おまかせ」で鳴る。
- 上級者の深さ：読み方の設定の「文字の音」で、おまかせ・タイプ・信号・なしを選べる。選ぶと、その音で「将棋の音」と試しに鳴る（選んだ結果がすぐ分かる。G:3-4）。
- 失敗したとき：該当なし。うるさいときは「なし」、全部止めたいときは効果音をOFF。
- ご褒美と使い道：なし。
- ほめる瞬間：なし。
- 捨てるもの：
  - ネットから探した音声ファイル（理由は11-2）。
  - 人物ごとの声の録音（ボイス）。
  - 音量のつまみ。オン/オフは今までの「効果音」と、文字の音の「なし」だけ（設定は最小限。UD:3-1）。
  - 早送り・「すぐ」の速さでの文字の音（速く出るときに鳴らすと音が詰まってうるさい）。
- 確かめ方：ユーザーに団体戦の誘いの場面を読んでもらい、次の3つを聞く。うるさくないか。誰の台詞か音で分かるか。クリックの音の手ざわりはどうか。

### 11-2. おすすめの音と、ファイルを使わずに作る理由

- おすすめは「おまかせ」です。
  - 地の文はタイプライター（紙を打つ短い雑音と、低い打鍵の芯）。
  - 台詞はモールス信号のような電子音で、話す人ごとに高さを変える。
  - 地の文と台詞が音で分かれ、台詞は誰のものか耳でも分かる。
  - モールス信号の短点・長点のように、4字に1字ほど長い音を混ぜて、信号らしさを出す。
- 音はネットからダウンロードせず、ブラウザの中で作る（Web Audio）。理由は次のとおり。
  - 1字ごとに鳴る音は数十ミリ秒の短い音で、その場で作れば、話す人ごとの高さ・長さを数字で自由に変えられる（ファイルなら人の数だけ用意する）。
  - 読み込みを待たない。場面の画面は開いたときに読み込むので、ファイルだと最初の数文字が無音になりやすい。インターネットなしの展示のパッケージにも、そのまま入る。
  - 素材の使用条件（再配布・クレジットの表記）を確かめる手間と危うさがない。
  - 触って直すときも、`novel-sound.mjs`の数字を変えるだけで、ファイルを作り直さない（文書の数値は初期値で、触って直す前提）。
- 駒音は今までどおりファイル（`move-sound.ts`）のまま。駒音は本物の木の音が気持ちよさの中心（UD:7-1）で、作った音では出せない。文字の音は、本物の音をまねなくてよい（D:3-4 音はフィクション）。

### 11-3. 決めたこと（初期値。触って直したら表も直す）

| 項目 | 値 |
| --- | --- |
| 文字の音の種類 | おまかせ（地の文はタイプ・台詞は信号）・タイプ・信号・なし。初期値はおまかせ |
| 信号 | 柔らかい正弦波。短い音32ms・長い音70ms（字の番号で、4字に1字ほど長い）。大きさ0.05 |
| タイプ | 雑音を帯域で絞った16msの「カッ」（中心は話す人の高さの3倍）と、190Hzの低い「トッ」。大きさ0.09 |
| 話す人の高さ | 地の文760Hz・羽音540Hz（落ち着いた低め）・百花880Hz（明るい高め）・あなた660Hz・司会600Hz・ほか700Hz。字ごとに±3%揺らす（同じ字はいつも同じ高さ） |
| 鳴らす間 | 前の音から50ms以上あいたときだけ。ふつうの速さ（1字30ms）では2字に1回、ゆっくり（55ms）では1字ずつ。音が重なってうるさくならないように（U:5 連続する音は重ねない） |
| 鳴らさない字 | 空白・句読点・かっこ・「！」「？」「…」「ー」など。間として黙る |
| 鳴らさないとき | 文字の速さ「すぐ」、押して行の残りを一度に出したとき、Ctrlの早送り |
| 押した音 | 進む：980→620Hzへ下がる「ポッ」45ms・0.11。答えを選ぶ：1180→760Hz・70ms・0.13（いちばんはっきり。G:3-3 重要度で音量）。下の帯のボタン・飛ばす：1400→1100Hz・28ms・0.06 |
| 物語の画面 | ストーリー選択（`ShogiStory.vue`）も同じ押した音。タブと戻るはボタンの音、開ける話のカードは答えの音、まだ開けないカードはボタンの音 |
| オン/オフ | 全体の「効果音」（対局画面のメニュー。`yacobihime:shogi-match:sound`）がOFFなら、文字の音も押した音も鳴らない。文字の音の「なし」は、文字の音だけを止める（押した音は効果音に従う）。設定のシートに「効果音がOFFだと音はぜんぶ鳴らない」と一言書く（スマホでも出す） |
| 保存 | 読み方の設定`novel-settings:v1`の`voice`（データリセットで消さない設定） |

- 音は立ち上がりを4msで速く、余韻を短くする（G:3-3 アタック強め・残響ほどほど）。どれも駒音より小さい（文を読むじゃまにならない）。
- 音だけで意味を伝えない。誰が話しているかは名前の札、押したことは画面が進むことで、見た目でも伝わる（G:3-3、U:5）。
- ブラウザは人が画面を押す前に音を出さないので、音の道具（AudioContext）は最初に鳴らすときに作る（U:5）。場面を閉じたら、最後の「ポッ」を切らないよう0.3秒待ってから閉じる。

## 12. ノベルのエンジンの強化と、台本の書き方（2026-11-04、ユーザーの依頼）

依頼：「ノベルゲームのエンジン部分を強化したい。ほかのAIでもノベルの部分を作れるようにしたい。キャラが動く演出などを簡単にできるようにしたい。ほかにも何かあれば作ってほしい。エンジンとして強化するか、作り方をマークダウンにまとめてほしい」。

両方をする。エンジンには演出の語彙と台本のテキスト形式と検査を足し、作り方は`docs/novel-authoring-guide.md`にまとめる。

### 12-1. 機能設計メモ（Game_Nintendo_Design.mdの14章の形）

### 機能名：ノベルの演出と台本の書き方

- 一言で：台本の行に「ぴょん」「！」「暗転」と一言添えるだけで、キャラが動き、気持ちが見え、場面が切り替わる。台本はマークダウンのような文で書け、書きまちがいはその場で教えてもらえる（D:8-2 ゲームのシナリオは特異、D:3-1 無反応をなくす、D:8-1 パラメーターでキャラ立ちを）。
- 解く課題（D:2-5）：
  1. 立ち絵が表情を変えるだけで動かない。驚く・喜ぶ・落ち込むが、文でしか伝わらない。
  2. 場面の途中で人が来る・去る、背景が変わる、時間が飛ぶ（暗転）を表せない。
  3. 台本がJavaScriptの中にあり、書くのに作りを知る必要がある。書いた台本を見るには、ゲームの中でその場面まで進める必要がある。
  4. 羽音の敬語と「！」、知らない表情の名前など、書きまちがいに気づく仕組みがない（人もAIも同じまちがいをする）。
- 初めての人（書き手）の最初の1分（D:3-3）：ガイドの「いちばん短い台本」を写し、試し読みのページに貼って「再生」を押すと動く。演出の名前を知らなくても、地の文と台詞だけで今までどおりの場面になる。
- 上級者の深さ（D:2-4）：ほかの人の動き（`[百花:うなずく]`）、表情だけ変える（`[百花:worried]`）、選択肢と返し、変数、背景の重ね替え、回想の色。
- 失敗したとき（D:7-1）：検査が行の番号と直し方を出す（「羽音は敬語を使いません：『です』」）。知らない演出は黙って捨てず、検査で必ず知らせる。
- ご褒美と使い道（D:5-1）：書き手のご褒美は、すぐ動いて見えること（試し読み）。プレイヤーには、気持ちの伝わる場面。
- 捨てるもの（N:1-4）：
  - 立ち絵の自由な位置・拡大縮小・回転の数値指定（自由すぎると書き手が迷い、画面の大きさで崩れる。位置は左・中・右の3つの決まった席にする）。
  - 演出の時間を書き手が数字で決める（間`間:600`だけ。ほかは決まった長さ。G:3-1 同じ段階は同じ強さ）。
  - BGM・効果音のファイル（素材がない。効果音はWeb Audioで作る短い音だけ。11章と同じ考え）。
  - セーブ・ロード、分岐で別の場面へ飛ぶ（場面は短く、分岐は選択肢の返しで足りる）。
- 確かめ方：検査と台本の読み込みは自動テスト。演出はブラウザの試し読みのページと物語の画面で写真。実際に読んでの手ざわりはユーザー（未確認）。

### 12-2. 演出の語彙（決めたこと。初期値）

行に足せるもの。どれも書かなければ今までどおり。名前は英語のid（コード）と日本語の呼び名（台本）の両方で書ける。

| 種類 | id（呼び名） | 見え方 | 長さ |
| --- | --- | --- | --- |
| 動き | `hop`（ぴょん） | 小さく1回跳ねる | 0.26秒 |
| 動き | `jump`（大喜び） | 2回跳ねる | 0.62秒 |
| 動き | `nod`（うなずく） | 下に2回うなずく | 0.42秒 |
| 動き | `shake`（首を振る） | 左右に振る | 0.48秒 |
| 動き | `tilt`（かしげる） | 首をかしげて戻る | 0.6秒 |
| 動き | `bow`（おじぎ） | 前に傾いて戻る | 0.7秒 |
| 動き | `shiver`（ぶるぶる） | 小さく震える | 0.5秒 |
| 動き | `lean`（前に出る） | ぐっと前に出て戻る | 0.42秒 |
| 動き | `recoil`（のけぞる） | 後ろへのけぞって戻る | 0.36秒 |
| 動き | `sink`（しょんぼり） | 少し沈んで暗くなり、戻る | 0.7秒 |
| 漫符 | `surprise`（！）・`question`（？）・`sweat`（汗）・`heart`（ハート）・`anger`（怒）・`note`（音符）・`idea`（ひらめき）・`sigh`（ため息）・`sparkle`（きらきら） | 頭の上に小さな印がぽんと出て消える | 1.1秒 |
| 画面 | `flash`（光る） | 白く光る | 0.22秒 |
| 画面 | `quake`（揺れる） | 画面が揺れる（だんだん小さく。G:3-2） | 0.4秒 |
| 画面 | `blackout`（暗転） | 暗くなってから明ける。文は明けてから出る（時間が飛ぶ・場所が変わる） | 0.9秒 |
| 色 | `tone:memory`（回想）・`tone:dim`（暗く）・`tone:none` | 次に変えるまで続く | 0.4秒で変わる |
| 背景 | `bg:<背景のid>` | 次に変えるまで続く。重ねて替わる | 0.5秒 |
| 登場・退場 | `enter`・`enter:left`・`enter:right`（登場）、`exit`（退場） | 横から入る・薄くなって出る。席は出ている人の数で決まる（1人は中、2人は左右、3人は左・中・右） | 0.32秒 |
| 表情だけ | `百花:worried` | 話していない人の表情を変える | すぐ |
| 効果音 | `sfx:pop`（ぽん）・`chime`（きらり）・`impact`（どん）・`koma`（駒音）・`door`（戸）・`bell`（チャイム） | Web Audioで作る短い音。効果音のオン/オフに従う | 0.1〜0.8秒 |
| 文 | `big`（大きく）・`small`（小さく）・`slow`（ゆっくり）・`fast`（早口） | その行だけ | ― |
| 間 | `wait:600`（間:600） | 文が出始めるまで待つ（0〜3000ms） | ― |

- 背景は今の4つ（`classroom`・`hall`・`venue`・`night`）に、`street`（夕方の帰り道）・`room`（部屋）・`black`（黒）・`white`（白）を足した。CSSで描く（画像を足さない。4章と同じ）。
- `prefers-reduced-motion: reduce`のときは、動き・揺れ・光りをなくし、漫符と色の変化と音だけ残す（G:3-2、U:7-4）。暗転は短い明るさの変化にする。
- 演出は見た目だけ。押して進む・ログ・オート・早送りは演出を待たない（G:3-2 プレイヤーの入力は止めない）。早送りとオートでも演出は出る（見えなくても、先へ進める）。
- 演出と同じ意味は文でも伝える（音や動きだけで意味を伝えない。G:3-3）。台本の書き方のきまりとしてガイドに書く。

### 12-3. 台本のテキスト形式

マークダウンのような文で書く（`src/story/scenes/<id>.md`）。くわしくはガイド。

```
# 四段の朝
id: pro-debut
bg: hall
cast: hanane momoka
summary: 4月1日、プロ棋士になった朝。……

: 4月1日。{name}は、将棋会館の前に立っていた。
羽音: おはよう。早いね。 [enter:right]
百花(wry): え、もう来てたの！ [!] [ぴょん]
[暗転] [bg:night]
: その夜。
```

- 頭の`# 題名`と`key: value`の行（`id`・`bg`・`cast`・`summary`・`voices`・`vars`・`start`）。
- 本文は1行1つ。`: 文`は地の文、`名前: 文`・`名前(表情): 文`は台詞。名前は表示の名前（羽音・百花）かid。
- `[...]`は演出。行の後ろに書くとその行、演出だけの行は次の行に付く。`名前:演出`はほかの人の演出。
- 選択肢は`- 答えの文 {値}`、その下に2つ下げた行で返しの台詞。
- `//`で始まる行は書き手のメモ（読まない）。

### 12-4. 検査（書きまちがいを教える）

`src/core/novel-direction.mjs`の`checkScene`と、台本の読み込み`src/core/novel-script.mjs`の`parseNovelScript`。まちがいは行の番号と直し方で返す。

- まちがい（error）：知らない人・知らない表情・知らない演出・知らない背景、castにいない人の登場、出ていない人の退場、`id`・題名・本文がない、選択肢の返しが空。
- 気をつけたいこと（warn）：羽音の敬語（です・ます・ください・ございます・お願いします・ありがとうございます）と「！」、1行が60字を超える（窓に3行で収まらない）、12行を超える（遊びを止めない。D:8-2。場面を分けることを勧める）、`{name}`・`{you}`・`vars`にない差し込み、あらすじがない。
- 組み込みの場面（団体戦・棋士の1年）と`src/story/scenes/`の台本は、自動テスト（`novel-library.test.mjs`）で全部検査する。まちがいがあると`npm test`が落ちる。
- 手で確かめるときは`npm run novel:check`（ファイルを指定してもよい）。

### 12-5. 試し読みのページ

`npm run novel-editor`で開く`novel-editor.html`（開発用。配布物には入らない。定跡エディターと同じ）。左に台本、右に検査の結果と演出の早見表。「再生」でその台本を本物の`NovelScene.vue`で読む。「この行から」で途中から再生する。書いた台本は「コピー」でファイルへ写す（ページは保存しない。ブラウザに下書きだけ残す）。

### 12-6. 物語モードとのつなぎ

- `src/story/scenes/*.md`の台本は、`src/core/novel-library.mjs`が読み込む（Viteの`import.meta.glob`。使うときに読み、結果を覚える）。
- ストーリー選択のメインの話は、目録の行に`scene: '<台本のid>'`を書けば読めるようになる（`status: 'soon'`を消す）。第一話はいつでも、第二話からは前の話を読むと開く。サブの話は今までどおり。
- 組み込みの場面（`team-story.mjs`・`pro-year-story.mjs`）も、行に演出を書ける（`line(who, face, text, fx)`の4つめ）。いくつかの場面に動きを足した（誘いの百花のぴょん、優勝の大喜びなど）。

### 12-7. 置き場所

## 6. 後の候補

- 場面の回想（やこびノートに、見た場面を並べて読み直せる「思い出」。D:5-1）。物語モードを作るときに。
- 物語モードの背景の絵・BGM（素材ができたら）。文字の音とクリックの音は11章で作った。
- 文字の音の続き：人物ごとの音の形（羽音は信号、百花はタイプ、など）を台本で指定できるようにする。耳で聞いた感想を聞いてから。
