# 盤を動かさない縦画面：やこび姫の欄と対局の札の高さを決める

スマホ縦・タブレット縦（縦積みの配置`--stack`）で、文の長さや札の出入りによって盤が大きくなったり小さくなったりし、押し間違えが起きていた。
盤の大きさと位置を、画面の大きさと対局の種類だけで決め、対局中は動かさないようにする。

- 決めた日：2026-10-27（ユーザーの依頼「文章の内容の変化によって盤面が大きくなったり小さくなったりして、押し間違えが起こる。操作中にボタンなどの位置が変わったりするのは避けたい」）
- 対象：縦積みの配置（スマホ縦・タブレット縦）。横並び（`--side`）とPC（`--wide`）は、盤の大きさがもともと画面の大きさだけで決まるので、上の欄（対局の札）の行を決めることだけを合わせる。

## 0. 見立て（直す前に測ったこと）

390×844（スマホ縦）で、盤の枠の幅を測った（`layoutprobe.cjs`・`guidestates.cjs`。手を流し込んで状態を作る）。

| 場面 | 盤の幅 |
| --- | --- |
| 竜王戦の七番勝負・始め | 362px |
| 勝負メシの札が出た | 291px |
| 勝負メシの札＋長い助言 | 277px |
| 勝負メシを選んだ（札が消えた）・長い助言のまま | 348px |
| 短い助言に戻った | 362px |
| ふつうの対局・始め | 377px |
| 作戦（原始棒銀）を選んだ | 277px |
| 囲い（美濃）を選び、飛車の振り先を聞かれた | 234px |
| 作戦の提案が出た | 314px |

原因は2つ。

1. 縦積みの盤の段が「ほかの欄の残り（`minmax(0, 1fr)`）」で、やこび姫の台詞（4.4〜5.6em）・補助の欄（作戦カード・札・案内の文）・対局の札（戦型の行が途中で増える）の高さが変わるたびに、盤が伸び縮みしていた。盤の枠の形（`portrait`・`compact`）も、盤の段の大きさで選び直していた。
2. 補助の欄の中身が、スマホ縦でもPCと同じ大きさだった（作戦カード244px、飛車の振り先300px）。

## 1. 機能設計メモ

### 機能名：盤を動かさない縦画面

- 目的（コンセプトとの関係）：押し間違えをなくす（迷わない・間違えない。D:2の1）。盤は画面でいちばん大きく、動かない主役にする（D:4-1）。
- 利用場面：スマホ縦・タブレット縦で対局するあいだずっと。とくに、札や助言が次々に出る大会の対局。
- 画面の主役：盤。
- 情報の優先順位：1 盤と駒 / 2 手番・直前の一手（盤の中） / 3 やこび姫の台詞と、いま答える札 / 4 対局の札（大会の名前・星・中継・相手） / 5 操作ボタン。
- 操作の流れ：変えない（盤を触る・札のボタンを押す）。
- 確認ダイアログ：なし。
- 使うメッセージ分類：変えない。
- 初めて使う人への伝え方：説明は足さない。盤が動かないこと自体が伝え方。
- 快の要素：なし（不快を除くだけ。D:2）。
- 見ている人への配慮：盤の大きさが変わらないので、のぞき込む人も見失わない（D:8）。
- 作らないと決めたこと：
  - 札を盤の上に重ねること（勝負メシや作戦の札は、選ばずに指し続けてよい。盤を隠すと指せない）。
  - 補助の欄を開いたり閉じたりするボタン（手数が増える。D:2の2）。
  - 盤を小さく固定して余白を残すこと（いつも盤が小さくなる。D:4-1）。
- 検証方法：上の表の場面を、直したあとに同じ手順で測り、盤の幅と位置が変わらないことを確かめる。3つの画面の大きさ（390×844・820×1180・1366×768）と、小さなスマホ（360×640）で見る。
- 根拠：U:7-5（1画面に収める・補足の文を省く）、U:7-2（盤は最大）、U:3-4（ボタンは盤と重ねない）、D:2（迷わない・間違えない）、N:3-3（遊びを止めない）。

## 2. 決めたこと

### 2-1. 縦積みは5段にし、盤の段は画面の幅で決める

```
見出し（手番・手数・図鑑・メニュー）   高さは決まっている
対局の札（大会の札・相手と戦型）       対局の種類ごとに行の数が決まっている
盤                                    画面の幅いっぱいのときの高さまで
やこび姫の欄（台詞と補助）              残り。最低の高さを取っておく
操作列（閃き・待った・表示補助）        高さは決まっている
```

- 盤の段は「盤を画面の幅いっぱいにしたときの高さ」（`--stack-board-max`。`useResponsiveLayout.ts`が画面の幅と縦横比で選ぶ盤の枠から出す）までしか伸びない。残りはやこび姫の欄へ回す。
- やこび姫の欄には最低の高さ（`--stack-dock-min`）を取っておく。盤はその分だけ先に引いた高さで決まるので、欄の中身がどう変わっても、盤の大きさと位置は変わらない。
- CSSのグリッドだけで決める：盤の段は`minmax(0, var(--stack-board-max))`、やこび姫の欄は`minmax(var(--stack-dock-min), 1fr)`。グリッドは、決まった上限のある段を先に伸ばし、残りを`fr`の段に渡す（CSS Grid 12.6・12.7）。
- 解析中（棋譜解析）は、盤の段を残り（`1fr`）のままにし、やこび姫の欄を決まった高さ（4.6em）にする。

### 2-2. やこび姫の欄は、台詞と補助を1つの入れ物に入れる

- 台詞（`shogi-game__coach`）と補助（`shogi-game__opening-guide`）を`shogi-game__dock`で包む。横並びとPCでは包みを`display: contents`にして、今までどおりグリッドに直接並べる。
- 縦積みでは、包みの中を縦の並びにする。補助は下に寄せて中身の高さ、台詞は残りの高さ。補助のボタンは欄の下にそろうので、台詞の長さが変わっても動かない。台詞が長いときは、台詞の中でスクロールする。
- 補助は一度に1つの種類だけ出す。いま答える札（勝負メシ・作戦の提案・作戦の中断・飛車の振り先・派生の選択・完全形まで続けるか）があるときは、作戦カード・「戦法・囲いを選ぶ」・案内の文をしまう。札があるあいだは、台詞を1行に縮め、やこび姫の顔をしまう。

### 2-3. 補助の中身をスマホ縦用に詰める

| もの | 縦積みでの形 |
| --- | --- |
| 作戦カード | 1行：小さな完成形・「戦法 ○○　囲い ○○」と「完成まで、あと○マス」・「完成形 ON」のボタン。「作戦を変える」はしまう（カードを押すと同じシートが開く） |
| 案内の文（「先に受けよう：▲6八金」など） | 1行。入りきらないところは「…」 |
| 札（勝負メシ・作戦の提案・中断・振り先） | 見出し1行（中断の理由は2行まで）と、ボタンを横1列 |

### 2-4. 対局の札の行を決めておく

- 戦型（先手・後手）の行は、決まる前から取っておく。決まるまでは「―」を薄く出す。
- 大会の札では、戦型を星取りの行（「◇ 防衛まであと4勝」）の右に入れる。星取りがない局でも、この行は取っておく。
- 縦積みでは、中継の勝率を相手の行に並べ（左に相手の顔と名前、右に中継）、相手の名前の前の「対」を省く。行を1つ減らす。
- 「2日目・まとめ」のボタンが出ても見出しの行の高さが変わらないよう、ボタンの高さを最初から取っておく。

## 6. どの大きさ・向きでも盤を主役にする（2026-11-13の依頼。見立て）

依頼：「スマホやPCで、ブラウザでプレイした時に縦横比が変わる。その時に表示が崩れるので直したい。また、スマホでプレイする時に盤が小さい。解析のときはもっと小さくて不便。小さい画面でも盤の大きさをなんとか保ちたい。」（ユーザーの写真：スマホ縦の棋士の1年の対局の解析。盤が画面の幅の半分ほど、下の操作の列が欄に重なり、対局の札に「Lv. undefined」）

読んだ指針：`UI_Nintendo_Design.md`（2 判断の優先順位、4-1 対局画面、9 チェックリスト）、`UI_Nintendo_Implementation.md`（3-4 操作ボタン、7-2 盤面、7-4 操作しやすさ、7-5 画面の大きさと向き、9 実装後のチェックリスト）、`UI_Nintendo.md`（2-5 必要なときだけ見せる、3-3 遊びを止めない）。

この作業環境のChromiumで、ビルドした`game.html`を開き、盤の段（`.shogi-game__board-shell`）の大きさを測った（自由対局の始め、投了して棋譜解析）。

| 画面 | 場面 | 盤の段（幅×高さ） | 盤の目の幅（見た目） |
| --- | --- | --- | --- |
| 390×760（スマホ縦・ブラウザの帯あり） | 対局 | 377×421 | 約316px（画面の81%） |
| 390×760 | 解析 | 377×246 | 約182px（47%） |
| 360×640 | 対局 | 348×342 | 約257px |
| 360×640 | 解析 | 348×162 | 約120px（33%） |
| 760×390（解析のまま横に回す） | 解析 | 380×374 | 右の列で、解析の欄（グラフ・手の選択・操作）とやこび姫の台詞が重なる |
| 700×768（PCの細い窓） | 対局 | 685×394 | 下の操作の列が横にはみ出し、「技の演出」「危ないマス」が画面の外 |

- 縦→横→縦と回したときの盤の大きさは、開き直したときと同じだった（自由対局の始めの局面）。崩れて見えるのは、**回した先の配置そのものが崩れている**ため（横向きの解析の重なり、細い窓の操作の列）。
- ただし、`useResponsiveLayout.ts`は盤の段（`boardShell`）の大きさの見張りを、部品をつけた最初の1回しか付けない。アプリはホームから始まり、対局の画面の盤の段はあとから出るので、盤の段だけが変わったとき（解析の欄の出入り・ブラウザの帯の出入り）に、盤の枠の形（`portrait`・`compact`）を選び直さない。回したあとに枠の形が古いまま残る見込みがある。
- 縦積みの解析は、やこび姫の欄を4.6emに縮めたかわりに、解析の欄（解析中の札・手の選択・つまみ・グラフ・凡例・操作の列）が約330pxを取り、盤の段が残りになる。
- スマホ縦の対局の盤が画面の81%なのは、盤の段の**高さ**が足りないため（盤の枠`portrait`は878×1168。幅377pxに広げるには高さ501pxが要る）。見出し（手番・手数・図鑑・メニュー）と対局の札（相手・戦型）で約110px、やこび姫の欄の最低の高さで約150pxを先に取っている。
- 写真の「Lv. undefined」は、棋士の1年の相手のLvを、竜王戦と同じ`ryuoOpponent.level`から読んでいるため（棋士の1年は`pending.level`）。見出しの「117手」が「完了して棋士の1年へ」のボタンに押されて切れている。

## 7. 機能設計メモ（UI_Nintendo_Design.mdの10章の形）

### 機能名：どの画面でも盤が主役

- 目的（コンセプトとの関係）：盤を画面でいちばん大きく、動かない主役にする（UD:4-1、U:7-2）。押し間違い・見間違いをなくす（UD:2の1）。
- 利用場面：スマホを縦・横に回す、ブラウザの帯が出入りする、PCで窓の大きさを変える。対局の途中でも、解析の途中でも。
- 画面の主役：盤。
- 情報の優先順位：対局は1 盤と駒 / 2 手番・直前の一手 / 3 やこび姫の台詞と、いま答える札 / 4 相手と大会の札 / 5 操作ボタン。解析は1 盤 / 2 いまの手と形勢（グラフ） / 3 手を進める・戻す操作 / 4 やこび姫の一言 / 5 そのほかの操作（手の一覧・検討・研究で開く）。
- 操作の流れ（手数）：変えない。解析で手を進める・戻すは今と同じく1回。盤を左右にはらっても1手ずつ進む・戻る（解析だけ。指で届きやすい場所でできる。U:7-4）。
- 確認ダイアログ：なし。
- 使うメッセージ分類：変えない。
- 初めて使う人への伝え方：説明は足さない。盤が大きく、動かないこと自体が伝え方。
- 快の要素：なし（不快を除くだけ。D:2）。
- 見ている人への配慮：盤が大きいと、横からのぞく人にも見える（UD:8）。
- 作らないと決めたこと：
  - 盤を拡大・縮小するつまみ（設定を増やさない。UD:1）。
  - 盤の上に解析の欄を重ねること（盤を隠すと見られない。U:3-4）。
  - 持ち駒の駒を盤の目より小さくすること（駒の字は離れても読める大きさに。U:7-2）。持ち駒の台は低くするが、駒の大きさは盤の目の8割を下回らない。
- 検証方法：8章の数を、直したあとに同じ手順で測る。6つの大きさ（U:7-5）と、大きさを順に変えていく流れ（縦→横→縦、帯あり→なし、PCの窓を細く→広く）で、開き直したときと同じ配置・同じ盤の大きさになることを、写真と自動の測定（盤の大きさ・はみ出し・重なり）で見る。
- 根拠：U:7-5（1画面に収める・並びを変える・タブで分ける）、U:7-2（盤は最大、スマホ縦は幅いっぱいに近づける）、U:3-4（ボタンは盤と重ねない）、U:7-4（44px）、N:2-5（必要なときだけ見せる）、N:3-3（遊びを止めない）。

## 8. 決めたこと

### 8-1. 大きさが変わっても崩れない（物差しを1つにする）

- 配置（`wide`・`side`・`stack`）と盤の枠の形は、ゲームの根（`gameRoot`）の大きさだけから、毎回はじめから計算し直す。前の配置の値を使わない。
- 盤の段の見張りは、盤の段が出たとき（`boardShell`が入ったとき）に付け直す。盤の段だけが変わったとき（解析の欄の出入り・ブラウザの帯）にも、枠の形を選び直す。
- 計算は1コマに1回にまとめる（`requestAnimationFrame`）。回している途中の何度もの変化で、盤が行ったり来たりしない。
- スマホのブラウザの帯の出入りでは、盤の大きさを変えない：縦積みの盤の上限は、帯が出ているときの高さ（`100svh`に当たる小さいほう）で決め、帯が引っ込んで増えた高さは、やこび姫の欄へ回す（2-1と同じ考え）。
- 横向き（`side`）の解析は、右の列を「上：解析の欄（つまみ・グラフ・操作）／下：やこび姫の一言（列の中でスクロール）」の2段にし、重ねない。
- PCの細い窓（幅900px未満の縦積み）で操作の列が入りきらないときは、表示補助の札を「表示補助」のボタンにまとめる（スマホと同じ形。入りきるかどうかは、ボタンの数と幅から決める）。
- 確かめを道具にする：`scripts/layout-resize-check.mjs`（新しく作る）。対局・解析・中継・棋士の1年の画面を、6つの大きさで開き直したときと、大きさを順に変えたときの両方で測り、盤の大きさ・配置の名前・はみ出し・重なり・画面の外のボタンを並べて、違えば知らせる。

### 8-2. スマホ縦の対局で、盤を幅いっぱいにする

| 変えるもの | 今 | 直したあと |
| --- | --- | --- |

### 8-3. スマホ縦の解析を「盤＋1つの帯」にする

解析中の下の欄を、次の1つの帯（約150px）にまとめる。盤の段は、見出しと帯と操作の列の残り。


- 手の選択（今の`<select>`）・凡例・「全体を確認」・「その他」は、真ん中の手のボタンを押すと開くシートへ入れる（いつも見るのは「いまの手」と「進む・戻る」だけ。N:2-5）。
- 盤を左右にはらうと1手戻る・進む（解析と振り返りのあいだだけ。対局中ははらっても何も起きない。駒を動かす操作とぶつからないよう、駒の上から始めたドラッグは今までどおり）。
- 390×760で、盤の目の幅は約182pxから約340px（87%）になる見込み。360×640では約120pxから約280pxになる見込み。
- 振り返り（「対局を振り返る」の段）も同じ帯に入れる。振り返りの問いの札は、帯の上に重ねて出し、盤には重ねない。

### 8-4. 小さな不具合

設計から変えたこと：

- 見出しと対局の札を1段にまとめる（8-2）のはやめ、対局の札を1行に詰めた。見出しの「あなたの番です」「考えています」「王手」は、盤の名札だけでは伝わりにくい（UD:4-1の4。状態表示は必要なときに文字でも）ため残した。それでも390×760で盤の目は95%になった。

- ブラウザの帯の出入りで盤を変えない（8-1）は作らなかった。対局の画面はページがスクロールしないので、帯はふつう出入りしない。回したとき・窓を変えたときは、開き直したときと同じ配置になることを道具で確かめた。
