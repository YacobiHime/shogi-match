# 戦法・囲いの判定を広げて正確にし、演出を付ける

## 1. 依頼（2026-11-20）

> 判定する戦法や囲いが少ない。精度も低かったりする。
> 銀冠穴熊やビッグ4など、将棋ウォーズや棋桜で判定されるものは判定できるようにしたい。
> エフェクトありで。
> まずは設計をして。

この文書は設計だけ。実装は11章の段階で、頼まれてから進める。

## 2. 今の作り（調べたこと）

### 2-1. 判定の流れ

1. `formation-tracker.mjs`の`detectFormationSnapshot`が、1つの局面ごとに次の2つで名前を付ける。
   - ひらがなすいしょうの判定式（`src/data/hiragana_suisho_formations.json`。tayayan/HiraganaSuishoの`tac_match.py`から写したもの、MIT）。140の規則。
     - 囲い61、戦法33、戦型8（相掛かり・横歩取りなど）、振り飛車の筋6、先手だけ17、後手だけ15。
   - 定跡補助の完成形（`opening-guide.mjs`の囲い32・戦法41の`completionSquares`）。
2. `updateFormationState`が局面ごとの結果をまとめる。
   - 囲いは毎回上書きする。
   - 戦法は1局のあいだ足していく。
3. 名前の使い道は次のとおり。
   - 対局の札の戦型の行（3つまで）。
   - コレクション（`matchFormationNames`）。
   - 技の演出（`move-waza.mjs`の`formationWaza`）。
   - 中継の解説、使用率、分身の得意戦法。

## 3. 機能設計メモ（Game_Nintendo_Design.mdの14章の形）

### 機能名：戦型の判定と演出の作り直し

- **一言で**：自分の組んだ形に、ウォーズで見るような名前が付き、珍しい形ほど派手に光る。集めたくなる。
- **解く課題**：次の3つを、1つの目録で一度に解く（D:2-5）。
  - 少ない（2-2のA・B）
  - 不正確（2-2のC・D・E）
  - 光らない・集まらない（2-2のA・F）
- **リスクとリターン**：
  - 珍しい囲い・戦法ほど組むのに手数がかかり、隙ができる（ビッグ4・四枚美濃・鬼殺し向かい飛車）。
  - 得るのは、★の高い演出とコレクションのカード（D:2-1）。
- **溜めと解放**：
  - 片美濃→本美濃→高美濃→銀冠と駒を足すたびに名前が「進化」し、上の形ほど大きく光る。
  - 穴熊も同じで、居飛車穴熊→松尾流穴熊→銀冠穴熊→ビッグ4（D:2-2）。
- **初めての人の最初の1分**：
  - 舟囲いや美濃囲いを組むと、帯と「はじめて！」が出る（★1〜2）。
  - 札の戦型の行に名前が残る（D:4-1）。
- **上級者の深さ**：
  - 囲い約50・戦法約110の目録。
  - ★4〜5の珍しい形（菊水矢倉・ビッグ4・天守閣美濃・UFO銀など）。
  - 進化の段、相手の珍しい形を見る楽しみ（D:2-4）。
- **失敗したとき**：
  - 判定は対局の勝ち負けに関係しない。崩されても、組んだ記録は残る（2-2のF。D:7-2）。
- **ご褒美と使い道**：
  - コレクションのカード（系統ごとのページ、★、はじめて組んだ日）。
  - 使用率・分身の得意戦法・中継の解説に、正しい名前で入る（D:5-1）。
- **ほめる瞬間**：
  - 組めた手そのもの。演出の強さは★で変える（D:5-4、G:3-1 重さの段階）。
  - 進化したら「進化！」。
- **捨てるもの**：次の5つは作らない。
  - 人物の絵の演出（ウォーズの夏目漱石など。模倣と権利を避け、系統の紋で見せる）。
  - ウォーズと同じ★の値・同じ名前の綴りへの完全な一致（一般の呼び方を正とし、ウォーズの綴りは別名で受ける）。
  - 手順そのものが名前の定跡（木村定跡・鷺宮定跡）のうち、局面の形で決めにくいもの（8-3）。
  - 手筋の追加（技の演出の18のまま）。
  - bioshogiのデータ。
- **確かめ方**：
  - 名前ごとの正解の束（9章）。
  - CPUの自己対局と図鑑の代表局で、出る名前の回数と出た手数を見る。
  - 実際に指して、演出がうるさくないか、うれしいかを見る。

### UI_Nintendo_Design.mdの10章の項目

- **目的**：組んだ形を名前で知り、覚えられる（強くなる道）。
- **利用場面**：対局中（自由対局・学習対局・大会）。中継の観戦。
- **画面の主役**：盤。演出は盤の上に重ねて、押せない（盤の操作を止めない）。
- **情報の優先順位**：次の順。
  1. 名前
  2. ★と系統
  3. 形を作る駒の光
  4. 進化の前の名前
  5. はじめて！
- **操作の流れ**：操作なし。盤を触ると消える。
- **確認ダイアログ**：なし。
- **メッセージ分類**：注目（UD:5-3）。
- **初めて使う人への伝え方**：形を作る駒が順に光るので、どの駒の形の名前かが文字なしで分かる。
- **快の要素**：段階ごとの和音（今の`wazaChime`を★1〜5に広げる）、紋の判子、進化の線。
- **見ている人への配慮**：相手の形も上の端の小さな帯で出す（観戦・中継でも見どころになる。D:8-3）。
- **作らないと決めたこと**：3章の「捨てるもの」と同じ。演出の長さを1.5秒より長くすること（U:6）。
- **検証方法**：9章。
- **根拠**：D:2-1、2-2、2-5、5-1、5-4、G:3-1、3-2、UD:5-3、7-2、U:6、U:8。

## 4. 決めたこと：目録（ひとつの正）

1. **戦型の目録を1つにする**（新しい`src/data/formation-catalog.mjs`）。
   - 判定・札の戦型の行・演出・コレクション・使用率・中継が、すべて同じ目録の`id`と名前を使う。
   - 作戦カードの目録（72）も、この目録の`id`を指す。
   - 別名の表（`FORMATION_LABEL_ALIASES`）は、目録の`aliases`に吸い込む。
2. **1つの項目が持つもの**（形は先手から見て書き、後手は反転する。戦法・囲いの案内の決まりと同じ）：
   - `id`・`name`（一般の呼び方）・`aliases`（ウォーズの綴りや前の版の名前。保存の移しかえにも使う）。
   - `kind`：囲い・戦法・戦型（相居飛車などの両者の形）。
   - `family`：系統。矢倉・美濃・銀冠・穴熊・雁木・舟・金無双・左美濃・ミレニアム・右玉・その他の囲い、居飛車急戦・居飛車持久・振り飛車・相振り・空中戦・奇襲。
   - `rarity`：★1〜5（5章）。
   - `parent`：進化のもとになる1つ前の名前。例は銀冠穴熊の`parent`が松尾流穴熊。
   - `shape`：自分の駒の条件。7章の語彙で書く。
   - `when`：手数の窓。
   - `opponent`：相手の条件。例は「相手が振り飛車」「相手が角道を止めた」。
   - `source`：形の出典。ひらがなすいしょう・定跡補助・自作。
3. **名前の数の目当て**：
   - 囲いはウォーズの42すべてと、矢倉穴熊・片銀冠・金銀冠・美濃熊・セメント囲い・左山囲いなど（約50）。
   - 戦法はウォーズの112のうち、盤の形で決められるもの（約100）。今の規則にあって、ウォーズにない名前（相掛かり横歩取らせ・角換わり37手目基本図など）は残す。
4. **作戦カードのない名前のカード**：
   - コレクションには入れる。完成形の小さな盤（`FormationThumb.vue`）と一言の説明を付ける。
   - 「この作戦で指す」は作戦カードのあるものだけにする。

| ★1 | 序盤によく出る、組むのが易しい | 舟囲い・片美濃・中住まい・ノーマル四間飛車・中飛車・棒銀 | 小さな帯（盤の上の端）0.9秒。止めなし |
| ★2 | 基本の完成形 | 本美濃・金矢倉・雁木・居飛車金無双・早繰り銀・腰掛け銀・石田流 | 帯（今の★）1.2秒。応手の止め0.4秒 |
| ★3 | 堅い形・名のある戦法 | 高美濃・居飛車穴熊・振り飛車穴熊・エルモ囲い・ゴキゲン中飛車・藤井システム・右四間飛車 | 帯＋形を作る駒が玉から外へ順に光る。1.35秒。止め0.6秒 |
| ★4 | 堅い完成形・プロの名のある形 | 銀冠・松尾流穴熊・銀冠穴熊・ミレニアム・菊水矢倉・ダイヤモンド美濃・升田式石田流・トマホーク | 金の帯＋系統の紋の判子＋駒の光。1.5秒。止め0.7秒 |

- 今の技の段階（★・★★・★★★）とは別の物差しにする。
  - 手筋は今のまま（銀・金・虹）。
  - 囲い・戦法は★1〜5の札にする。
  - 1つの手に技が重なったら、強さの比べ方は、★1〜2を★、★3〜4を★★、★5を★★★として今の`pickWaza`の順で選ぶ。
- ★の値は初期値。遊んでみて直したら、この表を直す（Game_Nintendo_Designの決まり）。

## 6. 決めたこと：演出の見せ方

1. **系統の紋**（SVG。人物の絵は使わない）。囲いの紋は次のとおり。
   - 矢倉：櫓
   - 美濃：扇
   - 銀冠：冠
   - 穴熊：熊の足あと
   - 雁木：雁の列
   - 舟：小舟
   - 金無双：金の双つの円
   - ミレニアム：千の字
   - 右玉・中住まい：家
   - その他：盾

   戦法の紋は次のとおり。
   - 居飛車急戦：稲妻
   - 居飛車持久：山
   - 振り飛車：筋の数字（四間なら「四」）
   - 相振り：向かい合う矢
   - 空中戦（横歩取り・相掛かり）：雲
   - 奇襲：手裏剣

   紋は帯の左に小さく、★4以上は帯の後ろに大きく薄く出す。
2. **形を作る駒が光る**：
   - 形の条件に当たった自分の駒のマスを、玉に近い順に（戦法は動いた駒から）0.06秒ずつ、白い縁と系統の色の輪で光らせる。
   - 黄色の面は使わない（盤の色の決まり。升の強調ではなく、駒の縁の光）。
   - 光は1回だけで、残さない。
3. **進化**：
   - 同じ系統で`parent`のつながる上の形ができたら、帯に前の名前を小さく消し線で出し、新しい名前に「進化！」の札を付ける。例は「高美濃 → 銀冠」。
   - 進化した形の★で演出する。
   - 1局で下の形に戻って、また上の形にしても、2回目からは小さい帯にする。
4. **はじめて！**：コレクションにまだない形は、今と同じく「はじめて！」の札を付け、少し長く出す。
5. **相手の形**：
   - 盤の上の端の小さな帯にする（朱の縁）。★4以上だけ紋を付ける。
   - 止めない。音は小さく。
6. **長さと止め**：
   - 合計1.5秒以内（U:6）。止めるのはCPUの応手の表示だけで、プレイヤーの入力は止めない（G:3-2）。
   - 盤を触ると打ち切る。
7. **演出の設定**：表示補助の「技の演出」を、次の3つにする（棋桜の簡易表示にならう）。
   - **全部**（はじめ）
   - **かんたん**（どの★も小さな帯だけ。駒の光と紋なし）
   - **なし**

   保存は今の`waza-effect:v1`に「かんたん」を足す。設定なのでデータリセットでは消さない。
8. **動きを減らす設定**（`prefers-reduced-motion`）では、帯の入りと光の広がりをなくし、色と音だけにする。
9. **出す場面**：今の技の演出と同じ（対CPUの対局。棋譜の検討・教室・問題集・二人で指す対局では出さない）。
   - 中継の観戦では、解説の欄に「▲先手 銀冠穴熊（★4）」の行を出す。盤の上は小さな帯だけ。

## 7. 決めたこと：判定の語彙と決まり

1. **形の条件**（`shape`）：
   - `own`：自分の駒がこのマスにある（全部）。
   - `ownAny`：どれか1つ。
   - `ownNot`：このマスに自分のこの駒がない（例：左美濃と銀冠の見分け）。
   - `empty`：空いている。
   - `oppAny` / `oppNot`：相手の駒の位置。
   - `king`：玉がこのマスのどれかにいる。囲いは**玉がその囲いの中にいるときだけ**付ける。今の規則は玉の位置を見ないものがある。
   - `rookFile`：飛車の筋（振り飛車の何間か）。
   - `hand`：持ち駒（角交換の有無）。
   - `path`：駒の通り道。例は早繰り銀の「銀が3七→4六」、棒銀の「銀が2七→2六か1五」。
     - 対局の手の記録から見る。
     - 局面だけの判定（中継の途中の局面・研究の局面編集）では、`path`のない形だけ見る。
2. **手数の窓**（`when`）：既定と、項目ごとに決める名前の例は次のとおり。
   - 戦法：60手目まで。
   - 囲い：100手目まで。
   - 奇襲・急戦：30手目まで（2手目3二飛・鬼殺し・新鬼殺しなど）。
   - 相手の条件のある名前（対振り持久戦・左美濃急戦など）：相手の飛車が振られてから。
3. **その手で完成**：
   - 名前は、その手で動いた駒（打った駒を含む）が形の条件に入っているときだけ新しく付ける。
   - 相手が駒を取って偶然できた形には付けない。
4. **いちばん具体的なもの**：
   - 同じ系統で当たった形が2つ以上あれば、条件の数が多いほうを1つ選ぶ。`parent`の子は親より先に選ぶ。
   - 定跡補助の完成形を先に勝たせる決まり（2-2のD）はやめる。補助の完成形は目録の形の1つとして入れる。
5. **組んだ記録と今の形を分ける**：
   - 対局の状態に、次の2つを持つ。
     - `formed`：1局で組んだ形。手数と、組んだときの形を残す。
     - `now`：今の囲い。札の戦型の行と中継に使う。
   - 演出とコレクションは`formed`に新しく入ったときだけ。
6. **先後**：
   - 形は先手で書き、後手は反転して同じ式で見る。

## 9. 精度の確かめ方

1. **名前ごとの正解の束**（`src/core/formation-catalog.test.mjs`）。名前ごとに次の局面を持つ。
   - **付く局面**：
     - 初めの配置から、その形を組む手順を指した局面。定跡補助に手順があればそれを使い、なければ手順を書く。
     - 先手と後手の両方で確かめる。
   - **付かない局面**：似ているが違う形を、少なくとも1つ。例は次のとおり。
     - 銀冠穴熊に対して、8七銀がない居飛車穴熊。
     - ビッグ4に対して、7七銀がない銀冠穴熊。
     - 玉が囲いの外にいる美濃。
   - **進化**：`parent`の局面から1手で子の局面になり、子の名前だけが出る。
2. **監査の道具**（`scripts/formation-audit.mjs`）：次の棋譜で、名前ごとの出た回数・はじめて出た手数・同じ局で同時に出た矛盾（居飛車と振り飛車の両方など）を出す。
   - CPUの自己対局（Lvを散らして100局ほど）。
   - 図鑑の代表局（`reference-kifu.mjs`）。
   - 中継の棋譜。

   手数の窓を過ぎてから出た名前、出すぎる名前（全局の半分以上）、一度も出ない名前を見直す。
3. **目当て**：
   - 正解の束はすべて通る。
   - 監査では、戦法が60手目より後に新しく付くことはない。
   - 図鑑の代表局で、戦型の名前（四間飛車・角換わりなど）が局の題と食い違わない。

## 15. F3の実装（2026-11-21、実装・自動テスト済み）

### 15-1. 作ったもの

- **戦法の規則の語彙**（`src/data/formation-rules.mjs`の`FORMATION_STRATEGY_RULES`）。囲いの語彙（`own`・`ownAny`・`ownNot`・`variants`）に、次を足した。
  - `opp`・`oppAny`：相手の駒。自分から見たマスで書く。
  - `oppRook`：相手の飛車の向き。
    - 相手から見て5〜9筋なら振り飛車（`ranging`）。
    - 1〜4筋なら居飛車（`static`）。
  - `visited`：1局のうちに、自分のその駒がそのマスにいたことがある（駒の通り道）。
  - `battle`：戦型（相掛かり・矢倉など）。
  - `maxPly`：その名前を付ける手数の上限。
  - 判定は`formation-catalog.mjs`の`strategyRuleMatches`。マスの札は`sideCells`・`turnCells`。
  - 局面ごとの判定に、両方の側の駒の札`cells`を足した（`detectFormationSnapshot`）。
  - 1局のまとめに、駒の通り道`visited`を足した（`updateFormationState`）。大駒・金・銀・桂と玉の、1局で一度でもいたマス。
- **足した戦法**（20）：
  - 脇システム・矢倉棒銀・矢倉中飛車・カニカニ銀
  - 相掛かり棒銀（戦型が相掛かりのとき）・5筋位取り・飯島流引き角戦法・ツノ銀雁木
