# やこび姫の作戦の助言（2026-10-23・設計）

対局の途中で、将棋AIの読みが「飛車を振る手」を強く勧めているとき、やこび姫が「右四間飛車にしたら？」のように、**手ではなく作戦の名前で**提案する。この文書は段階1（飛車を振る提案）の設計と、その先の段階の見通しをまとめる。

## 0. いまの助言と、足りないもの

いまの助言（`src/core/coach-advice.mjs`）は、次の3種類である。

| 種類 | 例 | 元になるもの |
| --- | --- | --- |
| 形勢 | 「良い出だしだね！」「まだまだやれるよ！」 | 最善手の評価値と手数 |
| 危険の知らせ | 「王手きたーっ！！」「何かあるよ、気を付けて！」「次に飛車を取られそうだね」 | 上位5手の評価の差・詰めろ・王手（`getCandidateRiskAdvice`） |
| 相手の戦型への対策 | 「相手は矢倉系だね。…右四間飛車の形で角筋を生かすのが狙い目だよ！」 | 相手の戦型の検出と、決まった台詞（`COUNTER_STRATEGY_TIPS`・`CASTLE_TIPS`） |

足りないのは、**「この局面で、何を目指すか」をAIの読みから言うこと**である。対策の台詞は戦型の一般論で、いまの局面でそれが良いかは見ていない。閃きは最善手を矢印で示すが、手の意味（なぜその手か、その先に何があるか）は伝えない。

作戦の助言は、AIの上位の候補手を**作戦の名前に翻訳**して、この2つの間を埋める。

## 1. 機能設計メモ

### 機能名：作戦の助言（段階1：飛車を振る）

- **一言で**：AIが飛車を振る手を強く勧める局面で、やこび姫が「ここで右四間飛車にしたら？」と作戦の名前で提案する。乗るか、自分の作戦を続けるかはプレイヤーが決める。
- **解く課題**（2-5。1つの仕組みで次の3つを解く）
  1. 閃きの矢印は「どこへ動かすか」しか伝えず、意味が残らない。作戦の名前で言えば、図鑑・教室で覚えた形とつながる。
  2. 作戦カードは対局の始めに選ぶもので、途中の局面に合わせて選び直す機会がない。
  3. 対策の台詞は一般論で、いまの局面で本当に良いかを見ていない。AIの読みと合わせると、台詞に裏付けが付く。
- **リスクとリターン**（2-1）：提案に乗ると、AIが良いと読んだ形に向かえて、作戦カードの矢印と薄い駒で手順も分かる。その代わり、自分で選んだ作戦は捨てることになる。乗らなくても損はない（提案は命令ではない）。
- **溜めと解放**（2-2）：序盤から中盤の入り口で、どう指すか迷っている時間が溜め。提案の札が出て、乗って組み上がると、作戦カードの欄に「完成！」が付く（今の表示）ところで解放される。戦法の完成を盤の上に大きく出す知らせは今は囲いだけなので、戦法にも広げるかは段階1の確かめ方（§7）で様子を見て決める。
- **初めての人の最初の1分**（3-3, 4-1）：台詞を読み、札の「右四間飛車にする」を押すと、盤に矢印と薄い駒が出て、飛車を動かすだけで始まる。作戦の名前を知らなくても、押せば形が見える。
- **上級者の深さ**（2-4）：提案は評価の差がはっきりしたときだけ出す。上級者には「AIはここで振るのか」という気づきになる。詳しい理由は図鑑で確かめられる（対局中の図鑑、`docs/match-dex-design.md`）。
- **失敗したとき**（7-1）：乗ってうまくいかなくても、作戦カードはいつでも選び直せる。中断したときの「作戦を変えよう」の札も今までどおり出る。
- **ご褒美と使い道**（5-1）：提案に乗って組んだ戦法は、コレクションの印になる（今の仕組みのまま）。まだ使えない段の戦法でも、提案されたものはその場で使えるようになる（戦法占いと同じ。§4の決めること2）。
- **ほめる瞬間**（5-4）：提案のあと、プレイヤーが飛車を振ったら（札を押しても、自分で指しても）、次の台詞で「右四間飛車だね！ 4筋から角の頭を狙っていこう」と、何が良いかを添えてほめる（5-8、情報としての称賛）。
- **捨てるもの**：
  - 評価値の数字を台詞に出すこと（§4の決めること3）。
  - 「応援のみ」での作戦の助言（1手しか読まないので、差が分からない）。
  - 段階1での、囲い・仕掛け・端攻めの提案（§6の段階2以降）。
  - 中盤以降（浮き飛車の横への移動、横歩取りの飛車の動き）の提案。段階1は自陣の段にいる飛車だけを見る。
- **確かめ方**（10-2）：§7。

## 2. いつ出すか（判定）

新しい純粋な処理`src/core/coach-plan-advice.mjs`の`planAdvice()`で判定する。対局画面から呼び、テストで確かめる。

### 2-1. 入力

- 上位の候補手（`rank`・`move`・プレイヤーから見た`score`）。**詳しい助言で今すでに読んでいる上位5手（`updateDedicatedCoachAdvice`の`multiPv: 5`）をそのまま使い、新しい探索は足さない**（`AGENTS.md`のCPUの項。同じエンジンで探索を積まない）。
- 局面のSFEN、プレイヤーの色、手数。
- いま選んでいる作戦カード（`selectedStrategy`）。
- 相手の戦型（今の`opponentFormations`）。
- この対局で出した助言の記録（今の`advisedCoachTopics`）。

### 2-2. 飛車を振る手の見分け方

候補手が次をすべて満たすとき、「飛車を振る手」とする。

- プレイヤーの成っていない飛車が、**自陣の飛車の段**（先手なら8段目、後手なら2段目）で、横に動く手。
- 動かす前の筋が、初めの筋（先手なら2筋）か、もう振った筋。
- 行き先の筋が、下の表にある。

行き先の筋（プレイヤーから見た筋。後手は反転する）と作戦：

| 行き先 | 作戦 | 作戦カード |
| --- | --- | --- |
| 3筋（初めの筋から） | 袖飛車 | `sodebisha` |
| 4筋（初めの筋から） | 右四間飛車 | `right-shiken` |
| 5筋 | 中飛車 | `nakabisha` |
| 6筋 | 四間飛車 | `shiken` |
| 7筋 | 三間飛車 | `sangen` |
| 8筋 | 向かい飛車 | `mukai` |

- 振った筋からもう一度動かす手（四間飛車から向かい飛車へ、など）は「振り直し」として、行き先の作戦で言う（「向かい飛車に振り直したら？」）。
- 初めの筋へ戻す手と、1筋・9筋は段階1では扱わない。

### 2-3. 「評価値が高い」の条件（初期値）

次をすべて満たすときだけ出す。

1. 飛車を振る手が**AIの最善手（1位）**である。
2. 飛車を振る手を除いた候補のうち最も良い手より、**80点（`PLAN_SWING_MARGIN`）以上**良い。差がない局面では、振っても振らなくても同じなので言わない。
3. 形勢が大きく傾いていない。最善手の評価が−1500〜＋1500の範囲（大差では方針より目の前の手が大事なため）。
4. 手数が60手目まで（序盤から中盤の入り口）。
5. 王手されていない。詰めろもない（危険の知らせが先）。
6. いま選んでいる作戦カードが、その作戦ではない（同じなら作戦カードの矢印が案内している）。
7. この対局で、同じ作戦の提案をまだしていない（`advisedTopics`に`plan-<作戦のid>`がない）。作戦の助言は1局に2回まで。

数値は初期値で、§7の測り方で調整し、この表を直す。

### 2-4. ほかの助言との順番

1つの局面で出す台詞は1つ（今の`showCoachAdvice`のまま）。上から先に出す。

1. 詰み・王手・詰めろ・評価の崖（今の`getCandidateRiskAdvice`の前半）
2. 指した手が悪手だったとき（今の`getMoveFeedback`）
3. **作戦の助言（新しく足す）**
4. 飛車が取られそう・守った方が良い、など（今の`getCandidateRiskAdvice`の後半）
5. 相手の戦型への対策（今の`formationAdvice`）
6. 形勢の一言

作戦の助言を相手の戦型への対策より先にするのは、いまの局面の読みに裏付けがあるからである。

## 3. 何を言うか（台詞）

主題（作戦の名前）を先に、理由を1つだけ添える（`UI_Nintendo_Implementation.md` 4章）。提案の形（「〜したら？」）にし、命令しない（6-3 攻略の自由、5-8 自律）。

```text
ここで右四間飛車にしたら？ 相手の矢倉の正面を、4筋から攻められるよ！
```

理由は、次の順で最初に見つかった1つを使う。

1. **相手の戦型との相性**：その作戦が、相手の戦型への対策の台詞（`COUNTER_STRATEGY_TIPS`・`CASTLE_TIPS`）で勧められているとき。例：相手が矢倉 → 右四間飛車。
2. **作戦のねらい**：`src/core/opening-explanations.mjs`のその作戦の`aim`。例：中飛車 →「5筋の位を取って、中央から攻めること！」を「中央から攻められるよ！」に言い換える。
3. **AIの読み**：上の2つがないとき。「AIの読みでも、いちばんの手だよ！」

振り直しのときは「向かい飛車に振り直したら？」のように言う。提案のあとに飛車を振ったら、次の手番で「右四間飛車だね！」とほめる（§1のほめる瞬間）。

台詞は`coach-plan-advice.mjs`にまとめ、テストで文を確かめる。

## 4. 画面と操作

- 台詞はいつものやこび姫の吹き出しに出す。
- 吹き出しの下に、中断のときの「作戦を変えよう」の札（`planInterruption`）と同じ形の札を出す。

```text
作戦の提案  右四間飛車
[右四間飛車にする]  [このまま指す]
```

- 「右四間飛車にする」：作戦カードにその戦法を入れる（今の`applyPlan`）。盤に作戦カードの矢印と薄い駒が出て、最初の一手（飛車を振る手）から案内する。閃きの回数は使わない（作戦カードを選ぶのと同じ扱い）。
- 「このまま指す」：札を閉じる。同じ作戦はこの対局でもう提案しない。
- 駒を動かしたら札は閉じる。確認ダイアログは出さない（取り消せる操作のため。`UI_Nintendo_Design.md` 5-2）。
- 札のボタンは高さ44px以上。スマホ縦では吹き出しと操作列のあいだに置き、盤を縮めない。

## 5. 対象の対局

- 「やこび姫の助言」が「詳しい助言」のとき（既定）。応援のみ・なしでは出さない。
- 通常対局・学習対局・竜王戦・名人戦・教室の対局。棋力測定は助言がないので出ない。
- 二人で指すときと、検討中（感想戦を含む）は出さない。

## 6. この先の段階（見通し）

段階1で、「AIの候補手を作戦の名前に翻訳して提案する」仕組み（判定・台詞・札・作戦カードへの反映）を作る。段階2以降は、翻訳の種類を足すだけで広げられる。

| 段階 | 提案 | 見分け方の元 |
| --- | --- | --- |
| 1 | 飛車を振る（右四間・袖・中・四間・三間・向かい） | 飛車の横の動き（§2-2） |
| 2 | 囲う（「先に美濃囲いに組もう」） | 最善手が玉・金・銀の手で、`nearestOpeningCastles`の距離を縮める |
| 3 | 仕掛ける（「今が仕掛けどき。3筋の歩を突こう」）・端攻め | 最善手が歩を突く手で、その手だけが他より大きく良い |
| 4 | 振り返りで言う（「ここで右四間飛車にできたよ」） | 棋譜解析の候補手に同じ判定を使う（`useGuidedReview.ts`） |

## 7. 確かめ方

- **純粋な処理のテスト**（`coach-plan-advice.test.mjs`）：
  - 先手・後手の反転
  - 筋と作戦の対応
  - 差が80点未満では出さない
  - 選んでいる作戦と同じなら出さない
  - 1局に同じ作戦は1回・合わせて2回まで
  - 王手・詰めろ・大差では出さない
  - 理由の選び方の順番
- **画面の回帰テスト**：詳しい助言の流れで、危険の知らせのあと・対策の台詞の前に判定していること、札の「にする」が`applyPlan`を呼ぶこと。
- **出る回数を測る**：将棋界図鑑の代表局と、CPUどうしの対局の序盤（60手まで）で、各局面の上位5手を今の助言と同じ読みの量で読み、条件を満たす局面の数を数えるスクリプトを`scripts/`に置く。**1局に0〜1回**くらいを目安に、80点の差を調整する。多すぎるとうるさく、少なすぎると出会わない。
- **ブラウザ**：条件を満たす局面から始めた対局（相手が矢倉で、右四間飛車が最善の局面など）で、390×844・820×1180・1366×768の3つで、台詞と札が出ること、「にする」で矢印と薄い駒が出ること、「このまま」で閉じることを確かめる。
- **人に触ってもらう**：将棋を少し知っている人に詳しい助言で1局指してもらい、提案を読んだか、押したか、押したあと迷わず飛車を動かせたかを後ろから見る（10-2）。

## 8. 決めること（実装の前に）

1. **札のボタン**：台詞だけにするか、「右四間飛車にする」の札も出すか。おすすめは**札も出す**。押すだけで作戦カードの案内につながり、言葉だけで終わらないため。
2. **まだ使えない作戦**：段で鍵のかかった作戦（右四間飛車は応用の段）を提案したとき、その場で使えるようにするか。おすすめは**使えるようにする**。戦法占いと同じ扱いにする。AIが勧める局面に出会ったことが、その作戦を覚えるいちばん良いきっかけになるため。
3. **評価値の数字**：台詞に「＋120」などを出すか。おすすめは**出さない**。初心者には数字より理由のほうが伝わる（5-5）。数字が見たい人は棋譜解析で見られる。
4. **段階1の範囲**：飛車を振る6つの作戦と、振り直しまででよいか。
