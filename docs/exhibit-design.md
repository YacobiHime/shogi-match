# 展示用パッケージと「最初から」（2026-10-20）

依頼: 学校の展示で、WindowsのPC（Chromeあり）で遊べるようにしたい。校内LANでは公開版のサイトに接続できない。展示用に「最初から」ボタンを付けたい。

読んだ指針: `Game_Nintendo_Design.md`（3-3 遅さは罪、4-1 初心者にはやさしく、9-1 いただく時間）、`UI_Nintendo_Design.md`（3-2 導線のルールの展示用の項、5-2 確認ダイアログ、8 対局者以外への配慮）、`UI_Nintendo_Implementation.md`（3-1 確認ダイアログ、9章のチェックリストの「展示」）。

## 1. 機能設計メモ（Game_Nintendo_Design.mdの14章の形）

- **一言で**：USBで運んだフォルダーのbatを押すと、インターネットなしで、公開版と同じ将棋（エンジン・助言・棋譜解析も）が全画面で始まる。来場者が替わったら「最初から」で、はじめての状態に戻す。
- **解く課題**：校内LANでは公開版に届かない／HTMLを直接開くとエンジンが動かない（COOP/COEPのヘッダーが要る）／来場者ごとに前の人の成績や進み具合が残る、を同時に解く。
- **リスクとリターン**：なし（運用の仕組み）。
- **初めての人の最初の1分**：来場者は、はじめての案内（将棋をどのくらい知っているか）から始まる。前の人の記録は見えない。
- **失敗したとき**：「最初から」を押し間違えても、確認で「やめる」に最初のフォーカスがある。
- **捨てるもの**：HTML 1枚にまとめる方式（エンジンが動かない）。放置したらホームへ戻る仕組み（依頼にない。9章のチェックリストの「展示」の1つ目は、まだ満たしていない）。Python・Node.jsなどを入れる必要のある起動方法。
- **確かめ方**：展示に使うPCで、start.batから遊び、「最初から」を押して、次の人の状態に戻ることを見る（実機での確認はユーザーが行う）。

## 2. 「最初から」（展示モード）

- Custom Elementの属性`exhibit`（`game.html`では`?exhibit=1`）を付けたときだけ、タイトル画面の左下に「データリセット」を出す。遊びの入口と競わないよう小さく置く（タップ領域は約50px）。
- 押すと確認を出す。取り消せない操作なので、確認を出す（`UI_Nintendo_Design.md`5-2の「学習の進み具合をリセット」に当たる）。
  - 「記録を消して、最初からにします。」／「成績・教室の進み具合・竜王戦・中断した対局が消えます。音と盤・駒の見た目は残ります。」
  - ボタンは「最初からにする」「やめる」。最初のフォーカスは「やめる」。背景を押す・Esc・ブラウザの戻るは「やめる」。ボタンの並びは、アプリのほかの確認（投了・中断した対局）と同じにした（実行が左、やめるが右）。`UI_Nintendo_Implementation.md`3-1の「実行は右」とは逆だが、アプリの中でそろえることを優先した。
- 「最初からにする」で、このゲームの保存（`yacobihime:shogi-match:`・`shogi-match:`・`shogi-match-`・`shogiMatch`で始まる鍵）を`localStorage`と`sessionStorage`から消し、ページを読み直す。展示する人の設定（音、盤・駒の見た目）は残す（`src/core/exhibit-reset.mjs`の`EXHIBIT_KEEP_KEYS`）。
- はじめての案内（`welcome.mjs`）は、残した設定を「遊んだ記録」に数えない。消したあと、次の来場者には案内が出る。前は、盤・駒の見た目を変えただけの端末も「遊んだことのある人」として案内を出さなかったが、設定だけで記録のない端末には案内を出すように変えた（`welcome.test.mjs`）。
- 確認は閉じずに読み直す。閉じると、ブラウザの戻る操作の見張り（`useBackNavigation`）を外す`history.back()`が走り、読み直しが取り消されるため。

## 3. 展示用パッケージ（Windows・Chrome・インターネット不要）

`npm run build:exhibit`（`build:hosting`のあとに`scripts/build-exhibit.mjs`）で、`exhibit/shogi-match-exhibit/`と`exhibit/shogi-match-exhibit.zip`を作る（生成物。gitに入れない）。

| ファイル | 中身 |
|---|---|
| `app/` | 公開版（`firebase-public/`）と同じ中身 |
| `server.ps1` | PowerShell（Windows 5.1以上）のローカルサーバー。`127.0.0.1`だけで待ち（ほかのPCからは見えない）、`app/`を配信する。将棋エンジンのために、COOP/COEP/CORPのヘッダーを付ける。`app/`の外は配信しない。ポート8765から空いているポートを使う。HTTP.sysを使わない（`TcpListener`）ので、管理者の権限が要らない |
| `start.bat` | サーバーを起動し、Chromeを全画面（キオスク表示）で開く。Alt+F4で閉じる |
| `start-window.bat` | サーバーを起動し、Chromeをふつうの窓（アプリの窓）で開く。準備・確認用 |
| `README.txt` | 準備・始め方・来場者の替え方・終わり方・動かないとき（日本語、UTF-8のBOM付き） |

- Chromeは、ふだんの記録とは別の場所（`%LOCALAPPDATA%\shogi-match-exhibit`）で開く。ふだんのChromeと記録が混ざらず、すでにChromeが開いていても全画面で開ける。
- 展示用のChromeが閉じたら、サーバーも止まる（起動から30秒後から、5秒ごとに確かめる。確かめられないときは、黒い画面を閉じるまで動く）。
- Chromeが見つからなければ、ふだんのブラウザで開く。
- batとPowerShellの文は、Windowsの文字コードの違いで壊れないよう、batは英数字だけ、`server.ps1`はUTF-8のBOM付きにする。改行はCRLF。

## 4. 確かめたこと

- 自動テスト（`exhibit-reset.test.mjs`）: 記録を消し、設定とほかのサイトの保存を残すこと、消したあとにはじめての案内が出ること、鍵の見分け、保存が使えなくても止まらないこと。
- PowerShell 7（Linux）で`server.ps1 -NoBrowser`を動かし、ヘッドレスChromeで、`crossOriginIsolated`が真になり、Lv21のCPU（将棋エンジン）が指すこと、wasmの種類（`application/wasm`）、`app/`の外（`/../`・`%2e%2e`）が404、GET以外が405になることを確かめた。
- 同じ環境で、`?exhibit=1`のときだけ「最初から」が出ること、確認の最初のフォーカスが「やめる」で、Escで閉じること、「最初からにする」で記録が消えて読み直し、はじめての案内が出ることを、1366×768・1920×1080・1280×1024で確かめた。
- Windows PowerShell 5.1とWindowsのChromeでの起動（batとChromeのキオスク表示）は、ここでは確かめられていない。展示の前に、実際のPCで確かめる必要がある。学校のPCでPowerShellのスクリプトが止められている場合は動かない（README.txtの「動かないとき」）。
- 実装後のチェックリスト（`UI_Nintendo_Implementation.md`9章）: 確認は「学習の進み具合のリセット」に当たる1つだけ足した。ボタンは動詞、最初のフォーカスは「やめる」。タップ領域は44px以上。フォーカスが見える。展示の「放置するとタイトルに戻る」はまだない（1章の捨てるもの）。

## 5. exe版（2026-10-23）

- Windows 10/11 x64用の単体exeを追加する。`npm run build:exhibit:exe`で`exhibit/shogi-match-exhibit.exe`と配布用の`shogi-match-exhibit-windows-x64.zip`を生成する。ビルドにはGo 1.22以上とzipコマンドが必要。GoコンパイラがPATHにない場合は`GO_BINARY`で指定する。npmの依存関係は増やさない。
- ゲーム資産をGoの`embed`で内蔵する。起動すると127.0.0.1:8765だけで配信し、ChromeまたはEdgeを展示用の別プロファイルで全画面表示する。ネット接続・Node.js・PowerShellは不要。ブラウザは展示PCにインストール済みのものを使う。
- ポートは記録の保存先を一定に保つため固定し、使用中なら理由をダイアログで表示する。ブラウザを閉じるとサーバーも終了する。`--window`で窓表示、`--no-browser`でサーバーのみ起動できる。
- タイトル左下に「データリセット」を置き、下端にボタンの余白を確保する。誤操作を防ぐため既存の確認と「やめる」への初期フォーカスを維持する。名前・成績・教室・大会・中断した対局を消し、音と盤・駒は残す。
- 指針：`Game_Nintendo_Design.md` 3-3・9-1（起動の手間を減らす）、`UI_Nintendo_Design.md` 3-2・5-2（主な入口と離し、取り消せない操作だけ確認）、`UI_Nintendo_Implementation.md` 7章（44px以上の操作領域）。
- 配布zipにはexe、説明書、ライセンス、ビルド時点のソースzipを含める。署名のないexeなので、展示PCの管理ポリシーによる実行制限は実機で確認する。

### exe版の検証結果

- GoのHTTPテスト：GET/HEAD、WASMのContent-Type、COOP/COEP、ディレクトリと範囲外のパスの404、POSTの405を確認。
- 同じ埋め込み資産・サーバーをLinux用にもビルドして起動し、ChromiumでWASM Workerの`usiok`・`readyok`（`ok: true`、`crossOriginIsolated: true`）を確認。
- 1366×768・390×844・820×1180で左下のボタンと44px以上の操作領域を確認。確認の初期フォーカスは「やめる」、Escで取り消し、実行後の記録消去と設定の保持、初回案内の再表示、通常版でのボタン非表示を確認。
- 全1,580テスト・型チェック・公開用ビルド成功。Windows x64のGUI実行形式を生成済み。Windows実機でのブラウザ起動・全画面・終了操作は未検証。
