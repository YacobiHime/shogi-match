# 棋力カルテ：棋力テスト・対局の場面採点・合わせ方（設計 2026-10-27）

依頼: 「誤差が大きすぎる（最大で±6くらい）。最善手からの差だけでなく、指し手の内容からも判断するべき。測定は対局に限るべきではない。棋力測定方法を考え直したい」。

決めたこと（ユーザー、2026-10-27）:
- 案A（棋力テスト）＋案B（対局の場面採点）＋案C（全部を合わせ続ける）＋案E（人で確かめる）で進める。
- 案D2（利用者の答えを、同意を取って匿名で集め、物差しを人で作り直す）は、Firebaseの無料プランで問題なく行えるなら行う。
- 確かめ（案E）に協力する（ユーザー自身の「五分のLv」は20）。

これまでの経緯（対局1〜3局での測定、序盤を数えない、実績を優先、レーティングの幅）は`docs/skill-measure-design.md`の1〜11章。

## 1. 誤差が大きい理由（11章までの方法の限界）

1. **材料が少ない**。1局の勝ち負けは1つの情報で、五分の相手と指しても±7Lvしか絞れない。指し手の損の平均も、30手で±7Lv。札（自己申告）＋1〜3局では、±3〜6Lvの外れが残る。
2. **差が出る場面を待っている**。中級の差は、1手で見える駒損や詰みの見逃しのような、まれな場面で出る（CPUで測ると、1手で見える大きな駒損はLv20で着手の約2%、Lv30で約0.7%。`docs/cpu-human-model-design.md`の2章）。1局に1回あるかどうか。
3. **物差しがCPU**。損の表も「1Lvの重さ」（Lvが1つ上がるとどれだけ勝ちにくいか）も、CPU同士で決めた。人では確かめていない。

## 2. 棋力の定義：総合と中身

- **総合**は今までどおり「このゲームのCPUと五分に指せるLv」（竜王戦・名人戦の難易度に使う。`docs/skill-measure-design.md`の11-2）。
- その総合を、1つの数字から推すのをやめ、**中身の力を別々に測って合わせる**。

| 力 | 中身 | 測る場所 |
|---|---|---|
| 見る | タダの駒を取る、取られそうな駒を守る、1手で見える駒損をしない | テスト・対局 |
| 読む | 手筋（両取り・叩きなど）で駒得する手、詰み | テスト・対局 |
| 受ける | 詰めろ・王手・攻めを防ぐ | テスト・対局 |
| 判断 | 落ち着いた局面で、いちばん良い方針の手を選ぶ | テスト（3択） |
| 勝ちきる | 実際の勝ち負け | 対局 |

- 力ごとの結果は、棋力テストの結果の札に出す（どこが弱いかが分かる。やこびノートの「能力」へつなぐのは次の段階）。

## 3. 全体の形（棋力カルテ）

```
札（自己申告の幅）  ─┐
棋力テスト（問題）  ─┼─→  合わせ方（ベイズ）  ─→  総合のLvと幅  ─→  レーティング・竜王戦の難易度
対局の場面採点      ─┤        ↑
CPUとの勝ち負け     ─┘   「その人のずれ」と「1Lvの重さ」は勝ち負けから学ぶ
```

- 勝ち負けは定義そのものなので、正とする。テストと場面採点は、「その人では勝ち負けとどれだけずれるか」の幅（個人のずれ）を持たせて入れる。勝ち負けが増えるほど、勝ち負けが効く。
- 測定は1回で終わりではない。テスト・対局のたびに材料が増え、幅が狭まる。

## 4. 案A：棋力テスト

### 4-1. 問題の種類

| 種類（力） | 問い | 答え方 | 材料 |
|---|---|---|---|
| take（見る） | タダか得になる駒を取ろう | 盤で指す | 自己対局から自動で作る |
| save（見る） | このままだと駒を取られちゃう！ いちばん良い手を指そう（逃げる・守るだけでなく、反撃が正解のこともある） | 盤で指す（良い手がいくつかあれば、どれでも正解） | 自己対局から自動で作る |
| tactic（読む） | 駒得できる手を見つけよう（手筋） | 盤で指す | 自己対局から自動で作る |
| mate（読む） | 詰ませよう（1・3・5・7手詰め） | 盤で指す（問題集と同じ判定。最後まで指す） | 問題集の詰将棋240問 |
| defend（受ける） | 詰めろを受けよう | 盤で指す（詰まない受けなら、どれでも正解） | 自己対局から自動で作る |
| judge（判断） | いちばん良い手はどれ？ | 3択（盤に矢印A・B・C） | 自己対局から自動で作る |

- 前例: 『将棋世界』の「昇段コース」は、3択の序盤・中盤・終盤の問題で段級位を認定している。Lichessの問題は、1回の挑戦を「問題との対局」として評価する（`Game_Nintendo_Design.md`の6-5）。

### 4-2. 問題の作り方（`scripts/build-skill-test-items.mjs`）

（2026-10-30に、10章の決め方（問いの約束を守る手を全部正解にする・手筋は名前の形で探す・二度読む）で作り直した。今の作り方は10-4〜10-6と10-11。下は最初の版の記録。）


1. いろいろなLv（10〜34）のCPUどうしで対局させ、局面を集める。弱いCPUどうしは数十手で大差になり、使える局面が少ないため、Lv10より上にする。
2. 審判のエンジン（6万nodes、MultiPV 8）で読み、問題になる局面を選ぶ。「何もしないとどうなるか」は、手番を渡した局面を相手側から読む（王手されていない局面だけ）。
   - take：駒を取る手が最善で、次善より300以上良く、取り合いの2手の読みで300以上の駒得。
   - save：何もしないと400以上損をし、取りの読みで300以上の駒を取られる。助ける手（最善から200以内）が5手以内。
   - tactic：すぐの駒取りではないが、最善の読み筋の5手先で300以上の駒得。次善より400以上良い。
   - defend：何もしないと9手以内で詰まされる。受け（最善から300以内で詰まない手）が5手以内。
   - judge：互角に近い（最善の評価値の絶対値が600以内）、取り合いの起きていない局面。最善手と、最善より200〜1000劣るが駒をタダで渡さない自然な手2つを、順を混ぜて並べる。最善と次善の差は120以上。
   - judgeの追加の読み（`--phase judge`）：上の条件では160局（約1万局面）から7問しか見つからなかった（落ち着いた局面では、上位8手が200以内に並ぶことが多い）。別の対局（seed 20261028）の局面から、判断だけを、読む手を12に増やし、最善と次善の差を問わず（選択肢に入れるのは最善より150〜1200劣る手だけ）、最善手が駒得の駒取りの局面と取られそうな駒がある局面（取り合いの2手の読み）を除いて探した（約2000局面で90問。1000局面あたり約40問）。`--phase calibrate --judge-file`で、元の7問と合わせて90問まで足した。
3. 同じ対局の近い局面（6手以内）は、似た問題になるので1つだけ。種類ごとに90問まで。
4. CPUの各Lv（1〜34の12段）に2回ずつ解かせ、正誤から「半分が解けるLv」（cpuB）を求める。詰将棋は初手を解かせる。

### 4-3. 難しさ（人に合わせる）

- CPUは人より読みが正確で、同じLvでも問題を解きやすい（序盤で人のほうが強く出たのと逆の向き）。cpuBのままだと、人の結果が低く出る。
- そこで、種類ごとに人に合わせた補正（`skill-test-bank.mjs`の`TYPE_OFFSETS`）を足して、問題の難しさbにする。初めの値は、詰将棋の手数の目安（1手詰め＝Lv8、3手詰め＝Lv16、5手詰め＝Lv24、7手詰め＝Lv30前後）とcpuBの差の中央値（`CPU_TO_HUMAN_OFFSET`）で、全部の種類で同じ値から始める。
- この補正は、確かめ（8章）と、集めた答え（7章）で直す。

### 4-4. 出し方と採点（`src/core/skill-test.mjs`）

- 正解の起こりやすさ: P(正解) = g + (1 − g − 0.05) / (1 + e^(−a(θ − b)))。aは1Lvあたり0.5、gは当て推量（3択は1/3、盤で指す問題は0）、0.05はうっかり。
- θ（テストで見た強さ）は、Lv0〜49の0.25刻みで起こりやすさを掛け合わせて求める。最初の目安は、札の幅か、今の棋力。
- 問題の選び方: 次は、今の推定で正解の見込みが6〜7割になる問題（ぴったり5割より、少しやさしい）。正答率5割は情報がいちばん多いが、外し続けると萎える（G:4-1）。少しの情報を手放して、続けたくなる難しさにする。
- 種類は順に回す（見る→読む→受ける→判断…）。全16問（見る4・読む4（手筋2・詰み2）・受ける4・判断4）。1問30〜60秒、全体で約10分（G:9-1）。
- 「わからない」で飛ばせる（不正解として数える）。時間は記録するが、採点には使わない。
- 結果: 総合のθと幅、力ごとのθ。力ごとの結果は、総合との差で出す（広い山の上で「その力の問題だけのθ」と「全部の問題のθ」の差を取り、問題の数nに対してn/(n+4)だけ残して、総合のθに足す）。札の幅は総合にだけ効くので、力ごとに出し直すと、全部の力が総合より低いようなちぐはぐな見え方になったため。4問なので幅が広い（「目安」と添える）。測った力が2つ以上で、いちばんの力に正解が1つ以上あるときだけ、いちばん良い力をほめる。結果の札では、力ごとの強さを、札に出す総合（棋力カルテの見立て）からの同じ差で並べる。

### 4-5. 画面（UIの機能設計メモ）

### 機能名：棋力テスト

- 目的（コンセプトとの関係）：竜王戦のちょうどいい難易度を、対局しなくても10分で決める。どの力が弱いかも分かる。
- 利用場面（誰が・いつ・どのくらいの時間）：はじめての案内で「少し指せる」「よく指している」を選んだ人、やこびノートの「棋力を測る」。約10分、16問。
- 画面の主役：盤（問題の局面）。
- 情報の優先順位（1〜5）：1. 盤 2. 問い（「タダの駒を取ろう」） 3. 進み具合（7/16の棒） 4. やこび姫の一言 5. 「わからない」「やめる」。
- 操作の流れ（手数）：札を選ぶ（1回）→ 盤で指す・3択を押す（1問1回）→ 結果の札で「竜王戦に出る」（1回）。
- 確認ダイアログ（有無・理由・初期フォーカス）：なし。やめても失うのは途中の答えだけで、すぐやり直せる（U:3-1の3種類に入らない）。
- 使うメッセージ分類：通常（問い・進み具合）、注目（正解の手を見せる）、特別（結果）。不正解は責めない（「答えは▲3四歩だったよ」）。
- 初めて使う人への伝え方（テキスト以外の方法）：問題集と同じ盤と操作。判断の3択は盤に矢印A・B・Cを描き、同じ色のボタンを並べる。
- 快の要素（音・動き）：答えたら、すぐ駒が動く。正解はふつうの駒音、まちがいは正解の手を緑の矢印で0.9秒見せて次へ（盤を触ると飛ばせる）。
- 見ている人への配慮：問いの1行と進み具合で、横から見ても何をしているか分かる。
- 作らないと決めたこと：時間の制限（焦らせる）。点数の表示（評価しない。U:4-3）。途中の正答率の表示。途中から再開する保存（10分なので、やり直せば足りる）。
- 検証方法：スマホ縦・タブレット縦・デスクトップで、札→16問→結果→竜王戦の入口までを通す。ユーザー（五分のLvが20）に受けてもらい、結果を比べる（7章）。
- 根拠（UI_Nintendo.md の章番号）：N:2-1（主役を大きく）、N:3-1（操作の手数）、N:3-4・3-5（確認と文言）、N:4-3（テキスト以外で伝える）、N:6-3（評価しない）。

### 機能名：棋力テスト（遊びの設計）

- 一言で：10分で、やこび姫が棋力と弱い力を見立てる。結果がそのまま竜王戦の難易度になる。
- 解く課題：対局1局では材料が少なく外れる／どこが弱いか分からない／測るのに対局が要る。
- リスクとリターン：なし（測定は評価ではなく目安。U:4-3）。
- 溜めと解放：進み具合の棒（16問）と、終わりの「あなたは5級くらい」の見立て。
- 初めての人の最初の1分：札を選ぶと、すぐ1問目の盤が出る。問いは1行。
- 上級者の深さ：正解すると問題が難しくなる。初段以上は7手詰め・深い手筋まで出る。
- 失敗したとき：外しても次はやさしくなる。答えの手を見せて、すぐ次へ（G:7-1）。
- ご褒美と使い道：竜王戦の難易度、力ごとの見立て。
- ほめる瞬間：結果の札で、いちばん良かった力を一言でほめる（「受けが強いね」）。
- 捨てるもの：対局しないと測れないこと、時間の制限、点数。
- 確かめ方：7章。
- 根拠：G:4-1（初心者にやさしく）、G:4-3（安全網）、G:4-10（作り手は基準にならない）、G:6-5（Lichessの問題の評価）、G:9-1（いただく時間）。

### 4-6. 生成の結果（2026-10-27）

（最初の版の記録。作り直した版の数は10-11。）


- 160局（約1万局面）から、take 90・save 90・tactic 90・defend 31・judge 7。judgeは追加の読みで90まで足した（4-2）。
- 詰将棋の手数ごとのcpuBの平均と目安: 1手詰め8.9（目安9.0）・3手詰め14.5（17.0）・5手詰め16.9（25.0）・7手詰め21.8（31.0）。CPUは初手だけを解くので、長い詰みほど人より楽に解く。差の中央値は3.7Lvで、これを補正の初めの値にした。
- 解かせたいちばん強いLv（34）でもほとんど解けなかった問題（cpuBが40以上）は出さない（`MAX_CPU_B`）。弱いLvだけが解けて強いLvが解けない、強さと関係のない問題も混じっていたため。除いたあと: take 88・save 81・tactic 70・defend 28・judge 68、詰将棋240。
- 種類ごとのbの平均: take 14.3・save 20.7・tactic 26.3・defend 20.4・judge 25.0・詰将棋20.5。場面採点の取れる駒・守るの難しさ（5章）は、これに合わせた。
- 問題の文: saveの正解は、逃げる・守るだけでなく反撃のこともあったので、「このままだと駒を取られちゃう！ いちばん良い手を指そう」にした（「助ける手」と言わない）。

## 5. 案B：対局の場面採点

- 1手ごとの損の平均をやめ、局面で起きた**場面**ごとに「できたか」を数える。場面は、解析の点（`analysisPointsFromResults`）と局面から決める（`src/core/play-content.mjs`）。

| 場面 | 起きたとき | できた |
|---|---|---|
| 取れる駒（見る） | 着手前の最善手が、タダか取り合いの2手の読みで300以上得になる駒取り | 指した手の損が300未満 |
| 守る（見る） | 相手に、こちらの駒をタダで取る手がある（手番を渡したら取られる） | 指した手の損が300未満 |
| 駒損をしない（見る） | 互角に近い局面での、すべての手 | 1手で見える駒損（取り合いの2手の読みで300以上損し、最善より300以上悪い）をしない |
| 詰み（読む） | 着手前の読みで、自分に7手以内の詰み | 詰みを逃さない |
| 受け（受ける） | 相手の詰めろを見つけるには、手番を渡した読みが要る（裏の解析には1局面に1回の読みしかない）。**v1では数えない**。受ける力はテストだけで測る | — |

- 場面ごとの難しさ（v1の値、`CONTENT_DIFFICULTY`）：取れる駒Lv14・守るLv20・駒損をしないLv4、詰みは詰将棋の手数の目安（1手Lv8・3手Lv16・5手Lv24・7手Lv30）。取れる駒・守るは、テストの同じ種類の問題の難しさの平均（4-6）に合わせた初めの値で、集めた答え（7-4）で直す。
- 形勢が大きく傾いた局面（評価値の差が1500以上）では、詰み以外の場面を数えない（勝ち負けに関係しない駒の出入りが多いため）。1局で場面が8つより少ないときは、中身のθを出さない。
- 1局の中身のθ（場面だけで出した強さ）と幅を、テストと同じ式（4-4）で求め、最近の対局（10局まで）を合わせる。
- 序盤（30手目まで）の「駒損をしない」は数える（定跡の知識ではなく、見る力の場面なので）。損の平均は使わない。
- 対象は、平手でレーティングに数える対局（自由対局・大会・測定の対局）。解析は、今の裏の解析（`usePlayInsightAnalysis.ts`）と大会の統計の解析の点を使う。

## 6. 案C：合わせ方（`src/core/skill-profile.mjs`）

### 6-1. 材料と重さ

| 材料 | 起こりやすさ | 重さ |
|---|---|---|
| CPUとの勝ち負け（レーティングの履歴、最大30局） | Elo式。1Lvの重さkは学ぶ（6-2） | 新しい対局ほど重く（1局さかのぼるごとに0.95倍）。大会の対局は0.7倍（棋士の棋風・特殊能力で、表のLvより強さがずれるため） |
| 棋力テスト（最近の3回） | テストのθ（平均m、幅s）に、個人のずれτ=3.5Lvを足した正規分布 | 複数回は合わせてから1つとして入れる（同じ人のずれは共通） |
| 場面採点（最近の10局） | 中身のθに、個人のずれτ=3Lvを足した正規分布 | 同上 |
| 札・自己申告の段級位 | 幅の中は同じ、外は裾（5Lv） | — |
| 何もないとき | 広い山（Lv15、幅12） | — |

- 個人のずれτは、「その人ではテストと勝ち負けがどれだけずれるか」の見込み。勝ち負けが少ないうちはテストが効き、勝ち負けが増えるとテストとのずれが勝ち負けで決まる（ずれを足した分布を掛け合わせると、自動でそうなる）。
- 推定のθの平均を総合のLv、標準偏差を幅にする。

### 6-2. 1Lvの重さを学ぶ

- 1Lvの重さkを、4つの候補（1Lvあたり0.35・0.45・0.65・0.9ロジット。Eloで約R60・R80・R110・R155）から、勝ち負けに合うものを重みで選ぶ（候補ごとの起こりやすさで平均する）。初めの重みは0.25・0.35・0.25・0.15。
- 勝ち負けが少ないうちは初めの重みのまま。違うLvの相手との勝ち負けが増えると、その人に合う重さに寄る。

### 6-3. レーティングへの反映

- 総合のLvと幅を、レーティング（R＝60×Lv−30）とその幅（60×幅）にして保存する。竜王戦・名人戦の難易度は、今までどおりレーティングから決まる。

### 7-1. 集めるもの・集めないもの

### 7-2. 同意

### 7-3. 送る条件と仕組み

### 10-2. 原因

1. **問いと採点のものさしが違う**。問いは人の言葉で約束する（「得する駒取り」「詰まない手」）。採点はエンジンの「最善手から○点以内」。約束どおりに指しても不正解になり、約束にない手（王手・反撃）が正解になる。
2. **種類を数字で決めている**。手筋は「すぐの駒取りではないが、読み筋の5手先で300以上の駒得」で選んだ。読み筋の途中の交換や、相手の受けの都合でも条件に当たるので、名前を言えない手が「手筋」になる。
3. **審判の読みが浅い**。落ち着いた局面の150〜200の差は、読みを深くすると入れ替わる。
4. **不正解のときに理由を見せない**。答えの手を見せるだけなので、自分の手のどこが悪かったのか分からない。1〜3と重なると、納得できない不正解になる（UD:6-1 失敗に納得できる難しさ、D:7-2）。

### 10-3. 直す原則

1. **問いは約束。約束を守った手は全部正解にする**（N:4-7 判定の幅：意図を汲む、D:12の1 将棋として正しいか）。正解の一覧は「約束を守る手のすべて」にする。
2. **人のものさしとエンジンのものさしが一致する局面だけを問題にする**。約束を守るのにエンジンでは大きく悪い手（罠）がある局面と、約束を守らないのにエンジンでは最善に近い手がある局面は、どちらで採点しても誰かが納得できない。そういう局面は問題にしない。問題は減るので、集める局面を増やして補う。
3. **手筋は名前で決める**。名前の付いた形（ふんどしの桂など。手筋図鑑か用語辞典に項目がある）に当たり、駒得や寄せがその形から生まれる局面だけを手筋の問題にする。名前は答えたあとに出す（問いに出すとヒントになる。D:6-5 Lichessのテーマ）。
4. **審判は二度読む**。見つけた問題は深く読み直し、答えと差が変わらないものだけを使う。
5. **答えのあとに理由を盤で見せる**。何もしないとどうなっていたか（取られる駒・詰み筋の1手目）と、手筋の名前（D:5-4 何が良かったかを伝えてほめる、UD:6-1）。

### 10-6. 問題の作り方（`scripts/build-skill-test-items.mjs`のv2）

1. **局面を増やす**。160局（約1万局面）から480局（約3万局面）へ。条件を厳しくすると、受けは今の半分、ほかの種類も減るため。
2. **種類ごとに探す**。手筋は形から探す。全部の局面の全部の合法手に盤だけの形の判定をかけ、形に当たる手がある局面だけをエンジンで読む（今は、エンジンの最善手を見てから、形を問わずに選んでいた）。
3. **約束を守る手の一覧は、全部の合法手を読んで作る**。一度に全部の手を読ませるとWASMのエンジンが止まったので、24手ずつ`searchMoves`で読む。詰まないかは、指したあとの局面を相手の側から読み直して確かめる。
4. **二度読み**。見つけた問題は40万nodesで読み直し、答えと、正解でない手との差（judgeは200、ほかは300）が変わらないものだけを残す。
5. **難しさ**は今と同じ（CPUの各Lvに2回ずつ解かせたcpuBと、`TYPE_OFFSETS`）。
6. **id**は`st2-<種類>-<番号>`にする。前の版の答え（匿名で集めた答え）と混ざらないように。`scripts/skill-data-report.mjs`は版ごとに分けて数える。
7. **データに足すもの**: `threat`（save・defend。相手の取る手・詰み筋の1手目）、`target`（save。取られそうな駒のマス）、`tesuji`（名前のid）、`line`（tactic・judge。答えからの読み筋3手）、`gap`（judge。2番目の選択肢との差）。
8. **数の目標**: 各種類60問以上（手筋は駒得40・寄せ20）。足りない種類は、判断の3択でしたのと同じく、別のseedの対局でその種類だけを探して足す。

### 10-8. 機能設計メモ

### 機能名：棋力テストの問題の見直し

- 一言で：問いの言葉どおりに指せば正解になる。手筋の問題は、名前の付いた手筋が出る。
- 解く課題：約束どおりの手が不正解になる（取る・守る・受ける）／手筋と言えない「手筋」（手筋）／読みの浅さで答えが揺れる（判断）／不正解の理由が分からない。
- リスクとリターン：変えない（測定は評価ではない。U:4-3）。
- 溜めと解放：答えたあとに、何が起きるところだったか（取られる駒・詰み筋）と手筋の名前が分かる。
- 初めての人の最初の1分：今と同じ。1問目の問いが、言葉どおりに採点される。

- ご褒美と使い道：手筋の名前（結果の札に並ぶ。手筋図鑑で読める）。棋力の見立ては今どおり竜王戦の難易度に。

- 捨てるもの：約束とエンジンが食い違う局面（問題が減っても使わない）。問いに手筋の名前を出すこと（ヒントになる）。図鑑へのリンク。垂れ歩・継ぎ歩（後の段階）。
