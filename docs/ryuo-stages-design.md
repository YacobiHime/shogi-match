# 竜王戦を3つの段階に分ける（設計・実装 2026-10-22、実装・自動テスト済み）

竜王戦の期の画面を、**① 組のトーナメント（ランキング戦）**・**② 組優勝者などのトーナメント（決勝トーナメント）**・**③ 番勝負（挑戦者決定三番勝負と七番勝負）** の3つの段階に分けて見せる。
見本は`docs/ryuo-stages/mock.html`（画像は同じフォルダの`mock-pc1.png`・`mock-pc2.png`・`mock-pc3.png`・`mock-phone.png`）。

設計の指針：UI_Nintendo_Design.mdの2章（迷わない・間違えないを最優先）・4章（重要度は大きさ・位置で表す）、UI_Nintendo_Implementation.mdの7-4・7-5（タブで分け、広い画面では、いつも見たいものを横に出す）、Game_Nintendo_Design.mdの2-2（溜めと解放）・5章（目標が見える）。

## 2. 3つの段階

| 段階 | 中身 | 主な見せ方 |
| --- | --- | --- |
| ① 組のトーナメント | その組のランキング戦。負けたあとの昇級者決定戦（1組は出場者決定戦）も、同じ組の中の戦いなので①に入れる | 試合の札の表（3章）。昇級者決定戦は①の中の切り替え |
| ② 決勝トーナメント | 各組の優勝者と1組・2組の上位（いまの規模の設定のまま） | 試合の札の表。名前に「1組優勝」「2組2位」の札、シードは「シード」と書く |
| ③ 番勝負 | 挑戦者決定三番勝負と、竜王との七番勝負 | 対戦の大きな札と星取り（4章） |

- 中身（制度・組み合わせ・昇級の決まり）は変えない。いまの段階（`season.phase`）を3つにまとめて見せるだけ：`ranking`・`revival` → ①、`main-setup`・`main` → ②、`playoff`・`finals` → ③。防衛戦（自分が竜王）は③から始まり、①②はほかの棋士の戦いを見るだけ（「挑戦者を待つ」）。
- 上の帯に、段階の道のり（①→②→③）を置く。終わった段階は緑の✓、いまの段階は琥珀色。押すと、その段階の表を見られる（まだの段階は、組み合わせの枠だけの下見。②なら「1組優勝」「6組優勝 ＝ あなた？」の枠）。いつか戦う相手と舞台が最初から見える（G:5、溜め）。
- 段階を越えたとき（組優勝・挑戦権）は、いまの節目の判子（`ryuo-milestone.mjs`）のあと、上の道のりの次の段階が光り、表が次の段階に替わる（解放）。

### 機能設計メモ（Game_Nintendo_Design.mdの14章）

- 一言で：竜王戦が「組の戦い → 選ばれた者の戦い → 竜王との番勝負」の3幕になり、いまどの幕にいるかが分かる。
- 解く課題：表が読めない／PCで空きが多く格好悪い／番勝負の星取りが見えない／全体のどこにいるか分からない。
- リスクとリターン：変えない（勝てば次の回戦、負ければ敗退・昇級者決定戦）。
- 溜めと解放：段階の中で回戦を上がる（溜め）→ 組優勝・挑戦権で次の段階が開く（解放）。③は1局ごとに星が1つ埋まる。
- 初めての人の最初の1分：上の①②③の道のり、真ん中に自分の組の表（自分の札は琥珀色、次の対局は朱色の「VS」）、右に次の相手と「対局する」。
- 上級者の深さ：まだの段階の下見、ほかの棋士の勝ち上がり、推しの棋士の札、昇級者決定戦の表。
- 失敗したとき：いまと同じ（負ければ昇級者決定戦へ、または期の結果へ）。
- ご褒美と使い道：段階を越えると、道のりに✓が付き、次の段階が開く。③では星取りが埋まる。
- ほめる瞬間：段階を越えたとき（いまの節目の判子と同じ重さ）。
- 捨てるもの：いまの木の図（`TournamentTree.vue`）の縦書きの葉。期の画面の表のタブ（ランキング戦／決勝トーナメント）は、段階の道のりに置き換える。
- 確かめ方：PC（1366×768・1920×1080）・タブレット縦・スマホ縦横で、①②③と防衛戦を撮る。初めての人に「いまどこ？」「次は誰？」を聞く。

## 3. 試合の札の表（①と②）

いまの木の図をやめ、スポーツの組み合わせ表のように、**1試合を1枚の札（2人を上下に並べる）**にして、左から右へ回戦の列を並べる（見本の`mock-pc1.png`・`mock-pc2.png`）。

- 札：上下に2人。各行に、勝ち負けの印（○は琥珀・●は灰）、名前（横書き。長いときは「…」）、段位。勝った人は太字、負けた人は薄く。
  - 自分の行は琥珀の地、次の相手の行は朱の地。次の対局の札は朱の縁と「VS」。推しの棋士は薄紫の「推し」、ライバル（羽音）は「ライバル」の札。
  - ②では、名前の前に「1組優勝」「2組2位」の小さな札を付ける。不戦勝（シード）は下の行を「シード」と書く。
  - まだ決まっていない行は「準々決勝の勝者」のように書く。
- 列：上に回戦の名前（1回戦・2回戦・準決勝・決勝。いまの回戦は琥珀）。列の見出しは表を縦に動かしても残す。
- 線：札の右から次の札へ、折れ線で結ぶ。自分が勝ち上がった線は琥珀で太く、ほかは灰（色は、いまの木の図の決まりと同じ：自分は琥珀、推しは薄紫、次の対局は朱）。
- 大きさ：PCは札の幅144px・列の幅160px（16名の表で4列＝640px）。32名以上は縦に動かす（枠の中だけ。U:7-5）。表は列の高さいっぱいに広げ、下を空けない。
- スマホ：列を横に並べ、横にすべらせて回戦を替える（列ごとに止まる）。開いたときは、いまの回戦が左に来る。下に、いま何列目かの点。
- 昇級者決定戦：①の見出しの横の「ランキング戦／昇級者決定戦」の切り替え（いまいる方を開く）。

## 4. 番勝負（③）

見本の`mock-pc3.png`・`mock-phone.png`（右）。

- 上に、挑戦者決定三番勝負の結果の1行（「ハル 2-0 田中一輝 ○○ 挑戦権獲得」）。三番勝負の最中は、三番勝負を大きく出し、七番勝負は「竜王 天鷺善彦が待つ」の1行。
- 真ん中に、対戦の大きな札：左に自分の駒「自」と名前（挑戦者・段位・次の局の先後）、右に相手の判子（竜王・冠の数）、真ん中に大きな「2-0」と「竜王まであと2勝」。VS画面（`RyuoVersus.vue`）と同じ、青（自分）と朱（相手）の斜めの地。
- その下に星取り：第1局〜第7局の札。終わった局は○●と「先手・終盤で逆転」（`game.how`と先後）、次の局は朱の縁で「次の対局」、まだの局は点線。決着がついて指さない局は消す。
- いちばん下に、この期の歩み：①②・三番勝負・七番勝負の勝敗を4枚の札に（下を空けない）。
- 「対局する」は「第3局を指す」にする（番勝負のときだけ）。

## 5. 画面の配置

### PC（幅1200px以上の横長）

- 上の帯を1本にする（56px）：「← 大会の選択へ」・竜の判子・「第2期 竜王戦」（下に推しの段）・段階の道のり（真ん中）・「予想」。
- その下を3列にする：**左 山の地図（330px）・真ん中 段階の表（残り全部）・右 次の一局（380px）**。
  - 山の地図は、3つの段階を麓（緑）・中腹（青）・頂上（金）の帯で塗り分け、帯の左上に「① 6組ランキング戦」などと書く。いまの段階の帯の名前は琥珀。
  - 真ん中は、見出し（「① 6組ランキング戦」と一言の説明）と、試合の札の表（3章）か番勝負（4章）。
  - 右の枠は上から詰める（真ん中に寄せない）：相手の役（「2回戦の相手」）・顔と名前と札・能力（レーダーチャートは軸の形を大きく、ランク8つ）・目標の1行・勝てば／負ければ・やこび姫の1行、「対局する」はいちばん下に固定。段階が変わっても「対局する」の位置は動かない。
- 1920×1080でも同じ3列。真ん中が広がるので、表の札の幅を広げる（最大200px）。

### タブレット・スマホ横（幅900〜1199px）

- いまと同じ2列（左に地図か表、右に次の一局）。地図と表の切り替えのタブは残し、表は選んだ段階のもの。

### スマホ縦

- 上の帯を2行にする：1行目は判子・期・推しの段・「予想」、2行目は段階の道のり（①6組・②決勝T・③番勝負の3つの札）。
- 真ん中は今までどおり「竜王への道／トーナメント表」の切り替え。表は3章のスマホの形。③では、表の代わりに番勝負（4章）を出す。
- 下の枠は今までどおり（相手と能力・勝てば／負ければ・「対局する」）。

## 6. 作り方（データ）

- 新しく`src/core/ryuo-stages.mjs`（画面に依存しない。テストできる）を作る。
  - `seasonStages(season)`：3つの段階の一覧（名前・状態：済み／いま／まだ・自分の勝敗）と、いまの段階の番号。
  - `matchBracket(season, bracket, labels)`：表を回戦ごとの試合の札の列にする（各試合：上下の2人・勝者・まだ決まっていない行の言葉・次の対局か・自分の道か）。いまの`bracketView`・`treeView`の情報（勝ち方・推し・ライバル）を引き継ぐ。
  - `previewMainBracket(season)`：決勝トーナメントがまだ決まっていないときの、枠だけの下見（「1組優勝」などの札と「？」）。
  - `seriesView(season)`：三番勝負と七番勝負の星取り（局ごとの勝者・先後・勝ち方、次の局、決着後に消す局）。
- `describeSeason`は`stages`・`brackets`・`series`を足す（いまの`tables`は名鑑などで使う間は残す）。
- 画面は、`src/RyuoBracket.vue`（試合の札の表。PCとスマホで同じ部品）と`src/RyuoSeries.vue`（番勝負）を新しく作り、`ShogiTournament.vue`の期の画面から使う。`TournamentTree.vue`は、ほかで使わなくなれば消す。

## 8. 決めたこと（2026-10-22、「おまかせ。①②はできるだけ現実の竜王戦に近く、でもゲームとしての面白さも大事に」）

1. 昇級者決定戦（敗者復活戦）は残し、①の中の切り替えにする。実物の竜王戦でも、ランキング戦で負けた棋士が昇級者決定戦で昇級を争う（1組は出場者決定戦）。負けてもまだ組の中に道があることが、①の表の上の切り替え（「ランキング戦／昇級者決定戦」）で見える。
2. ②の出場者は、実物と同じ「1組5名・2組2名・3〜6組の優勝者各1名」（規模の設定で縮めた形）のまま。上位の組ほどシードで勝ち数が少なく、6組優勝は1回戦から。これを面白さに変えるため、②の下見に「6組優勝なら、挑戦者決定三番勝負まで5勝」と、自分の枠からの勝ち数を出す（`winsToPlayoff`）。下の組から勝ち上がるほど長い道になる、という実物の魅力がそのまま目標になる（G:5）。
3. PCでは山の地図を左の細い列に残す（330pxまで）。地図は3つの段階の帯で塗り分け、いまの段階の名前を琥珀にする。表の幅を取りすぎないよう、列の幅を固定し、真ん中の表を残り全部にする。

## 9. 実装（2026-10-22）

- データ：`src/core/ryuo-stages.mjs`（`seasonStages`・`matchBracket`・`winsToPlayoff`・`seriesView`）。`ryuo.mjs`の`describeSeason`は`stages`（段階の一覧・①の表の一覧・②の表か下見・③の番勝負・いまの竜王・規模の決まり）を返す。②の下見は`previewMain`で、「1組優勝」などの枠と「？」で組み合わせを作る。循環を避けるため、`ryuo-stages.mjs`は`ryuo.mjs`を読まず、棋士の札と回戦の名前は関数で受け取る。
- 画面：
  - `src/RyuoBracket.vue`：試合の札の表。枠の大きさを測り、列の幅（168〜236px）は幅に合わせ、入りきらなければ横にすべらせる（列ごとに止まる）。札の間隔は高さいっぱいに広げる（下を空けない）。開いたとき・表が替わったときは、自分の次の試合（なければ最後の試合）の列まですべらせる。
  - `src/RyuoSeries.vue`：番勝負。前の番勝負の1行、対戦の大きな札と勝ち数、星取り（勝ち方は名鑑と同じ言葉）、この期の歩みの札。防衛戦では、自分を「竜王(防衛)」、相手を「挑戦者」にする。番勝負がまだないときは「竜王が頂上で待つ」。
  - `src/ShogiTournament.vue`：期の画面の上の帯を1本にし、段階の道のり（押すとその段階の表）を置く。段階を越えた直後は、次の段階の札を光らせる（動きを減らす設定では光らせない）。番勝負のときは「対局する」を「第N局を指す」にする。PC（幅1200px以上、縦横比4:3以上）は、地図・表・次の一局の3列。次の一局の枠は上から詰め、「対局する」をいちばん下に固定し、高さに余裕があれば相手の戦法の使用率の上位3つも出す。
  - `src/RyuoMountain.vue`：3つの段階の帯（麓・中腹・頂上）と段階の名前。地図が枠より背が低いときは、下に寄せる。
- 捨てたもの：`src/TournamentTree.vue`と`src/core/ryuo-tree-layout.mjs`（木の図）、期の画面の表のタブ（ランキング戦／決勝トーナメントなど）。名鑑の推しのために、`describeSeason`の`tables`は、ランキング戦・昇級者決定戦・決勝トーナメントの表だけ残す。
- テスト：`src/core/ryuo-stages.test.mjs`（段階の振り分け・防衛戦・敗退後・試合の札・シード・下見の勝ち数・番勝負の星取り）。
- 確かめたこと：Chromiumの自動操作で、PC（1366×768・1920×1080）の①②③、スマホ縦の①・②の下見・③、防衛戦を撮った。実機での手動確認は未実施。

## 10. PCの地図を真ん中の列の表の上へ（2026-10-22）

広い画面で、左の細い列の山の地図が小さく（防衛戦では2段だけで、列のほとんどが空）、見づらかった。「真ん中のブロックの下あたりに」との指示で表の下に置き、そのあと「上に置いた方が美しい」との指示で表の上に移した（山の空が上の帯に続いて見え、地面の上に表が載る）。

- PC（幅1200px以上、縦横比4:3以上）は2列にする：**左 横長の地図と、その下に段階の表・右 次の一局**。
- 地図は横長の図（`mountainLayoutWide`・`mountainLayersWide`、`RyuoMountain.vue`の`wide`）：左の麓の将棋会館から、右へ段を登って頂上の竜王の座へ。段は横に84ずつ並べ、少しずつ高くする。枠の大きさに合わせて縮め、送らない（U:7-5）。
  - 3つの段階は縦の帯で塗り分け、帯が名前より狭いときは短い名前（「② 決勝T」）にする。
  - 次の相手の顔は段の右上に置き、吹き出しは顔の上に出す。頂上のすぐ下の段では、金屏風と重ねないよう左上に置き、やこび姫を右に置く。
- 高さの配分：①②の表は高さを使うので、地図は上の帯（画面の高さの28%、12〜20rem）。③の番勝負は中身の高さだけにし（札と星取りの高さも控えめにする）、残りを地図に回す（最低12rem）。
- 狭い画面（タブレット・スマホ）は今までどおり縦長の図とタブ。
- 設計の指針：UI_Nintendo_Design.mdの2章（迷わない。いまどこかが一目で分かる地図を、小さくしない）、UI_Nintendo_Implementation.mdの7-5（1画面に収め、広い画面ではいつも見たいものを出す）。
