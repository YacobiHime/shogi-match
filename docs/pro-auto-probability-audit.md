# 分身の勝率表示と抽選の調査（2026-11-18）

**同日、表示と抽選をそろえる修正を実施。以下の調査本文は修正前の記録で、修正後の結果は末尾と設計27章を参照。**

対象：`1b95387`。依頼：「勝利確率61%なのに天鷺善彦に負け続ける。確率通りか、補正がないか調査」。ユーザーから「分身に任せる」の自動対局と確認済み。ゲームの勝敗処理は変更していない。

## 結論

**表示された61%を、そのまま勝敗の抽選には使っていない。** 表示は補正前のElo式で、抽選には相手の能力・特殊能力・先後などの補正が加わる。標準の善彦を相手に61%表示の条件を再現すると、抽選確率の平均は約52.64%、10万局の実測は52.595%だった。ユーザーの保存データそのものは未取得なので、個々の対局の正確な確率や連敗回数は断定しない。

## 表示と抽選の違い

- `src/core/pro-year.mjs`の`proYearView`の`pending.autoChance`：自分のレーティング＋調子・研究★・分身の成長と、相手のレーティングだけで`winProbability`を計算する。`ShogiProYear.vue`は百分率に四捨五入して表示する。
- 同ファイルの`recordProGame(..., 'auto')`：同じ調子・研究・成長を足した自分と相手を`simulateMemberGame`に渡す。こちらは以下も勝敗の確率に反映する。
  - 能力の配分、戦法の相性、金の特殊能力、逆転の名手。まとめてレーティング±60まで。
  - 安定感によるレーティング差の倍率（0.85〜1.15）。
  - 先手の有利：レーティング＋17、後手は−17。
- 善彦には「大局観」「深い読み」「逆転の名手」があり、標準の分身との比較では上記の上乗せが善彦側へ上限まで働く。名前や人物IDを見て自動対局の勝ち負けを強制する分岐は見つからなかった。
- **先後にも不一致がある。** `pending.color`は既に決まっているが、自動対局の呼び出しは`aColor`を渡していないため、シミュレーター内で先後を抽選し直す。
- 自動対局の呼び出しは`big`も渡さず、大舞台の補正は既定の無効。善彦の標準の特殊能力に大舞台の特徴はないため、今回の差の原因ではない。
- 負けると調子が下がる処理はある（通常1段、二日制2段。1段はレーティング40相当）。これは次の対局の表示にも含まれる。連敗数を使ってさらに負かす処理は見つからなかった。
- 本物の世界で善彦の実対局CPUをLv49に固定する処理はあるが、分身の自動対局はそのCPUを使わない。

## 同じ61%表示での再現結果

標準名簿（seed=11）の善彦R2130に対して、調子・研究・成長を足した後のレーティング差を`400 × log10(0.61 / 0.39)`（約77.706）に固定。各条件10万局、乱数seed=20261118。プレイヤーの`character`・`repertoire`が無い点も、棋士の1年の分身の作り方に合わせる。自分のレーティングの実値はユーザーの保存データを意味しない。

| 条件 | 勝数 / 100,000局 | 実測勝率 | 抽選確率の平均 |
| --- | ---: | ---: | ---: |
| 標準の善彦、実装どおり先後を抽選 | 52,595 | 52.595% | 52.643% |
| 自分を先手に固定 | 55,097 | 55.097% | 55.089% |
| 自分を後手に固定 | 50,257 | 50.257% | 50.213% |
| 能力を保ち、相手の名前・人物IDだけ変更 | 52,595 | 52.595% | 52.643% |
| 善彦の特殊能力のみ外す | 60,708 | 60.708% | 60.878% |
| 能力・特殊能力・得意戦法の補正を外す | 61,133 | 61.133% | 60.975% |

実測は、表示よりも**補正後の抽選確率**に近い。少なくともこの60万局では、乱数の大きな偏りより、表示に補正が入っていないことが主な差だった。有限回の試行で勝数を必ず所定の割合にそろえる処理ではない。

再現コマンド：`node scripts/pro-auto-probability-audit.mjs`。各条件の局数を変える場合は末尾に正の整数を渡す。関連の既存テストは`ryuo-simulation.test.mjs`・`pro-week.test.mjs`・`pro-year.test.mjs`の計70件成功。

## 乱数とやり直し

`ryuo-random.mjs`の`createRng(state.rng)`で保存した状態から乱数列を再開する。1局の勝敗は`rng.next() < probability`で決まる。その後の形勢の展開の引き直しは、決定済みの勝敗を変更しない。同じ対局前の保存に戻り、同じ操作で自動対局すると同じ結果が再現されるため、それは独立した抽選の繰り返しにはならない。

## 修正するときの方針

表示と抽選で**同じ補正後の確率を共有する**必要がある。対局の先後は`pending.color`を使う。戦型の抽選でも確率が変わる相手がいるので、対局の条件を確定してから表示し、その値を勝敗にも使う形が確実。特殊能力を残すか取り除くかでゲームの強さが変わるため、今回の調査では勝敗処理を変更していない。


## 同日の修正と再検証

ユーザーから修正と公開の依頼を受け、`pro-auto-game.mjs`へ分身の補正とシミュレーションの呼び出しを共通化した。表示は世界の乱数の写し、勝敗確定は実際の乱数を渡す。同じ状態なら選ばれる戦型と確率が一致する。先後は`pending.color`を使い、欠けている旧保存では対局の組み合わせから復元する。特殊能力は従来の効果を保つ。

旧61%の入力は、先手なら約55%、後手なら約50%と補正後の値を表示する。別に「修正後の表示自体が61%」となる条件を先後それぞれ作り、各10万局を検証した。

| 修正後の条件 | 勝数 / 100,000局 | 実測 | 表示用の確率の平均 | 表示と抽選の最大差 |
| --- | ---: | ---: | ---: | ---: |
| 自分が先手・表示61% | 60,974 | 60.974% | 61% | 0 |
| 自分が後手・表示61% | 60,886 | 60.886% | 61% | 0 |

いずれも対局の先後は途中で再抽選せず、全試行で表示用と抽選用の確率が一致した。有限回の勝数を強制的に調整する処理は加えていない。画面の値は整数丸めで、抽選は丸め前を使う。

再現スクリプトは、修正前の6条件と修正後の2条件を実行するよう更新した。
